# 1. 背景

V2 公开端将使用两种主要群组浏览形式：

* “发现新群”和自定义板块使用横向 Carousel
* “所有群组”和搜索结果使用响应式 Grid

无论群组出现在何种区域，都需要使用同一套群组卡片和群组详情交互。

当前产品规则已经冻结：

* 卡片只展示摘要信息
* 卡片不直接展示加群按钮
* 点击卡片打开详情弹窗
* 弹窗不跳转到独立页面
* URL 增加 `?group=<group_id>`
* 直接访问带 `group` 参数的 URL 自动打开弹窗
* 弹窗提供分享按钮
* 分享按钮复制规范化群组链接
* 卡片简介最多显示四行
* 点赞是独立操作
* Carousel 支持鼠标、触摸、触控板、滚轮和键盘
* 手机 Carousel 目标为同时看到至少两张卡片
* 手机详情弹窗接近全屏

本任务负责建立这些公开端核心可复用组件。

本任务完成后，子任务 07 只需负责首页信息架构、数据编排、搜索状态和分页，不应重新实现另一套卡片、Carousel 或详情弹窗。

# 2. 任务目标

## 2.1 建立统一群组卡片

实现一套可同时用于以下场景的正式群组卡片：

* 发现新群 Carousel
* 自定义板块 Carousel
* 所有群组 Grid
* 搜索结果 Grid

卡片必须在不同容器中保持相同信息结构和主要交互，只允许通过布局属性调整宽度。

## 2.2 建立通用 Carousel

实现一个与群组业务解耦的通用横向 Carousel，支持：

* 鼠标拖动
* 手指滑动
* 触控板横向滚动
* 鼠标滚轮横向查看
* 键盘左右移动
* 滚动吸附
* 边界处理
* 溢出提示
* 拖动与点击冲突处理

## 2.3 建立群组详情弹窗

实现一个可访问、可分享、可深链接的群组详情弹窗，展示：

* 群组完整信息
* 完整简介
* 点赞状态
* 一个或多个加群方式
* 复制、打开链接和二维码等能力
* 分享按钮

## 2.4 建立 URL 驱动状态

群组详情弹窗必须与 Vue Router 查询参数同步，使其支持：

* 卡片点击打开
* 浏览器返回关闭
* 浏览器前进重新打开
* 直接访问深链接
* 保留搜索查询参数
* 分享独立规范链接
* 无效群组安全处理

## 2.5 建立可访问性基础

卡片、Carousel 和 Dialog 必须在鼠标、键盘和触摸设备上可用，并正确处理：

* 焦点
* 滚动锁定
* 焦点恢复
* Escape
* 屏幕阅读器语义
* 减少动态效果

# 9. 群组卡片布局

## 9.1 头像

头像必须：

* 保持固定宽高比
* 避免加载导致布局跳动
* 使用现有 WebP 资源
* 支持懒加载
* 支持加载失败占位
* 提供合理替代文本或装饰性语义
* 不因深色模式应用图像反色

如果头像只是群组标志且标题紧邻，可使用简洁替代文本；不得让屏幕阅读器重复朗读完全相同内容。

## 9.2 标题

标题：

* 数据上限为 50 显示宽度单位
* 卡片中最多两行
* 超出可用空间时使用视觉省略
* 不修改原始字符串
* 详情弹窗显示完整标题
* 应避免长英文单词撑破布局

## 9.3 平台

平台应使用：

* 平台文字
* 或视觉规范确认的徽标

平台不能只通过颜色或图标表达，必要时提供文本或可访问名称。

## 9.4 简介

卡片简介：

* 最多四行
* 使用 CSS 行数截断
* 超出部分显示省略号
* 不在 JavaScript 中裁剪原始文本
* 不向数据中写入省略号
* 不影响详情弹窗完整简介
* 保留合理换行语义
* 避免超长连续字符串撑破卡片

## 9.5 点赞区

点赞区至少包括：

* 点赞按钮
* 当前点赞状态
* 点赞数量

点赞数量需要遵守现有格式化规则。

不得因点赞数变化导致卡片明显宽度跳动。

# 10. 卡片尺寸与响应式

## 10.1 Carousel 卡片

Carousel 卡片宽度必须遵守 `ui-design.md`。

在标准手机宽度下：

* 同时至少看到两张卡片
* 保留卡片间距
* 保留页面左右边距
* 不让单卡独占一整行
* 允许下一张卡片部分露出作为滑动提示

## 10.2 Grid 卡片

Grid 卡片应能够适应：

* 手机两列
* 平板多列
* 桌面多列
* 超宽屏最大列数

实际 Grid 容器由子任务 07 完成，本任务需确保卡片本身在目标最小宽度下可用。

## 10.3 高度

卡片可以因标题和简介内容产生小幅高度差异，但应避免：

* 简介无限展开
* 操作区位置完全不可预测
* Carousel 被极端单卡撑出巨大高度

推荐通过：

* 标题两行上限
* 简介四行上限
* 统一内容区域结构
* 点赞区域固定位置

保持卡片视觉稳定。

## 10.4 极端内容

必须验证：

* 50 个 ASCII 宽度标题
* 25 个中文字符标题
* Emoji 混合标题
* 四行以上中文简介
* 四行以上英文简介
* 无空格长字符串
* 平台名较长
* 点赞数较大

# 11. 卡片可点击语义

## 11.1 主体点击

点击卡片主体打开群组详情弹窗。

不得通过在卡片外层嵌套一个原生 `<button>`，再在内部放置点赞 `<button>`，造成非法嵌套交互元素。

可采用：

* 卡片容器配合 `role="button"`
* 独立可点击覆盖区域
* 其他符合无障碍规范的结构

具体结构必须保证：

* 卡片主体可聚焦
* 点赞按钮独立聚焦
* DOM 语义合法
* 屏幕阅读器能够理解

## 11.2 键盘操作

聚焦卡片主体后：

* Enter 打开详情
* Space 打开详情
* Space 不得同时滚动页面
* 焦点样式明显

## 11.3 辅助名称

卡片可访问名称应包含群组标题，并表达“打开详情”。

不得只朗读“按钮”。

# 12. 点赞独立交互

## 12.1 点击隔离

点击点赞按钮时：

* 执行点赞或取消点赞
* 不打开详情弹窗
* 不改变 `group` URL 参数
* 不触发卡片按压后的打开事件

必须正确处理：

* `stopPropagation`
* 键盘事件
* 触摸事件
* 乐观更新

不得仅处理鼠标 `click` 而遗漏键盘。

## 12.2 复用现有逻辑

必须复用现有：

* 设备 ID
* pepper 哈希后端逻辑
* 乐观更新
* localStorage 持久化
* 错误回滚
* Toast 或错误反馈

不得在本任务中创建第二套点赞状态存储。

## 12.3 多处同步

同一个群组可能同时出现在：

* 发现新群
* 多个板块
* 所有群组
* 详情弹窗

当点赞状态变化时，当前页面中同一群组的所有实例应尽量保持一致。

实现应通过共享状态或统一事件更新，而不是每张卡片完全隔离。

具体全首页同步可在子任务 07 接入时完成，但本任务提供的卡片和 Dialog 必须支持受控点赞状态。

## 12.4 请求失败

乐观更新失败时：

* 恢复原点赞状态
* 恢复原点赞数
* 显示错误反馈
* 不打开详情弹窗
* 不关闭已有详情弹窗

# 13. 通用 Carousel 组件

## 13.1 业务无关

`HorizontalCarousel` 不得直接依赖：

* Group 类型
* 群组 API
* 点赞状态
* 板块排序模式

它应接收：

* 子项内容
* 可选标题外部容器
* 滚动区域引用
* 可选控制按钮配置
* 必要的可访问标签

## 13.2 原生滚动优先

应优先基于：

* `overflow-x: auto`
* `scroll-snap`
* 原生触摸滚动
* 原生触控板滚动

实现。

不得默认引入复杂第三方 Carousel 运行时。

## 13.3 不自动播放

Carousel 不允许：

* 自动轮播
* 定时自动移动
* 无限循环
* 到末尾后跳回开头
* 未经用户操作自动改变当前查看位置

本项目的“每小时随机”属于数据顺序，不是前端自动轮播。

# 14. Carousel 滚动吸附

## 14.1 Snap 规则

每张卡片应使用一致的滚动吸附位置。

推荐：

```text
scroll-snap-type: x mandatory 或 proximity
scroll-snap-align: start
```

最终值依据原型体验决定。

## 14.2 用户自由滚动

吸附不能严重阻碍：

* 快速触摸滑动
* 鼠标拖动
* 触控板惯性滚动
* 键盘跳转

如 `mandatory` 导致体验僵硬，应使用 `proximity`，但必须记录原因。

# 15. 鼠标拖动

## 15.1 基本行为

桌面用户可以：

1. 在 Carousel 滚动区域按下鼠标
2. 横向拖动
3. 松开完成滚动

## 15.2 指针样式

可根据设计规范显示：

* `grab`
* 拖动时 `grabbing`

不得覆盖内部点赞按钮等交互控件的正常指针语义。

## 15.3 拖动阈值

需要设定合理阈值区分：

* 点击
* 拖动

只有位移超过阈值后，才视为拖动。

阈值应：

* 足以避免手抖误判
* 不让拖动显得迟钝
* 可在测试中固定

具体像素值在 `design.md` 中记录。

## 15.4 拖动后点击抑制

一旦本次指针操作被判定为拖动：

* 松开后不得打开卡片
* 不得触发内部链接
* 不得触发详情弹窗
* 应只抑制当前手势对应的一次点击
* 不能让后续正常点击永久失效

## 15.5 文本选择

拖动时应避免大量选中文本或图片拖拽，但不得通过全局永久禁用文本选择破坏可访问性。

# 16. 触摸滑动

## 16.1 原生行为

触摸设备优先使用浏览器原生横向滚动。

不得自行实现复杂触摸惯性算法。

## 16.2 页面纵向滚动

用户在 Carousel 上主要做纵向手势时，页面应能继续上下滚动。

不得因错误设置 `touch-action: none` 锁死页面。

建议根据实现使用：

```text
touch-action: pan-y pinch-zoom
```

或兼容横向原生滚动的适当值，并通过真实设备测试。

## 16.3 点击与滑动

触摸滑动超过阈值后：

* 不打开详情
* 不误触点赞
* 不触发长按图片拖拽

轻触卡片仍正常打开详情。

# 17. 触控板与原生滚动

触控板横向手势应直接使用原生 `scrollLeft` 行为。

不得拦截所有 Wheel 事件并重新计算，破坏原生横向手势。

需要区分：

* `deltaX` 明显的触控板横向输入
* `deltaY` 为主的鼠标滚轮输入
* 浏览器缩放手势
* Ctrl/Meta 修饰的缩放输入

带 Ctrl 或其他浏览器缩放语义的 Wheel 事件不得被改为横向滚动。

---

# 18. 鼠标滚轮处理

## 18.1 转换条件

只有同时满足以下条件时，才将主要纵向滚轮输入转换为横向滚动：

* 当前 Carousel 存在横向溢出
* 指针位于 Carousel 有效区域
* 用户并非在可纵向滚动的 Dialog 内容内
* Carousel 在对应方向仍可继续滚动
* 事件不是浏览器缩放
* 页面没有更高优先级滚动容器需要处理

## 18.2 边界释放

当 Carousel 已到：

* 最左边且用户继续向上或向左滚
* 最右边且用户继续向下或向右滚

应释放事件，让页面继续纵向滚动。

不得让用户被困在某个 Carousel。

## 18.3 无溢出

卡片数量不足、没有横向溢出时：

* 不拦截滚轮
* 不显示可用的左右控制按钮
* 不展示误导性的边缘遮罩

## 18.4 被动监听

如需要调用 `preventDefault`，必须正确配置监听器，不得产生浏览器被动监听警告。

监听器在组件销毁时必须清理。

---

# 19. 键盘操作

## 19.1 Carousel 容器

Carousel 应具有可识别的区域语义和可访问名称。

是否让容器本身进入 Tab 顺序，由 `design.md` 决定。

## 19.2 左右方向键

当焦点位于 Carousel 或其卡片时：

* ArrowRight 移动到下一张卡片或向右滚动一张
* ArrowLeft 移动到上一张卡片或向左滚动一张

不得劫持输入框或其他文本编辑控件中的方向键。

## 19.3 Home 与 End

建议支持：

* Home 移动到第一张
* End 移动到最后一张

如未实现，需要说明原因。

## 19.4 焦点策略

两种可接受策略：

### 策略 A：卡片自然 Tab

每张卡片均可通过 Tab 聚焦。

适合卡片数量有限的 Carousel。

### 策略 B：Roving tabindex

Carousel 内只有一个卡片进入 Tab 顺序，左右键切换。

适合较多卡片，但实现更复杂。

最终策略必须在 `design.md` 中冻结，并与无障碍测试一致。

不得同时混用两种策略造成焦点混乱。

## 19.5 滚动跟随

键盘聚焦移动时，目标卡片应滚动到可见区域。

# 20. Carousel 控制按钮

## 20.1 桌面按钮

* 只在有溢出时显示
* 到左边界时禁用左按钮
* 到右边界时禁用右按钮

## 20.2 手机

## 20.3 滚动距离

点击箭头推荐滚动：

* 一张卡片
* 或一个可视页面宽度减去重叠

最终方式在 `design.md` 中固定。

不得每次使用不稳定的任意像素值。

* 下一张卡片部分露出
* 边缘渐变
* 左右按钮
* 滚动位置指示

## 21.1 边界状态

* 最左侧不显示左侧可继续提示
* 最右侧不显示右侧可继续提示
* 无溢出时不显示提示

## 21.2 主题

渐变和遮罩必须使用主题 Token，不得写死浅色背景。

# 22. Carousel 滚动状态

* 是否存在溢出
* 是否位于左边界
* 是否位于右边界
* 是否正在拖动
* 当前可见卡片或当前焦点卡片，如需要

## 22.1 尺寸变化

以下情况后应重新计算：

* 容器宽度变化
* 卡片数量变化
* 字体加载
* 响应式断点变化
* 浏览器缩放
* 侧边栏或管理面板影响布局

监听器必须正确清理。

# 23. 群组详情弹窗信息结构

## 23.1 必须展示

详情弹窗固定展示：

* 群组头像
* 完整标题
* 平台
* 完整简介
* 点赞按钮
* 点赞数量
* 一个或多个加群方式
* 分享按钮
* 关闭按钮

## 23.2 可复用现有能力

加群方式根据现有数据类型，可能包括：

* 群号复制

* 加群方式排序
* QR 码查看
* 复制
* 链接打开

* 安全 URL 校验

## 23.3 不展示

公开详情不得展示：

* 管理状态

* 删除信息

# 24. 详情数据来源

## 24.1 从卡片打开

当卡片当前已有足够详情数据时，可以立即用现有数据打开 Dialog。

如果完整加群方式不在卡片 DTO 中，应：

* 先打开加载态 Dialog
* 按群组 ID 请求公开详情
* 成功后展示完整内容

不得为了避免一次请求，把完整敏感加群信息塞入所有卡片列表响应。

## 24.2 直接深链接

访问：

```text
/?group=<group_id>
```

时，页面未必已经加载包含该群组的列表。

必须能够按群组 ID 获取公开详情。

## 24.3 公开详情能力

Agent 必须首先检查是否已有公开详情接口。

### 已有接口

若已有接口：

* 复用
* 补充 Typed Contract
* 确认只返回已发布群组
* 确认字段满足 Dialog

### 没有接口

若没有能够支持深链接的接口，本任务允许增加一个最小只读公开详情接口，例如：

```text
GET /api/groups/:groupId
```

具体路径遵循当前 API 规范。

该最小后端扩展只允许：

* 按群组 ID 查询
* 返回公开详情 DTO
* 只返回已发布群组
* 复用现有 repository/service
* 使用共享 Zod 响应解析
* 添加必要 Workers Vitest

不得借此实现板块 API、搜索 API 或其他后端功能。

## 24.4 状态安全

公开详情接口只能返回当前已发布群组。

以下状态统一不可公开：

* 已下架
* 回收站
* 永久删除
* 草稿
* 待审核
* 其他非公开状态

不得通过知道 ID 绕过公开状态过滤。

# 25. Dialog 加载状态

直接访问或需要补充请求时，Dialog 应支持：

* 加载 Skeleton
* 加载失败
* 群组不存在
* 群组不可公开
* 请求取消
* 重试

## 25.1 加载期间

* Dialog 已经打开
* URL 保持 `group` 参数
* 焦点仍在 Dialog 内
* 用户可以关闭
* 不展示上一个群组的旧详情

## 25.2 请求竞态

用户快速点击不同卡片时：

* 旧请求不得覆盖新群组详情
* 应使用 AbortController、请求序列或现有请求竞态方案
* URL 中的 `group` ID 是当前详情来源

# 26. Dialog 语义

## 26.1 正式 Dialog

应使用：

* 原生 `<dialog>`，如果与当前架构和浏览器支持兼容
* 或具备等效 ARIA 语义的正式 Dialog 组件

必须包含：

* `role="dialog"` 或原生语义
* `aria-modal="true"`
* 可识别标题
* 描述关联，如适用

不得只是普通固定定位 `div`。

## 26.2 标题

Dialog 的可访问标题应为群组标题或“群组详情：标题”。

## 26.3 关闭按钮

关闭按钮：

* 始终可见
* 有可访问名称
* 手机和桌面均可操作
* 不被滚动内容推出视口
* 符合安全区

---

# 27. Dialog 打开方式

## 27.1 卡片点击

点击卡片后：

1. 更新 Router 查询参数
2. 打开 Dialog
3. 显示已有数据或加载态
4. 将焦点移入 Dialog

## 27.2 URL 是状态来源

Dialog 是否打开由当前路由的 `group` 参数决定。

不得只维护一个与 URL 无关的本地 `isOpen`，否则浏览器前进、后退和深链接会失效。

允许内部维护过渡状态，但最终真值必须与 Router 同步。

## 27.3 同一群组重复点击

当前已经打开同一群组时重复操作：

* 不重复 push 相同历史记录
* 不重复发起无必要请求
* 不重置用户已经滚动的简介位置，除非明确需要

---

# 28. URL 查询参数规则

## 28.1 基本格式

```text
?group=<group_id>
```

群组 ID 必须使用当前正式公开 ID 类型。

## 28.2 与搜索并存

例如：

```text
/?q=计算机&group=<group_id>
```

打开和关闭详情时必须保留：

* `q`
* 其他合法公开页面查询参数

不得清空搜索状态。

## 28.3 打开时

从页面卡片打开：

* 使用 `router.push`
* 新增一条浏览历史
* 浏览器返回可以关闭 Dialog

## 28.4 关闭时

关闭逻辑必须区分：

### 页面内打开

如果当前 Dialog 是通过本页面的 `router.push` 打开，关闭可优先使用浏览器历史回退，使前进可以再次打开。

### 直接深链接或外部进入

如果用户直接访问带 `group` 参数的页面，关闭 Dialog 不应把用户带离网站。

此时应使用 `router.replace` 移除 `group` 参数。

## 28.5 状态标记

可通过 Router state、内部打开来源记录或其他可靠方式判断：

* 页面内打开
* 直接链接打开

不得单纯使用 `history.length` 判断，因为它包含网站外部历史。

## 28.6 参数顺序

不依赖查询参数顺序判断状态。

## 28.7 无效参数

以下情况视为无效：

* 空 `group`
* ID 格式非法
* 重复冲突参数
* 不存在群组
* 非公开群组

应显示安全反馈并允许移除参数。

# 29. 浏览器历史行为

必须满足：

## 29.1 页面内打开

初始：

```text
/?q=计算机
```

点击卡片：

```text
/?q=计算机&group=123
```

点击浏览器返回：

```text
/?q=计算机
```

Dialog 关闭，搜索结果保留。

点击浏览器前进：

```text
/?q=计算机&group=123
```

Dialog 重新打开。

## 29.2 直接深链接

直接进入：

```text
/?group=123
```

关闭 Dialog：

```text
/
```

仍留在网站首页，不跳回外部来源。

## 29.3 群组切换

Dialog 打开时，如用户通过未来可能存在的内部入口切换到另一群组，应明确使用 push 还是 replace。

第一版本不要求 Dialog 内上一组、下一组导航。

# 30. 深链接加载

## 30.1 页面启动

应用启动时如存在合法 `group` 参数：

* 不等待无限滚动找到该卡片
* 直接按 ID 获取详情
* 打开 Dialog
* 背景页面按其他参数正常加载

## 30.2 背景页面

深链接背景可以是：

* 默认首页
* 搜索结果页面

取决于 URL 是否存在 `q`。

Dialog 不能导致搜索框位置改变。

首页完整结构由子任务 07 完成，本任务需保证 Router 机制可复用。

## 30.3 未找到群组

如果群组不存在或不可公开：

* 不泄露具体内部状态
* 显示“群组不存在或暂不可查看”等安全文案
* 提供关闭操作
* 关闭后移除 `group`
* 页面其他内容继续可用

# 31. 分享按钮

## 31.1 位置

分享按钮位于群组详情弹窗中。

卡片不直接展示分享按钮。

## 31.2 规范链接

复制链接格式：

```text
https://当前公开域名/?group=<group_id>
```

如果网站部署在子路径，应通过 Router 或站点配置生成正确绝对 URL。

## 31.3 参数清理

分享链接默认只包含：

* 公开网站基础地址
* `group`

不得包含：

* `q`
* 管理端参数
* 页码
* 筛选
* 调试参数
* CSRF
* 会话信息
* 临时来源参数

## 31.4 Origin

使用当前公开站点规范 origin 或 `siteConfig` 定义的 canonical origin。

不得硬编码：

* localhost
* Preview URL
* 临时 Cloudflare Pages 分支域名

开发和测试环境可依据当前运行 origin 验证，但生产生成规则必须明确。

## 31.5 剪贴板

优先使用 Clipboard API。

需处理：

* 安全上下文
* 用户权限拒绝
* 浏览器不支持
* 测试环境

如项目已有复制工具，必须复用。

是否提供降级复制方案由当前共享工具能力决定。

## 31.6 反馈

复制成功：

* 显示成功 Toast
* 按钮可短暂显示已复制状态

复制失败：

* 显示错误 Toast 或 ErrorBanner
* 不虚假提示成功
* 不关闭 Dialog

## 31.7 无重复写入

连续快速点击分享按钮时：

* 不产生大量重复 Toast
* 不导致 Dialog 状态异常

# 32. 完整简介

## 32.1 数据

Dialog 展示数据库保存的完整简介。

不得使用卡片经过 CSS 截断的 DOM 文本作为详情来源。

## 32.2 格式

需要安全展示：

* 换行
* 中文
* Emoji
* 长英文
* URL 文本
* 特殊字符

不得将简介作为未经清洗的 HTML 注入。

除非当前项目明确支持富文本，否则简介按纯文本显示。

## 32.3 滚动

长简介应在 Dialog 内容区域内正常滚动。

Dialog 的：

* 标题区
* 关闭按钮
* 关键底部操作

是否固定由 `ui-design.md` 决定。

不得让关闭按钮随超长简介滚出不可访问位置。

# 33. 加群方式

## 33.1 数量

Dialog 支持：

* 一个加群方式
* 多个加群方式
* 异常情况下零个加群方式

正常已发布群组是否必须至少有一个加群方式，以当前共享 Schema 为准。

## 33.2 顺序

多个加群方式按照管理员配置顺序展示。

不得按类型重新排序，除非现有领域规则明确要求。

## 33.3 类型

对每种现有加群方式：

* 显示明确名称
* 显示对应操作
* 保留平台与加入方式解耦后的领域模型
* 不推断平台必然对应固定加入方式

## 33.4 二维码

复用现有 QR 码能力。

如果当前二维码为二级弹窗：

* 层级必须高于群组详情 Dialog
* 关闭二维码后焦点返回对应加群方式按钮
* Escape 优先关闭最上层二维码
* 再次 Escape 才关闭群组详情

如果将二维码嵌入详情 Dialog：

* 必须符合 `ui-design.md`
* 不影响手机布局
* 图片可放大查看

## 33.5 外部链接

加群链接：

* 使用现有 URL 校验
* 外部打开方式遵守项目安全规范
* 使用必要的 `rel`
* 不允许 `javascript:` 等危险协议

## 33.6 复制

复制群号或文本时：

* 使用共享复制工具
* 成功和失败有反馈
* 不传播点击打开卡片事件
* 不修改 `group` 参数

# 34. Dialog 点赞

Dialog 中的点赞按钮应与卡片使用同一点赞状态和操作逻辑。

当 Dialog 点赞变化时：

* 当前卡片更新
* 其他相同群组卡片更新
* localStorage 状态更新
* 失败时全部回滚到一致状态

不得在 Dialog 中创建独立点赞请求实现。

# 35. 焦点管理

## 35.1 打开时

打开 Dialog 后：

* 保存触发元素
* 焦点移入 Dialog
* 优先聚焦关闭按钮、Dialog 容器或设计规范指定的首个控件
* 不让焦点留在遮罩后的卡片上

## 35.2 焦点锁定

Dialog 打开时，Tab 和 Shift+Tab 应循环在 Dialog 可交互元素内。

不得让焦点进入底层页面。

## 35.3 关闭后恢复

关闭后：

* 优先将焦点恢复到原卡片
* 如果原卡片因搜索、分页或路由变化已经不存在，恢复到合理备用元素
* 备用可为搜索框或主内容容器

## 35.4 深链接

直接深链接没有原卡片触发元素。

关闭后应将焦点放到：

* 主搜索框
* 或页面主内容标题

具体按页面结构和可用元素决定。

## 35.5 多层弹窗

二维码等二级弹窗关闭后：

* 焦点返回群组详情内原触发按钮
* 不直接回到背景卡片

---

# 36. Escape 与关闭行为

## 36.1 Escape

按 Escape：

* 如有二级弹窗，先关闭二级弹窗
* 否则关闭群组详情 Dialog
* 更新 URL
* 恢复焦点

## 36.2 遮罩点击

点击遮罩可以关闭详情 Dialog。

点击 Dialog 内容区域不得冒泡关闭。

## 36.3 关闭按钮

关闭按钮始终可用。

## 36.4 加载期间

即使详情仍在加载，也允许：

* Escape 关闭
* 点击关闭按钮
* 点击遮罩关闭

关闭后应取消未完成请求。

---

# 37. 页面滚动锁定

Dialog 打开时：

* 锁定背景页面滚动
* 保留原页面滚动位置
* 关闭后恢复原位置
* 不产生明显页面宽度跳动
* 不与顶栏 sticky 行为冲突

## 37.1 手机

需处理：

* iOS Safari
* Android 浏览器
* 地址栏变化
* 软键盘
* 安全区

不得简单设置后导致页面关闭 Dialog 后跳到顶部。

## 37.2 多层弹窗

存在二维码二级弹窗时，不得因为关闭二级弹窗提前解除背景滚动锁定。

# 38. 手机全屏化布局

## 38.1 目标

在标准手机宽度下，详情 Dialog 接近全屏。

可以保留：

* 小范围外边距
* 圆角
* 顶部安全区
* 底部安全区

具体遵循 `ui-design.md`。

## 38.2 布局

手机 Dialog 需要：

* 关闭按钮易触达
* 标题不被挤压
* 简介可滚动
* 多个加群方式纵向排列
* 分享和点赞操作清晰
* 二维码适配屏幕宽度
* 底部操作不被浏览器工具栏遮挡

## 38.3 横屏

手机横屏或低高度窗口时：

* Dialog 内容仍可滚动
* 关闭按钮仍可见
* 不出现无法访问的底部按钮

# 39. 桌面 Dialog

桌面端应：

* 使用 `ui-design.md` 定义的最大宽度
* 不无限扩展
* 不因短内容显得空洞
* 不因长内容超出视口
* 头像和主要信息层级清晰
* 多个加群方式保持合理密度

不得将 Dialog 扩展成几乎整个桌面页面，除非视觉规范已明确确认。

# 40. 深色模式

卡片、Carousel 和 Dialog 必须完全使用子任务 03 的语义 Token。

需要覆盖：

* 卡片背景
* 卡片边框
* Hover
* Focus
* 点赞状态
* Carousel 箭头
* 边缘渐变
* Dialog 背景
* 遮罩
* 关闭按钮
* 分享按钮
* 加群方式
* QR 区域
* Skeleton
* 错误状态

不得：

* 直接使用大量 `dark:` 硬编码颜色绕过语义 Token
* 对头像或二维码应用颜色反转
* 让 QR 码背景变透明导致不可扫描

# 41. 减少动态效果

尊重：

```text
prefers-reduced-motion: reduce
```

需要降级：

* 卡片 Hover 位移
* Dialog 进入退出动画
* Carousel 平滑滚动
* Skeleton 动画
* 点赞动画
* Toast 动画

减少动态效果时：

* 功能仍完整
* Dialog 可立即出现
* 滚动定位可使用非动画方式
* 不删除必要状态反馈

# 42. 错误与异常状态

## 42.1 头像失败

显示项目统一头像占位。

不得导致卡片高度变化。

## 42.2 详情请求失败

Dialog 显示：

* 明确错误
* 重试按钮
* 关闭按钮

不得显示空白 Dialog。

## 42.3 群组不可公开

显示安全文案，不区分：

* 已下架
* 回收站
* 删除
* 不存在

避免泄露内部状态。

## 42.4 Clipboard 失败

显示错误反馈，不关闭 Dialog。

## 42.5 QR 图片失败

显示对应加群方式错误状态，不影响其他加群方式。

## 42.6 点赞失败

回滚点赞，不关闭 Dialog，不影响 URL。

# 43. 数据缓存

## 43.1 详情缓存

可以在前端会话中缓存已成功加载的公开详情，以减少重复请求。

缓存必须：

* 以群组 ID 为 Key
* 不跨越不合理长时间
* 不让已下架群组永久可见
* 在请求返回不可公开时清除对应缓存
* 不写入包含敏感数据的长期 localStorage

## 43.2 列表数据复用

从卡片打开时，可立即使用列表已有摘要，随后补全详情。

不得显示上一群组的完整加群方式作为新群组临时内容。

# 44. URL 与状态竞态

必须处理：

* 快速连续点击多个卡片
* 打开后立刻浏览器返回
* 请求进行中关闭
* 请求进行中切换群组 ID
* URL 被外部修改
* 无效 ID 变为有效 ID
* 有效 ID 被移除
* 搜索参数与 `group` 同时变化

最终显示的详情必须与当前 URL `group` 一致。

---

# 45. SSR 与非浏览器环境

当前项目为 Vite SPA，但组件和工具在 Vitest 环境中不得无条件访问：

* `window`
* `document`
* `navigator.clipboard`
* `history`

需要：

* 生命周期后访问
* 提供安全检测
* 在测试中可注入
* 不因模块导入直接报错

# 46. 性能要求

## 46.1 卡片

* 图片懒加载
* 固定尺寸避免 CLS
* 四行截断使用 CSS
* 不在每次渲染执行昂贵字符串处理
* 不为每张卡片注册全局监听器

## 46.2 Carousel

全局或容器级监听应最小化。

## 46.3 Dialog

* 不预加载全部群组完整加群方式
* 长简介不导致大量重复 DOM

## 46.4 组件数量

一个群组可能出现在多个区域。

组件应避免每个实例独立建立相同全局状态监听。
