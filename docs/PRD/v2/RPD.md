# 1. 项目背景

当前网站的公开端、管理端、后端 API、数据库、图片存储、安全机制和自动化测试基础均已成型。

现有系统已经具备：

* 公开群组浏览、搜索、提交和匿名点赞
* 群组卡片、无限滚动、URL 搜索同步
* 管理端群组 CRUD、筛选、排序、回收站
* WebP 图片上传和资源生命周期管理
* HMAC 会话、CSRF 防护和版本冲突处理
* Cloudflare D1、R2 和 Analytics 集成
* 前后端共享 Zod Schema
* Workers 集成测试和 Playwright E2E 测试

本次升级不是从零开发，而是在不破坏现有能力的基础上，对以下内容进行系统性重构：

1. 公开首页信息架构
2. 群组卡片与详情交互
3. 自定义板块功能
4. 管理端信息架构
5. 管理端分页和响应式表格
6. 全站设计语言
7. 深色模式
8. 响应式体验
9. 自动化测试和系统级回归

# 2. 项目目标

## 2.1 核心目标

### 目标一：提高首页的信息组织能力

首页不再只是一个单一群组网格，而是由发现、标签、自定义板块和完整群组目录共同组成。

### 目标二：降低卡片操作密度

群组卡片只承担快速浏览和点赞功能，完整群组信息及加群方式统一进入详情弹窗。

### 目标三：建立可配置内容板块

管理员可以创建多个板块，并控制板块状态、顺序、成员和排序模式。

### 目标四：建立统一设计系统

以用户后续提供的视觉模板为参考，形成统一的颜色、间距、圆角、字体、组件和响应式规范。

### 目标五：提升跨设备体验

公开端和管理端必须在桌面、平板、手机和常见系统主题下正常使用，不得因屏幕变窄而丢失核心功能。

### 目标六：保持现有系统稳定

本次升级不得破坏现有认证、提交、点赞、图片上传、回收站、版本冲突和资源清理机制。

---

# 3. 非目标

以下内容不属于本次升级范围：

* 不开发原生移动应用
* 不增加用户注册和普通用户账号系统
* 不将群组详情改为独立页面
* 不引入 WebSocket 或服务端实时推送
* 不重写现有管理员认证体系
* 不改变现有 R2 图片资源生命周期
* 不重新设计 Cloudflare Analytics 数据来源
* 不为板块成员数量设置硬性上限
* 不为管理端提供可切换的每页条数
* 不在第一版本实现板块成员拖拽排序
* 不在第一版本建立新的搜索相关性算法

# 4. 产品设计原则

## 4.1 发现与检索分离

有限、精选、可配置的内容使用横向 Carousel。

完整目录和搜索结果使用纵向 Grid。

| 区域    | 布局       |
| ----- | -------- |
| 发现新群  | Carousel |
| 自定义板块 | Carousel |
| 所有标签  | 标签聚合卡片   |
| 所有群组  | Grid     |
| 搜索结果  | Grid     |

## 4.2 摘要与详情分离

卡片负责摘要浏览，详情弹窗负责完整信息和加群操作。

## 4.3 状态语义明确

已发布、已下架、回收站和永久删除必须有不同的公开展示与关联处理规则。

## 4.4 设计系统先于页面实现

不得先完成全部页面，再在最后统一改视觉样式。

视觉模板必须在基础组件正式实现前完成设计语言提炼。

## 4.5 前后端共享约束

字符宽度、字段长度、板块排序模式和 API 数据结构必须通过共享类型或共享 Zod Schema 保持一致。

# 5. 公开端总体信息架构

## 5.1 默认首页

搜索框为空时，首页从上到下依次展示：

1. 顶栏
2. 主搜索框
3. 发现新群
4. 所有标签
5. 零个、一个或多个自定义板块
6. 所有群组

已下架群组更改为不在公开端出现。

## 5.2 搜索状态

搜索框存在有效内容时，页面自动切换为：

1. 顶栏
2. 位置不变的主搜索框
3. 搜索结果

以下默认首页区域暂时隐藏：

* 发现新群
* 所有标签
* 自定义板块
* 所有群组

清空搜索内容后，恢复默认首页。

## 5.3 搜索框位置稳定

搜索状态切换前后，搜索框的纵向位置和主要尺寸不得明显变化。

页面不能因为进入搜索模式而产生大幅布局跳动。

# 6. 顶栏

## 6.1 桌面布局

左侧：

* 网站 Logo
* 网站名称

右侧：

* 主题模式控件
* GitHub 支持按钮
* 添加新群组按钮

宽屏按钮使用“图标 + 文字”。

推荐文字：

* （太阳月亮图标）（根据当前设计方案显示“自动”“浅色”或“深色”）
* （GitHub Logo） ”支持项目”
* （加号图标） “添加新的群组”

## 6.2 窄屏布局

屏幕宽度不足时：

* Logo 和网站名称仍需保留
* 主题模式控件只显示图标
* GitHub 支持按钮只显示图标
* 添加按钮缩短为“添加群”三个字
* 添加按钮不得缩减为单独的加号

所有图标按钮必须具备：

* 可访问名称
* Tooltip 或等效提示
* 清晰的键盘焦点状态

## 6.3 顶栏响应式原则

* 不打乱左右区域语义
* 不隐藏核心功能
* 优先缩减间距、文字和按钮装饰
* 不使用移动端汉堡菜单替代当前三个主要操作
* 不产生页面级横向滚动

# 7. 深色模式

## 7.1 主题偏好

系统支持三种偏好：

```ts
type ThemePreference = 'system' | 'light' | 'dark'
```

默认值为：

```ts
'system'
```

## 7.2 优先级

1. 浏览器本地存在合法用户偏好时，使用该偏好
2. 不存在本地偏好时，使用 `system`
3. `system` 模式根据 `prefers-color-scheme` 决定实际主题

## 7.3 自动模式

自动模式必须：

* 支持 iOS、macOS、Windows、Android 等系统主题检测
* 在系统主题发生变化时实时跟随
* 不只在首次进入网站时检测一次

## 7.4 本地持久化

用户选择的模式保存在 localStorage。

本地值损坏或不合法时，自动回退到 `system`。

## 7.5 首屏主题

主题必须在 Vue 应用挂载前尽早应用，避免出现先亮后暗或先暗后亮的闪烁。

## 7.6 覆盖范围

深色模式必须覆盖：

* 公开首页
* 搜索结果
* 群组详情弹窗
* 提交群组页面或弹窗
* 登录页
* 管理端群组管理
* 管理端板块管理
* 数据分析页
* 管理抽屉
* Toast
* ErrorBanner
* Skeleton
* 空状态
* 二维码弹窗
* 表单和表格

# 9. 群组内容长度规则

## 9.1 显示宽度计算

不能直接使用 JavaScript `string.length` 作为限制依据。

需要建立前后端共享的显示宽度计算规则。

建议共享函数：

```ts
measureDisplayWidth(value: string): number
```

基本规则：

* ASCII 字符：1 个宽度单位
* 半角拉丁字符：1 个宽度单位
* 中文、日文、韩文和全角字符：2 个宽度单位
* 单个 Emoji 字素簇：2 个宽度单位
* 组合 Emoji 按一个可见字素计算
* 带重音的拉丁字母不能简单按非 ASCII 统一计算为 2
* 前后空格在校验前清理
* 换行符计入合理宽度，防止通过大量换行绕过限制

具体 Unicode 算法由技术设计确定，但前后端结果必须完全一致。

## 9.2 标题限制

群组标题最大：

```text
50 个显示宽度单位
```

标题在卡片上最多显示两行。

极端情况下允许视觉省略，但原始标题完整保存在数据中，并在详情弹窗中显示。

## 9.3 简介限制

群组简介最大：

```text
1000 个显示宽度单位
```

简介不允许无限制存储。

卡片中最多显示四行，超出部分使用视觉省略号。

详情弹窗中显示完整简介。

## 9.4 表单反馈

创建和编辑表单应显示：

* 当前已使用宽度单位
* 最大宽度单位
* 超限错误

客户端和服务端必须使用同一个共享校验规则。

# 10. 群组卡片

## 10.1 卡片展示内容

所有公开区域统一使用同一种群组卡片。

卡片展示：

* 群组头像
* 群组标题
* 平台
* 最多四行简介摘要
* 点赞按钮
* 点赞数量

卡片不直接展示：

* 群号
* 加群链接
* 二维码
* 加群方式按钮
* 复制按钮

## 10.2 卡片点击

点击卡片主体后打开群组详情弹窗，不跳转页面。

以下操作不得触发打开弹窗：

* 点击点赞按钮
* 在 Carousel 中完成拖动
* 点击卡片中的其他独立交互控件

## 10.3 可访问性

卡片必须支持：

* 鼠标点击
* 触摸点击
* 键盘聚焦
* Enter 打开
* Space 打开

不得通过嵌套原生按钮制造非法交互结构。

点赞按钮必须保持独立可聚焦和可操作。

# 11. 群组详情弹窗

## 11.1 弹窗内容

详情弹窗展示：

* 群组头像
* 完整标题
* 平台
* 完整简介
* 点赞按钮
* 点赞数量
* 一个或多个加群方式
* 二维码、复制、打开链接等现有能力
* 分享按钮

多个加群方式按照管理员配置顺序展示。

## 11.2 URL 状态

打开详情弹窗时，URL 增加：

```text
?group=<group_id>
```

当页面同时存在搜索参数时：

```text
/?q=计算机&group=<group_id>
```

关闭弹窗后只移除 `group` 参数，保留其他查询参数。

## 11.3 深链接

直接访问：

```text
/?group=<group_id>
```

时，页面加载完成后自动打开对应群组详情弹窗。

公开详情接口只能返回已发布群组。

无效、已下架、回收站或已删除的群组不得通过深链接泄露信息。

## 11.4 分享按钮

点击分享按钮后，复制群组的规范化公开链接：

```text
https://当前域名/?group=<group_id>
```

复制的分享链接默认不携带搜索词等无关查询参数。

复制成功后显示 Toast。

复制失败时提供明确错误反馈。

## 11.5 浏览器历史

* 从卡片打开弹窗后，浏览器返回操作可以关闭弹窗
* 浏览器前进可以重新打开弹窗
* 关闭弹窗不得清除搜索词和页面筛选状态
* 关闭后焦点返回原卡片

## 11.6 弹窗交互

必须支持：

* Escape 关闭
* 点击遮罩关闭
* 明确的关闭按钮
* 焦点锁定
* 关闭后焦点恢复
* 打开后锁定底层滚动
* 手机端接近全屏
* 长简介在弹窗内容区域内滚动
* 深色模式
* 减少动态效果偏好

# 12. Carousel

## 12.1 使用区域

Carousel 只用于：

* 发现新群
* 自定义板块

所有群组和搜索结果不得使用超长单行 Carousel。

## 12.2 响应式卡片数量

Carousel 中的卡片数量根据容器宽度调整。

在标准手机宽度下，视口内至少能够同时看到两张卡片。

不得因为屏幕变窄而改成单卡独占整行。

## 12.3 交互方式

支持：

* 手指横向滑动
* 鼠标按住拖动
* 触控板横向滚动
* 鼠标滚轮横向查看
* 键盘左右方向键
* `scroll-snap`

## 12.4 鼠标滚轮规则

只有在 Carousel 存在横向溢出且仍可继续横向滚动时，才将滚轮操作用于横向移动。

滚动到左右边界后，应允许页面继续纵向滚动，不能锁死页面。

## 12.5 点击与拖动冲突

拖动距离超过阈值后：

* 本次动作视为拖动
* 不触发卡片点击
* 不打开详情弹窗

## 12.6 溢出提示

设计语言可采用以下一种或多种方式提示内容可横向查看：

* 部分露出下一张卡片
* 左右渐变遮罩
* 桌面端左右箭头
* 滚动位置指示

具体视觉方案由 `ui-design.md` 确定。

# 13. 发现新群

## 13.1 定义

“发现新群”展示最近一次进入已发布状态的群组。

不再使用随机排序。

## 13.2 数据字段

群组表新增：

```text
last_published_at
```

该字段允许为空。

## 13.3 更新时间规则

仅在群组发生以下状态转换时更新：

```text
非已发布状态 → 已发布状态
```

具体包括：

* 新建后直接发布
* 草稿或待审核状态发布
* 已下架群组重新发布
* 从回收站恢复后再次发布

以下操作不更新时间：

* 编辑已发布群组的标题
* 编辑简介、标签、头像和加群方式
* 保存一个仍然保持已发布状态的群组

## 13.4 排序

查询规则：

```text
status = published
ORDER BY last_published_at DESC, id DESC
LIMIT 10
```

`id` 作为稳定次排序字段。

## 13.5 更新方式

发现新群不需要 WebSocket 或自动轮询。

用户重新进入、刷新页面或触发重新请求时，即可看到最新发布群组。

## 13.6 数量

* 默认最多展示 10 个群组
* 少于 10 个时展示全部
* 不支持无限加载
* 使用 Carousel 展示

# 14. 所有标签

## 14.1 统计范围

只统计已发布群组。

已下架、回收站和永久删除群组不计入数量。

## 14.2 标签卡片

“所有标签”使用一个独立大卡片展示：

* 标签名称
* 对应已发布群组数量

## 14.3 点击行为

点击标签后：

1. 用标签文本替换搜索框当前内容
2. 更新 URL 中的搜索参数
3. 进入搜索结果状态
4. 不跳转到新页面

标签不会追加到已有搜索词后面。

## 14.4 排序

默认建议：

1. 群组数量降序
2. 标签名称作为稳定次排序

最终排序规则可在标签子任务 PRD 中确认。

## 14.5 聚合查询

标签数量必须通过聚合查询获得，不得为每个标签单独发起数据库查询。

# 15. 自定义板块

## 15.1 板块能力

管理员可以：

* 创建板块
* 修改标题
* 启用板块
* 关闭板块
* 删除板块
* 拖拽调整板块之间的顺序
* 修改板块内部排序模式
* 添加群组
* 移除群组
* 上移群组
* 下移群组

## 15.2 板块公开规则

只有启用状态的板块出现在公开首页。

未启用板块：

* 不在公开端显示
* 仍可在管理端正常编辑
* 保留所有成员和排序配置

## 15.3 空板块

启用但没有可显示成员的板块，在公开端展示空状态。

板块数量为零时，首页不显示自定义板块区域。

## 15.4 默认板块

首次初始化或迁移数据库时，自动创建一个空板块：

```text
自定板块
```

该板块：

* 不具有特殊系统权限
* 可以编辑
* 可以关闭
* 可以删除
* 删除后允许板块总数为零

## 15.5 板块成员

* 一个群组可以加入多个不同板块
* 同一群组不能在同一板块中重复
* 板块成员数量暂不设置硬上限
* 管理端可以对过长板块显示软性体验提示，但不得阻止保存

## 15.6 群组状态与关联

| 群组状态 | 板块关联  | 公开端 |
| ---- | ----- | --- |
| 已发布  | 保留    | 显示  |
| 已下架  | 保留    | 不显示 |
| 回收站  | 移除    | 不显示 |
| 永久删除 | 不存在关联 | 不显示 |

管理员允许向板块添加：

* 已发布群组
* 已下架群组

不得添加已经进入回收站的群组。

## 15.7 回收站行为

将群组移入回收站时：

* 删除该群组的全部板块关联
* 群组状态变化和关联删除必须原子完成
* 应复用现有突变令牌和批量操作模式

从回收站恢复后：

* 不自动恢复原板块关联
* 管理端应明确提示该行为

# 16. 板块排序

## 16.1 排序模式

```ts
type BoardSortMode =
  | 'manual_asc'
  | 'manual_desc'
  | 'hourly_random'
```

## 16.2 手动正序

按照管理员配置的成员位置正序展示。

## 16.3 手动倒序

按照管理员配置的成员位置倒序展示。

管理端仍按照标准位置顺序编辑，公开端负责反向展示。

## 16.4 每小时随机

随机模式必须满足：

* 同一个自然小时内顺序稳定
* 刷新页面不会改变顺序
* 下一个小时自动形成新顺序
* 不通过定时任务修改数据库位置
* 不实际覆盖人工排序位置

建议使用：

```text
board_id + 小时槽位 + group_id
```

计算稳定随机顺序。

小时槽位应使用站点配置时区，而不是依赖服务器本地时区。

# 21. 管理端群组管理

## 21.1 页码分页

```text
50 条
```

第一版本不提供每页数量切换。

## 21.2 返回结构

管理端列表 API 返回：

```ts
{
  items: Group[]
  page: number
  pageSize: 50
  totalItems: number
  totalPages: number
```

## 21.3 URL 状态

以下状态必须同步至 URL：

* 页码
* 搜索词
* 状态筛选
* 回收站筛选
* 排序字段
* 排序方向

示例：

```text
/admin/groups?page=3&status=published&sort=updated_at&direction=desc
```

## 21.4 状态变化规则

* 修改筛选时回到第一页
* 修改排序时回到第一页
* 修改搜索词时回到第一页
* 删除当前页最后一项并导致页面为空时，自动回到上一页
* 刷新后恢复当前状态
* 浏览器返回和前进恢复当前状态

## 21.5 分页器


同时展示：

```text
共 1,173 条，第 7 / 24 页
```

所有排序必须添加稳定次排序字段，避免相同值记录在不同页面间跳动。

## 21.7 保留现有能力

以下现有功能继续保留：

* 多状态筛选

* 多列排序
* 抽屉编辑

* 脏表单守卫

* 加群方式编辑
* 永久删除流程

# 23. 管理端板块管理

## 23.1 页面结构

板块管理页面由多个板块容器组成。

每个板块容器包括：

* 拖拽手柄
* 板块标题
* 启用或关闭状态
* 排序模式
* 当前成员数量
* 添加群组
* 编辑板块
* 删除板块
* 固定尺寸成员表格

## 23.2 板块拖拽

管理员可以拖拽调整板块之间的展示顺序。

拖拽完成后：

* 批量更新 `boards.position`
* 使用原子操作
* 复用版本冲突或等效并发保护
* 失败时回滚前端乐观排序并提示错误

## 23.3 成员表格

每个板块有一个独立小表格。

表格固定可视高度，超出后在表格内部滚动，不使用页码分页。

固定表格列：

| 列   | 内容          |
| --- | ----------- |
| 标题  | 群组标题        |
| 状态  | 已发布或已下架     |
| 操作  | 编辑、上移、下移、移除 |

最终像素高度和可见行数由 `ui-design.md` 确定。

## 23.4 成员操作

### 编辑

打开现有群组编辑抽屉。

### 上移

将群组与前一个成员交换位置。

第一项禁用上移。

### 下移

将群组与后一个成员交换位置。

最后一项禁用下移。

### 移除

只删除板块和群组之间的关联。

不得将该按钮命名为“删除群组”。

## 23.5 添加群组

添加选择器必须：

* 支持搜索
* 展示已发布群组
* 展示已下架群组
* 不展示回收站群组
* 清晰显示当前状态
* 对已加入当前板块的群组禁用或隐藏
* 防止重复添加

## 23.6 删除板块

删除板块需要二次确认。

删除后：

* 板块成员关联一并删除
* 群组本身不受影响
* 允许删除最后一个板块

## 23.7 未启用板块

未启用板块在管理端仍允许：

* 重命名
* 调整成员
* 调整排序
* 修改排序模式
* 删除

# 24. 数据库设计

## 24.1 群组表新增字段

```text

boards

- title
- is_enabled

- version
- created_at
```

字段含义：

```text
board_groups

- created_at
```

```text
PRIMARY KEY (board_id, group_id)
```

还需具备：

* 板块删除时级联删除成员关联
* 群组永久删除时清除成员关联

* 外键与当前 D1 配置兼容

## 24.5 位置维护

成员上移、下移和板块拖拽必须使用原子批量更新。

# 25. 数据迁移

## 25.1 `last_published_at` 回填

现有已发布群组：

* 优先使用现有可识别的发布时间
* 没有可靠发布时间时回填 `created_at`
* 不得统一回填部署时间

从未发布过的群组保持为空。

## 25.2 默认板块

迁移或新数据库初始化时创建一个空的“自定板块”。

该操作必须幂等：

* 重复运行迁移不能创建多个默认板块
* 已存在板块数据时不得重复插入

## 25.3 回滚和兼容

迁移执行前需要确认：

* 旧代码在短暂部署窗口内是否能容忍新增字段和表
* 新代码在迁移尚未完成时如何失败
* 本地测试数据库和 Workers 测试数据库同步更新

# 27. 性能要求

## 27.1 数据加载

* 所有群组和搜索结果保持 cursor pagination
* 管理端每页固定 50 条
* 发现新群最多 10 条
* 标签通过单次聚合查询
* 板块成员接口不得产生明显 N+1 查询
* 图片继续懒加载
* 图片保持固定比例，避免布局跳动

## 27.2 DOM 规模

板块成员管理表使用固定高度和内部滚动，避免同时渲染过长页面。

公开 Carousel 虽不设产品硬上限，但实现需要避免明显主线程阻塞。

## 27.3 主题性能

首屏主题设置不能依赖 Vue 挂载完成后才执行。

## 27.4 稳定随机

每小时随机排序必须可计算、可缓存、可测试，不运行每小时写数据库的定时任务。
