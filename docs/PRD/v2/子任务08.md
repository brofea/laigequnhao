# 1. 背景

当前管理端主要具备两个页面：

1. 所有群组
2. 统计数据

其中“所有群组”页面已经拥有：

* 群组筛选
* 群组排序
* 管理端搜索
* 群组新建
* 群组编辑抽屉
* 脏表单守卫
* 版本冲突处理
* 回收站
* 永久删除
* 图片上传
* 标签编辑
* 加群方式编辑

统计数据页面已经具备：

* Cloudflare Analytics Engine 代理数据
* 现有统计展示和错误处理

V2 增加完整的板块领域，并将管理端主要信息架构调整为三个页面：

1. 群组管理
2. 板块管理
3. 数据分析

本任务需要：

* 建立统一管理端页面壳层和导航
* 新增完整板块管理页面
* 将已有群组页面接入新的管理端壳层
* 将已有统计页面接入新的管理端壳层
* 保证三个页面切换、导航、页面标题、操作反馈和视觉语言一致
* 保留已有群组与统计业务能力
* 不提前实施子任务 09 的页码分页和表格响应式改造

本任务的核心不是单独增加一个板块页面，而是将管理端从两个相互独立的页面整理为一个结构统一、操作一致、可继续扩展的管理系统。

# 2. 任务目标

## 2.1 建立管理端三页面信息架构

正式管理端主要页面固定为：

```text
群组管理
板块管理
数据分析
```

* 使用同一管理端布局
* 使用同一导航
* 使用统一页面标题区域

* 查看所有板块
* 创建板块

* 上移成员
* 下移成员
* 移除成员

* 处理版本冲突

* 群组列表

# 7. 管理端页面信息架构

## 7.1 正式页面名称

管理端主要页面名称固定为：

```text
群组管理
板块管理
数据分析
```

原“所有群组”页面在导航中显示为：

```text
群组管理
```

页面内部可以继续使用“所有群组”作为列表区标题，但整体页面职责名称为“群组管理”。

原“统计数据”页面在导航中显示为：

```text
数据分析
```

具体页面主标题可根据 `ui-design.md` 使用“数据分析”或已确认文案。

## 7.2 路由

建议路由语义：

```text
/admin/groups
/admin/boards
/admin/analytics
```

实际路径必须根据现有项目路由和迁移兼容性在 `design.md` 中冻结。

如果现有统计路径不是 `/admin/analytics`：

* 可以保留现有路径
* 或建立重定向
* 不得无提示破坏旧书签和测试

## 7.3 默认管理页面

管理员进入 `/admin` 时，应根据现有行为：

* 重定向至群组管理
* 或使用当前已有默认页面

最终规则必须唯一。

不得根据上次访问页面建立未确认的持久化跳转。

# 9. 管理端导航

## 9.1 导航项

固定三个主要导航项：

1. 群组管理
2. 板块管理
3. 数据分析

## 9.2 当前页面

当前页面必须通过以下方式明确表达：

* 视觉高亮
* 文字或背景变化
* `aria-current="page"`
* 深浅主题均清晰

颜色不得作为唯一当前状态表达。

## 9.3 导航交互

导航必须支持：

* 鼠标
* 触摸
* Tab
* Enter
* 浏览器返回
* 浏览器前进
* 直接访问 URL

不得使用无法复制链接或无法历史导航的纯本地 Tab 状态代替 Router。

## 9.4 管理员会话

三个页面共享同一管理员会话。

页面切换不得：

* 重新登录
* 清除 CSRF Cookie
* 重新生成不必要会话
* 导致退出按钮消失
* 泄露页面内容给未认证用户

## 9.5 页面切换

切换页面时：

* 当前页面未保存表单需要遵守已有脏表单守卫
* 没有未保存数据时应立即切换
* 不显示整页白屏
* 导航保持可见
* 页面 Loading 仅出现在内容区域

# 10. 管理导航响应式

具体形式遵循 `ui-design.md`，可以是：

* 顶部水平导航
* 桌面侧栏、手机顶部导航
* 其他已经确认的管理端结构

无论采用何种形式，必须保证：

* 三个页面均可直接访问
* 当前页面清晰
* 不隐藏在难以发现的多层菜单中
* 手机端不会产生页面级横向溢出
* 导航文字可读
* 图标不是唯一表达

如果手机端使用横向可滚动导航：

* 必须有可发现性
* 当前项应自动滚动到可见
* 页面滚动不得被锁死

# 16. 板块展开与固定表格

用户已确认板块成员表采用：

```text
固定大小 + 内部滚动
```

而不是页码分页。

## 16.1 容器高度

成员表格需要具有统一或受控的固定可视高度。

具体像素值和可见行数由 `ui-design.md` 确定。

## 16.2 内部滚动

成员数量超过可视高度后：

* 表格主体内部纵向滚动
* 板块头部保持在容器外部
* 表头可按设计使用 sticky
* 页面本身仍可正常纵向滚动
* 鼠标滚轮到内部边界后应继续滚动页面

## 16.3 不分页

不得：

* 显示成员页码
* 每页加载成员
* 使用 cursor 分页
* 设置成员硬上限

接口按子任务 05 规则返回该板块全部成员。

## 16.4 多板块页面

多个板块同时存在时，每个板块拥有独立成员滚动区域。

不得让一个板块滚动状态影响另一个板块。

# 17. 板块折叠

当前产品已确认使用固定高度成员表，而未要求默认折叠。

因此第一版本：

* 板块容器默认显示成员表
* 不依赖折叠才能管理
* 可以根据 `ui-design.md` 提供折叠作为辅助能力
* 折叠不是验收阻塞项

如果实现折叠：

* 只保存到管理员当前浏览器
* 不保存到数据库
* 不改变公开板块状态
* 新建板块默认展开
* 展开状态不得影响拖拽排序

页面标题区域提供：

```text
创建板块
```

## 18.2 表单字段

至少包括：

* 板块标题
* 启用状态
* 排序模式

初始位置由后端自动追加到末尾，不向管理员暴露位置数字。

## 18.3 默认值

默认值以子任务 05 Contract 为准。

推荐：

```text
启用
手动正序
```

但不得与后端正式默认值不一致。

## 18.4 表单校验

使用共享 Zod Contract。

需要显示：

* 标题必填
* 标题超限
* 非法排序模式
* 其他字段错误

## 18.5 提交

提交期间：

* 禁止重复提交
* 显示 Loading
* Dialog 不意外关闭
* CSRF 正常发送

成功后：

* 关闭 Dialog
* 插入 API 返回的正式板块
* 保持后端顺序
* 显示成功 Toast
* 新板块可立即操作

失败后：

* 保留输入
* 显示字段或表单错误
* 不插入临时板块

---

# 19. 编辑板块

## 19.1 入口

每个板块头部提供“编辑”。

## 19.2 可编辑字段

* 标题
* 启用状态
* 排序模式

不得通过编辑 Dialog 修改板块位置。

## 19.3 版本

打开编辑 Dialog 时记录当前板块版本。

提交时发送：

```text
expectedVersion
```

成功后使用 API 返回的新版本和完整板块数据更新本地状态。

不得在前端自行计算：

```text
version + 1
```

## 19.4 状态切换

关闭板块后：

* 板块仍留在管理页面
* 成员仍显示
* 操作仍可用
* 状态标签变为“未启用”

重新启用后恢复“已启用”。

## 19.5 排序模式

修改排序模式后：

* 管理成员表的人工顺序不变
* 成员行不在前端重新排序
* 管理端仍按标准 position 顺序显示
* 公开端顺序由后端处理

---

# 20. 删除板块

## 20.1 入口

每个板块头部提供危险操作：

```text
删除
```

## 20.2 二次确认

删除前必须显示确认 Dialog。

确认内容至少包括：

* 板块标题
* 删除后成员关联会被移除
* 群组本身不会被删除
* 操作不可恢复

不得让管理员误以为会删除群组。

## 20.3 默认板块

“自定板块”和其他板块完全相同，可以删除。

不得：

* 隐藏删除按钮
* 显示系统保留标记
* 删除后自动重建

## 20.4 最后一个板块

允许删除最后一个板块。

成功后进入零板块状态。

## 20.5 提交

需要发送：

* 板块 ID
* expectedVersion
* mutation token，如 Contract 要求

成功后：

* 从页面移除板块
* 使用后端返回的最新顺序或重新同步
* 显示成功 Toast

失败后：

* 保留板块
* 关闭或保留确认 Dialog按统一规范处理
* 显示错误
* 不局部移除成员

# 21. 板块拖拽排序

## 21.1 范围

拖拽只用于：

```text
板块之间排序
```

不用于：

* 板块成员行排序
* 群组管理表格
* 公开端 Carousel

## 21.2 拖拽手柄

每个板块头部提供明确拖拽手柄。

不得让整个板块容器都成为拖拽区域，避免与：

* 内部滚动
* 按钮点击
* 文本选择
* 表格操作

冲突。

## 21.3 桌面交互

支持：

* 鼠标拖拽
* 触控板指针操作
* 拖动占位
* 目标位置指示
* 拖拽中的视觉抬升

## 21.4 触摸

管理端手机是否支持触摸拖拽，取决于所用实现的可用性。

如果触摸拖拽不可靠，必须提供键盘或按钮后备方式，例如：

* 上移板块
* 下移板块

具体后备方式在 `design.md` 中冻结。

不得让手机管理员完全无法调整顺序。

## 21.5 键盘

拖拽排序应支持可访问的键盘后备。

可以采用：

* 聚焦拖拽手柄后通过按键进入移动模式
* 提供上移和下移菜单项
* 其他符合可访问性规范的方式

不能只支持鼠标。

## 21.6 拖拽结果

拖拽完成后向后端提交完整顺序和版本信息。

不得只修改本地 position 而不保存。

---

# 22. 板块拖拽乐观更新

## 22.1 拖拽完成

前端可以立即显示新顺序，再发起后端请求。

## 22.2 请求期间

需要：

* 防止同时开始第二个重排请求
* 或将后续拖拽排队
* 显示保存状态
* 保持其他板块操作合理禁用

## 22.3 成功

使用后端返回的：

* 正式顺序
* 最新版本

替换本地状态。

## 22.4 失败

失败时：

* 回滚至请求前顺序
* 恢复版本
* 显示错误 Toast 或 Banner
* 不保留部分乐观顺序
* 不影响成员表内容

## 22.5 版本冲突

后端返回版本冲突时：

* 回滚乐观顺序
* 显示冲突提示
* 获取最新板块顺序
* 提示管理员重新执行拖拽

不得自动覆盖其他管理员排序。

---

# 23. 排序过程中的其他操作

板块重排请求进行中，建议暂时禁用：

* 其他板块拖拽
* 删除板块
* 修改板块位置相关操作

可以继续允许：

* 查看成员
* 打开群组编辑

是否允许编辑板块标题由实现复杂度决定，但必须避免版本更新互相覆盖。

最安全策略是短暂禁用板块配置写操作，直到重排完成。

# 24. 固定高度成员表格

每个板块的成员表格固定三列：

| 列  | 内容          |
| -- | ----------- |
| 标题 | 群组标题        |
| 状态 | 已发布或已下架     |
| 操作 | 编辑、上移、下移、移除 |

不得增加会显著降低密度的列，例如：

* 标签
* 平台
* 点赞
* 加群方式
* 创建时间

这些信息可以通过编辑抽屉查看。

# 25. 成员标题列

## 25.1 内容

展示群组标题。

## 25.2 长标题

* 单行或按 `ui-design.md` 的有限行数显示
* 超出使用省略号
* Tooltip 或可访问名称显示完整标题
* 不撑破表格

## 25.3 点击

标题本身可作为编辑入口，或只通过“编辑”按钮进入。

最终方式必须保持操作明确。

如果标题可点击：

* 仍保留可访问名称
* 不与行拖动冲突，因为成员不支持拖拽

# 26. 成员状态列

只需展示：

```text
已发布
已下架
```

正常情况下不应出现：

* 回收站
* 永久删除
* 不存在记录

如果 API 返回异常状态：

* 不公开显示敏感细节
* 阻止不适用操作
* 显示数据异常反馈
* 允许刷新

状态不能只通过颜色表达。

# 27. 成员操作列

固定操作：

* 编辑
* 上移
* 下移
* 移除

可以根据宽度使用：

* 图标加文字
* 图标按钮
* 操作菜单

但必须保证四种操作都能发现和使用。

## 27.1 编辑

打开现有群组编辑抽屉。

## 27.2 上移

将成员与标准人工顺序中的前一项交换。

## 27.3 下移

将成员与标准人工顺序中的后一项交换。

## 27.4 移除

只解除板块关联。

不得命名为：

```text
删除群组
```

---

# 28. 成员上移与下移

## 28.1 顺序语义

管理端成员表始终按照标准人工 position 正序显示。

即使板块为：

* 手动倒序
* 每小时随机

上移和下移仍修改人工顺序。

## 28.2 边界

第一项：

* 上移按钮禁用

最后一项：

* 下移按钮禁用

只有一个成员时：

* 上移和下移均禁用

## 28.3 请求

移动请求至少携带：

* 板块 ID
* 群组 ID
* direction
* expectedVersion
* mutation token

## 28.4 乐观更新

可以乐观交换两行。

请求失败时：

* 恢复原顺序
* 恢复原版本
* 显示错误

## 28.5 请求锁

同一板块成员移动进行中时：

* 禁止再次移动
* 或严格排队

不得同时发送多个基于同一旧版本的移动请求。

## 28.6 成功

使用 API 返回的新版本和正式成员顺序同步。

---

# 29. 移除成员

## 29.1 语义

“移除”只解除：

```text
板块 ↔ 群组
```

关系。

群组仍然：

* 存在于群组管理
* 保持当前状态
* 保留头像、标签和加群方式
* 可以加入其他板块

## 29.2 确认

是否每次移除都二次确认，由 `ui-design.md` 和操作风险决定。

推荐：

* 普通移除可使用轻量确认
* 至少明确写“只会从当前板块移除”

## 29.3 成功

* 行从当前表格移除
* 后续行位置更新
* 成员数量更新
* 板块版本更新
* Toast 提示成功

## 29.4 失败

* 恢复行和顺序
* 恢复数量和版本
* 显示错误
* 不删除群组

---

# 30. 编辑板块中的群组

## 30.1 复用现有抽屉

“编辑”操作必须复用当前群组管理页面使用的群组编辑抽屉和表单。

不得为板块页面建立第二套群组编辑器。

## 30.2 保留能力

从板块页面打开抽屉时，仍必须支持：

* 标题
* 简介
* 平台
* 标签
* 加群方式
* 图片
* 状态
* 版本冲突
* 脏表单守卫
* Escape
* beforeunload
* 路由切换守卫

## 30.3 编辑后同步

编辑成功后，板块页面应更新对应成员的：

* 标题
* 状态
* 其他当前表格使用字段

如群组被改为已下架：

* 仍保留在板块成员表
* 状态变为“已下架”

如群组被重新发布：

* 状态变为“已发布”

如群组被移入回收站：

* 子任务 05 后端会删除关联
* 板块页面需要移除该成员
* 成员数量和版本根据后端结果更新或重新同步

## 30.4 路由切换

群组编辑抽屉有未保存修改时，点击管理导航切换页面必须触发现有脏表单守卫。

# 31. 添加群组

## 31.1 入口

每个板块头部提供：

```text
添加群组
```

## 31.2 选择器形式

可以使用：

* Dialog
* Popover
* 抽屉
* 其他已确认管理端组件

需支持较多群组的搜索，不得直接渲染全部群组。

## 31.3 搜索

候选搜索使用子任务 05 的候选 API。

支持按当前后端能力查询。

至少需要通过标题快速定位群组。

## 31.4 候选状态

允许：

* 已发布
* 已下架

不允许：

* 回收站
* 永久删除
* 产品未允许的其他状态

## 31.5 状态显示

每个候选必须清晰显示：

* 标题
* 状态

不得只显示标题，使管理员无法区分已下架成员。

## 31.6 已加入成员

已经属于当前板块的群组：

* 不显示
* 或显示为已加入并禁用

具体采用子任务 05 Contract 规定方式。

添加接口仍需防止重复。

---

# 32. 候选查询分页

候选搜索可以使用：

* cursor
* 页码
* 限量搜索建议

具体由子任务 05 Contract 决定。

本任务不得一次加载数据库全部群组。

候选分页不等于板块成员表分页。

---

# 33. 添加单个或多个成员

当前后端能力若只支持单个添加，第一版本可逐个添加。

如果 Contract 支持批量添加，可提供多选。

不得在前端模拟批量并忽略中间失败。

无论单选或多选：

* 已发布和已下架都可选
* 添加后追加到标准人工顺序末尾
* 板块版本更新
* 成员表立即同步

---

# 34. 添加成员成功

成功后：

* 关闭选择器或保留继续添加能力，按设计确认
* 新成员出现在表格末尾
* 状态正确
* 成员数量更新
* 板块版本更新
* 显示成功反馈

如果板块当前为手动倒序或每小时随机，管理表仍把新成员显示在人工顺序末尾。

---

# 35. 添加成员失败

需要区分：

* 板块不存在
* 群组不存在
* 群组已在板块中
* 群组已进入回收站
* 版本冲突
* CSRF 失败
* 网络失败

失败时：

* 不插入临时成员
* 保留搜索输入
* 允许刷新候选
* 必要时刷新板块版本

# 36. 空板块

## 36.1 定义

板块成员列表长度为 0。

## 36.2 显示

空板块仍显示完整板块容器，包括：

* 标题
* 状态
* 排序模式
* 添加群组
* 编辑
* 删除

成员区域显示明确空状态。

## 36.3 空状态操作

空状态中可提供：

```text
添加第一个群组
```

操作。

不得因为为空隐藏板块。

# 37. 零板块

## 37.1 定义

管理端板块 API 返回：

```text
[]
```

## 37.2 显示

页面显示完整零状态，包括：

* 当前还没有板块
* 创建板块说明
* “创建板块”主操作

不得：

* 自动创建“自定板块”
* 显示错误
* 伪造一个本地默认板块
* 阻止管理员访问其他管理页面

## 37.3 页面导航

零板块状态下：

* 群组管理可正常切换
* 数据分析可正常切换

* 主题可切换

# 38. 初始加载状态

板块页面首次进入时：

* 页面壳层和导航立即显示
* 板块内容区显示 Skeleton
* 不使用全屏遮罩阻止页面切换
* 创建按钮可按设计在加载期间禁用
* 不显示旧页面残留数据

---

# 39. 页面级加载错误

板块初始列表加载失败时：

* 显示页面内容区 ErrorBanner
* 提供“重新加载板块”
* 导航保持可用
* 不影响群组管理和数据分析
* 不自动退出登录，除非错误确实是会话失效

## 39.1 会话失效

会话失效按照现有认证流程处理。

不得将 401 显示为普通网络错误后继续展示管理数据。

---

# 40. 区域级错误

以下操作失败只影响对应范围：

* 单板块更新失败
* 单板块成员加载失败
* 单成员移动失败
* 添加候选加载失败
* 删除确认失败

不得因为一个板块操作失败而清空全部页面。

---

# 41. 数据读取策略

## 41.1 板块列表与成员

根据子任务 05 API 设计，可以采用：

### 方案 A：一次加载全部板块和成员

适合板块和成员量可控。

### 方案 B：先加载板块摘要，再批量或按需加载成员

适合成员较多。

最终策略必须：

* 避免逐板块 N+1
* 支持固定高度成员表
* 支持版本同步
* 支持局部重试

## 41.2 不得前端拼接管理事实

成员数量、版本和状态应使用后端正式返回值。

---

# 42. 板块本地状态

每个板块至少维护：

* 板块元数据
* 成员数据
* 成员加载状态
* 成员错误
* 当前写操作状态
* 当前版本
* 是否正在拖拽
* 是否正在移动成员

## 42.1 单一来源

不得为：

* 板块列表
* 拖拽组件
* 编辑 Dialog
* 成员表

维护互相不一致的多个板块副本。

应建立集中页面状态或 store/composable。

不得仅为此任务引入新的大型状态管理库。

---

# 43. 乐观更新范围

允许乐观更新：

* 板块拖拽顺序
* 成员上移和下移
* 成员移除
* 启用状态切换，如设计适合

创建和删除可根据实现选择保守更新。

所有乐观更新必须：

* 保存请求前快照
* 失败时完整回滚
* 成功后使用服务器响应覆盖
* 处理版本更新
* 防止旧响应覆盖新状态

---

# 44. 请求竞态

必须处理：

* 快速连续拖拽
* 连续上移或下移
* 编辑板块同时后台刷新
* 添加成员时板块版本变化
* 群组编辑后成员状态变化
* 板块删除后旧成员请求返回
* 页面切换后旧请求返回

最终状态必须与当前：

* 路由
* 板块 ID
* 版本
* 请求序号

一致。

---

# 45. 版本冲突

## 45.1 适用操作

需要处理版本冲突：

* 编辑板块
* 删除板块
* 板块重排
* 添加成员
* 移除成员
* 上移成员
* 下移成员

## 45.2 冲突反馈

冲突时显示明确提示，例如：

```text
该板块已被其他管理员修改，已为你加载最新内容。
```

不得只显示：

```text
请求失败
```

## 45.3 冲突处理

推荐流程：

1. 回滚乐观状态
2. 显示冲突提示
3. 重新获取最新板块或完整板块列表
4. 更新版本
5. 要求管理员重新执行操作

不得自动重新提交会覆盖他人修改的写操作。

## 45.4 编辑 Dialog

编辑 Dialog 发生冲突时：

* 保留管理员输入
* 展示服务器最新数据
* 提供重新应用或关闭选择
* 具体行为沿用现有群组版本冲突模式

# 46. CSRF 错误

* 不进行乐观状态保留
* 回滚本地变更
* 显示安全错误
* 根据现有认证策略要求重新登录或刷新会话

不得在前端自动绕过或重试无效 CSRF。

# 47. 一次性突变令牌

以下操作使用子任务 05 规定的 mutation token：

* 板块重排
* 删除板块
* 成员上移
* 成员下移
* 成员移除
* 其他多行操作

前端需要：

* 每次新逻辑操作生成新令牌
* 同一次请求重试复用相同令牌，按现有规范
* 不在不同操作之间复用
* 不持久化到长期存储
* 不暴露到 URL
* 不记录到用户可见日志

# 61. 性能要求

## 61.1 板块数量

板块数量不设硬上限。

页面不得为每个板块注册大量全局事件。

## 61.2 成员数量

成员数量不设硬上限。

固定高度和内部滚动可以限制页面高度，但 DOM 仍可能较大。

实现应：

* 避免重复计算
* 避免每行独立全局监听
* 使用稳定 Key
* 不为每个成员请求完整群组详情
* 不产生 N+1 API 请求

## 61.3 候选搜索

使用 debounce 和分页或限量结果。

不得每输入一个字符立即发送请求。

## 61.4 拖拽

拖拽时避免重新渲染所有成员表内容。
