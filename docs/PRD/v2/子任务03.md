# 2. 任务目标

## 2.1 建立正式设计基础

将 `ui-design.md` 中已经确认的设计 Token 转化为正式生产代码，并保证：

* Token 命名语义化
* 浅色和深色映射完整
* Tailwind 与 CSS 自定义属性保持一致
* 组件不需要直接引用散落色值
* 后续功能可以稳定扩展
* 现有页面可逐步迁移，不要求一次性重写全部页面

## 2.2 建立三态主题系统

支持：

```ts
type ThemePreference = 'system' | 'light' | 'dark'
```

默认偏好：

```ts
'system'
```

系统需要同时区分：

```ts
type EffectiveTheme = 'light' | 'dark'
```

其中：

* `ThemePreference` 表示用户选择
* `EffectiveTheme` 表示当前实际显示主题

## 2.3 重构全站顶栏

正式顶栏需要实现：

左侧：

* 网站 Logo
* 网站名称

右侧：

* 主题模式控件
* GitHub 支持按钮
* 添加新群组按钮

顶栏必须根据宽度自动调整，但不得隐藏核心操作或改成汉堡菜单。

## 2.4 建立公共状态样式

建立后续组件可复用的基础状态，包括：

* Hover
* Active
* Focus-visible
* Disabled
* Loading
* Selected
* Success
* Warning
* Error
* 信息提示
* Skeleton 基础色
* 遮罩基础色

本任务主要建立基础规范和样式能力，不负责完成所有业务组件的最终视觉重构。

# 6. Token 分层

正式 Token 应尽量分为三层。

## 6.1 原始 Token

包括但不限于：

* 原始色阶
* 间距尺度
* 字号尺度
* 行高尺度
* 圆角尺度
* 阴影尺度
* 动画时长
* 缓动函数
* 层级数值

原始 Token 不应被业务组件大量直接使用。

## 6.2 语义 Token

包括：

* `background`
* `surface`
* `text-primary`
* `text-secondary`
* `border-default`
* `accent`
* `danger`
* `focus-ring`

正式组件应优先使用语义 Token。

## 6.3 组件 Token

仅为确有必要的稳定组件尺寸建立，例如：

* 顶栏高度
* 页面最大宽度
* 搜索框高度
* 卡片圆角
* Dialog 最大宽度
* 表格行高

不得为每个局部间距创建大量难以维护的组件变量。

# 7. Tailwind Token 映射

## 7.1 目标

Tailwind 配置需要映射到 CSS 自定义属性，使正式组件可以使用语义化 class，而不是散落硬编码色值。

示意方向：

```ts
colors: {
  background: '...',
  surface: '...',
  foreground: '...',
  muted: '...',
  border: '...',
  accent: '...',
  danger: '...'
}
```

具体实现必须兼容项目当前 Tailwind 版本和配置方式。

## 7.2 约束

不得：

* 删除仍被现有页面依赖的 Token
* 一次性重命名全部旧 class 而不提供迁移方案
* 在 Vue 模板中大面积使用任意十六进制颜色
* 在浅色和深色主题中维护两套完全分离的组件 class
* 为了视觉便利引入新的大型 UI 框架

## 7.3 渐进迁移

本任务应为旧样式提供合理的过渡方案：

* 新代码必须使用正式语义 Token
* 本任务直接涉及的顶栏必须完成迁移
* 现有页面中容易安全替换的全局背景和文字可迁移
* 尚未进入对应子任务的复杂组件不要求本任务全部重写
* 旧硬编码颜色需要在审计结果中记录，交由对应后续任务处理

# 8. 三态主题模型

## 8.1 类型

正式共享前端类型：

```ts
export type ThemePreference = 'system' | 'light' | 'dark'
export type EffectiveTheme = 'light' | 'dark'
```

如项目已有合适的共享类型位置，应按当前目录规范放置。

## 8.2 默认行为

首次访问且本地没有合法主题偏好时：

```text
ThemePreference = system
```

实际主题通过操作系统或浏览器的：

```text
prefers-color-scheme
```

决定。

## 8.3 用户手动选择

用户可以明确选择：

* 自动
* 浅色
* 深色

选择结果写入 localStorage。

用户选择“自动”时，保存的偏好应是：

```text
system
```

而不是删除后依赖不明确的默认行为，除非现有 Spec 明确规定删除键。最终存储规则必须唯一并有测试。

## 8.4 实际主题计算

规则：

```text
preference = light → effectiveTheme = light
preference = dark  → effectiveTheme = dark
preference = system → 根据 prefers-color-scheme
```

## 8.5 非法数据

localStorage 中出现以下情况时必须回退到 `system`：

* 空字符串
* 未知字符串
* JSON 损坏
* 旧版本无效值
* 非字符串值

不得因为主题存储异常阻止应用加载。

# 9. localStorage 持久化

## 9.1 存储键

使用一个稳定、具备项目命名空间的存储键。

存储键必须：

* 在代码中集中定义
* 不散落硬编码
* 不与现有 localStorage 键冲突
* 在测试中可控制
* 在文档中记录

## 9.2 存取安全

读取和写入 localStorage 必须考虑：

* 浏览器隐私模式
* 存储被禁用
* 存储空间异常
* SSR 或非浏览器测试环境
* `SecurityError`

存储失败不能阻止主题切换在当前会话中生效。

## 9.3 事件同步

如架构允许，建议支持同域多个标签页之间通过 `storage` 事件同步主题偏好。

如果实现该能力，必须测试：

* 一个标签页切换主题
* 另一个标签页更新显示
* 当前标签页自身写入不会错误重复处理

如子任务 01 认定该能力超出现有架构需要，可以不实现，但必须在设计说明中明确。

# 10. 系统主题监听

## 10.1 自动模式

当用户偏好为 `system` 时：

* 首次读取系统主题
* 监听系统主题变化
* 系统从浅色切换为深色时立即更新
* 系统从深色切换为浅色时立即更新

## 10.2 手动模式

用户偏好为 `light` 或 `dark` 时：

* 系统主题变化不得覆盖用户选择
* 可以保留媒体查询监听，但不得修改实际主题
* 切回 `system` 时应立即采用当前系统状态

## 10.3 兼容性

监听方式需要兼容目标浏览器。

如需要兼容旧式媒体查询监听 API，应根据项目现有浏览器支持范围决定，不得无依据添加复杂兼容代码。

## 10.4 生命周期

监听器必须：

* 只注册必要次数
* 在对应生命周期正确清理
* 避免热更新或重复挂载产生多个监听器
* 在测试环境中可替换或模拟

# 11. DOM 主题标记

## 11.1 根节点

实际主题统一应用到：

```text
document.documentElement
```

建议通过：

* class
* `data-theme`
* 或 `ui-design.md` 指定的正式方式

实现。

## 11.2 唯一来源

项目中不得同时存在互相竞争的多套主题标记，例如：

* 一部分组件依赖 `.dark`
* 一部分组件依赖 `data-theme`
* 一部分组件只依赖媒体查询

必须确定唯一正式机制。

如 Tailwind 使用 class 模式，根节点状态应与其保持一致。

## 11.3 可选元数据

如设计要求，应同步设置：

```html
<meta name="color-scheme">
```

或等效能力，改善浏览器原生控件与页面主题一致性。

具体范围由技术实现决定，但必须避免表单控件与页面主题明显冲突。

# 12. 首屏防闪烁

## 12.1 问题定义

如果主题只在 Vue 挂载后读取，深色用户会先看到浅色页面，再切换为深色，形成明显闪烁。

本任务必须避免此问题。

## 12.2 初始化时机

在应用主要 CSS 和 Vue 首屏渲染产生可见内容前，尽早执行最小主题初始化逻辑。

初始化逻辑负责：

1. 安全读取本地偏好
2. 校验偏好
3. 必要时读取系统主题
4. 将实际主题应用到根节点

## 12.3 约束

首屏脚本必须：

* 尽可能小
* 不依赖 Vue
* 不依赖异步请求
* 不访问后端
* 出错时安全回退
* 与正式主题管理模块使用一致规则
* 不形成两套彼此漂移的主题判断逻辑

建议通过共享常量或可生成的内联逻辑减少重复，但不得为了完全去重引入复杂构建流程。

## 12.4 测试

Playwright 需要验证：

* localStorage 为深色时首次截图没有明显浅色闪屏
* system 为深色时首次加载直接进入深色
* 非法本地值不会导致页面空白或脚本错误

# 13. 正式主题管理模块

## 13.1 推荐职责

建立一个集中主题管理能力，负责：

* 当前偏好
* 当前实际主题
* 初始化
* 设置偏好
* localStorage 存取
* 系统媒体查询监听
* 根节点同步
* 可选跨标签页同步
* 组件订阅

具体使用 composable、store 或其他现有架构方式，由子任务 01 审计结果决定。

不得仅为了主题引入新的大型状态管理依赖。

## 13.2 API 语义

正式 API 至少应能表达：

```ts
themePreference
effectiveTheme
setThemePreference(...)
```

如提供初始化或销毁方法，其调用位置必须唯一且明确。

## 13.3 单一实例

全局主题监听和 DOM 更新应由单一实例管理。

不得每个主题按钮组件各自：

* 读取 localStorage
* 监听系统主题
* 修改根节点
* 维护独立状态

# 14. 主题控件

## 14.1 三个状态

控件必须让用户能够明确选择：

* 自动
* 浅色
* 深色

不得只提供一个图标，让用户不断点击并猜测当前处于哪个状态。

## 14.2 交互形式

正式形式依据已确认的 `ui-design.md`，可以是：

* 图标按钮打开菜单
* 分段选择器
* 下拉菜单
* 其他已确认形式

但必须满足：

* 当前偏好可识别
* 三个选项名称清楚
* 键盘可操作
* 触摸可操作
* 不把实际主题与用户偏好混为一谈

例如用户选择“自动”，系统当前显示深色时，控件仍应表达偏好是“自动”。

## 14.3 图标

可使用：

* 自动模式对应的系统或设备图标
* 浅色对应太阳图标
* 深色对应月亮图标

图标必须具有可访问文本。

## 14.4 反馈

切换主题应立即生效，不需要刷新页面。

除非 `ui-design.md` 明确要求，不需要用 Toast 提示每次主题切换，以免产生不必要干扰。

# 15. 顶栏信息架构

## 15.1 左侧区域

固定包含：

* 网站 Logo
* 网站名称

点击 Logo 或网站名称的行为应延续当前首页导航规则。

如果当前系统已规定点击后返回首页，应保留。

是否清除搜索参数和详情参数，必须遵守现有路由规范或总 PRD，不得在本任务中重新定义业务导航。

## 15.2 右侧区域

固定包含：

1. 主题模式控件
2. GitHub 支持按钮
3. 添加新群组按钮

排列顺序不得由 Agent 随意改变。

## 15.3 GitHub 支持按钮

应使用项目现有或站点配置中的 GitHub 地址。

不得：

* 在组件中硬编码临时地址
* 生成不存在的仓库链接
* 连接到视觉模板作者的 GitHub
* 因地址缺失而默默隐藏按钮

如当前配置中没有 GitHub 地址，应通过现有 `siteConfig` 或等效配置补充前端配置项，不需要后端接口。

外部链接应遵守项目现有安全规范。

## 15.4 添加新群组按钮

点击后进入现有群组提交流程。

不得在本任务中重写提交表单业务。

宽屏文案：

```text
+ 添加新的群组
```

窄屏文案：

```text
添加群
```

不得缩减为只有一个加号。

# 16. 顶栏宽屏行为

在有足够空间时：

* Logo 和网站名完整显示
* 主题控件显示图标和文字
* GitHub 支持按钮显示图标和文字
* 添加新群组按钮显示完整文案
* 按钮之间保持 `ui-design.md` 规定的间距
* 不出现文字折行
* 不遮挡内容

主题控件的文字应表达当前用户偏好：

* 自动
* 浅色
* 深色

---

# 17. 顶栏窄屏行为

宽度不足时：

* 左侧 Logo 保留
* 网站名称原则上保留
* 主题控件仅显示图标
* GitHub 支持按钮仅显示图标
* 添加按钮显示“添加群”
* 不使用汉堡菜单
* 不隐藏主题控件
* 不隐藏 GitHub 按钮
* 不隐藏添加按钮
* 不产生页面级横向滚动

如果极窄宽度下 Logo、网站名称和全部操作无法同时合理容纳，应优先按 `ui-design.md` 中的已确认策略处理，例如：

* 缩小间距
* 缩小 Logo
* 限制网站名称最大宽度
* 对网站名称进行视觉截断

不得临时删除功能。

# 18. 顶栏布局规则

## 18.1 页面关系

需要明确顶栏是：

* 静态
* Sticky
* 或其他已确认行为

必须严格遵守 `ui-design.md`，不得由实现 Agent自行改变。

## 18.2 高度稳定

# 20. 公共基础状态样式

本任务需要建立后续组件可直接使用的公共基础样式。

## 20.1 Focus-visible

所有：

* 按钮
* 链接
* 输入框
* 图标按钮
* 菜单项
* 可点击卡片

应具备一致、清晰的键盘焦点语言。

不得通过全局规则简单移除 outline。

## 20.2 Disabled

禁用状态必须同时通过以下方式表达：

* 视觉弱化
* 指针或交互反馈
* 原生禁用语义或 ARIA

不得只降低透明度而保留误导性的 Hover。

## 20.3 Hover 与 Active

Hover 与 Active 状态应：

* 使用语义 Token
* 在浅色和深色中均清晰
* 不引起明显布局跳动
* 不依赖改变边框宽度造成元素尺寸变化

## 20.4 状态色

成功、警告、错误和信息状态必须具有：

* 背景色
* 前景色
* 边框或图标表达
* 深色映射

颜色不能作为唯一信息来源。

## 20.5 Skeleton

建立统一 Skeleton 基础：

* 背景色
* 高光色
* 动画时间
* 深色模式
* 减少动态效果降级

本任务不负责为所有页面编写具体 Skeleton 布局。

## 20.6 遮罩

建立 Dialog 和抽屉将复用的遮罩 Token，但不在本任务中正式实现群组详情 Dialog。

prefers-reduced-motion: reduce

* 菜单打开动画
* Hover 位移动画

主题切换过渡如存在，应短暂、克制，并遵守 `ui-design.md`。
