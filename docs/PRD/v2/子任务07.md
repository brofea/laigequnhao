# 1. 背景

当前公开端已经具备：

* 首页群组卡片网格
* 旋转排位算法
* cursor pagination
* 无限滚动
* 关键词搜索
* debounce
* URL 搜索同步
* 群组提交
* 匿名点赞
* QR 码
* 复制能力

V2 将首页从单一群组目录重构为一个同时支持内容发现和完整检索的导航首页。

默认首页将包含：

1. 顶栏
2. 主搜索框
3. 发现新群
4. 所有标签
5. 零个、一个或多个自定义板块
6. 所有群组

搜索框存在有效内容时，页面切换为：

1. 顶栏
2. 位置不变的主搜索框
3. 搜索结果

本任务不重新实现卡片、Carousel 或详情弹窗，而是复用：

* 子任务 03 的顶栏、主题与设计 Token
* 子任务 05 的公开板块 API
* 子任务 06 的群组卡片、Carousel、详情弹窗和 `?group=` URL 控制器

本任务的核心难点不是单纯排列组件，而是建立稳定的首页数据编排和搜索状态机，处理：

* 多个独立首页区域
* 区域级加载与错误
* 搜索请求竞态
* cursor pagination
* 浏览器历史
* `q` 与 `group` 查询参数共存
* 页面滚动恢复
* 下架数据过滤
* 响应式 Grid 与 Carousel
* 现有旋转排序兼容
* 深链接背景页面加载

# 2. 任务目标

## 2.1 完成默认首页

搜索框为空时，正式首页按照固定顺序展示：

1. 顶栏
2. 主搜索框
3. 发现新群
4. 所有标签

6. 所有群组

* 调换主要区域顺序
* 因某个区域为空而打乱其他区域顺序
* 将所有群组改成 Carousel
* 公开展示已下架群组

## 2.2 完成搜索模式

搜索框存在有效关键词时：

* 无需按 Enter
* 经过 debounce 自动搜索
* 页面只展示搜索结果区域
* 默认首页内容隐藏
* 搜索框位置保持稳定
* 搜索词同步至 URL
* 搜索结果继续使用 cursor pagination
* 清空搜索后恢复默认首页

## 2.3 完成数据发现区域

实现：

* 最近发布的 10 个群组
* 所有已发布群组标签统计
* 管理员配置的已启用板块
* 启用但无公开成员的空板块

## 2.4 保留完整目录能力

“所有群组”继续：

* 使用 Grid
* 只展示已发布群组
* 使用现有默认旋转排序
* 使用 cursor pagination
* 支持无限滚动
* 最终可浏览全部群组

## 2.5 建立区域级容错

默认首页的各数据区域应尽量独立加载。

某一区域失败时：

* 不应使整个首页白屏
* 不应阻止搜索框使用
* 不应阻止其他区域显示
* 应在该区域展示重试能力

## 2.6 保证 URL 与历史一致

需要同时支持：

```text id="22blpt"
/
?q=<keyword>
?group=<group_id>
?q=<keyword>&group=<group_id>
```

并保证：

* 搜索历史可返回和前进
* 群组详情历史可返回和前进
* 关闭详情不丢失搜索词
* 直接深链接背景页面正确
* 分享链接不被首页逻辑污染

# 9. 搜索模式判定

## 9.1 原始输入与有效查询

需要区分：

```ts id="zjbah8"
rawSearchInput
effectiveSearchQuery
```

推荐规则：

```text id="xhmzgw"
effectiveSearchQuery = rawSearchInput.trim()
```

当有效查询为空时，进入默认首页。

只输入：

* 空格
* Tab
* 换行

应视为空搜索。

## 9.2 URL 来源

页面初始化时从：

```text id="lek92k"
route.query.q
```

恢复搜索内容。

非法或非字符串 `q` 参数应安全处理。

## 9.3 模式切换

```text id="bh3pz8"
effectiveSearchQuery === ''
→ Default Home Mode

effectiveSearchQuery !== ''
→ Search Mode
```

不得依赖用户是否按过 Enter。

# 11. Debounce

## 11.1 基本行为

用户输入后经过 debounce 发起搜索。

具体时长沿用当前成熟实现，或根据审计结果在 `design.md` 中冻结。

不得无依据频繁更改。

## 11.2 URL 更新时间

需要明确输入与 URL 的同步时机。

推荐：

* 用户输入立即更新本地输入状态
* debounce 完成后使用 Router 更新 `q`
* 搜索请求以 URL 中稳定查询词为准

另一可接受方案是：

* 输入后立即 `replace` URL
* 请求仍 debounce

最终必须避免每个字符产生大量浏览器历史记录。

## 11.3 历史策略

普通连续输入应使用：

```text id="vmmom5"
router.replace
```

避免：

```text id="35ppfm"
c
ca
cam
camp
campus
```

全部进入历史。

当用户通过标签点击从默认首页进入搜索模式时，可以使用一次 `router.push`，使浏览器返回可回到默认首页。

具体策略必须在 `design.md` 中统一。

## 11.4 请求次数

同一个稳定查询词不得因以下原因重复请求：

* 输入状态和 URL watcher 同时触发
* 组件重复挂载
* 浏览器前进恢复
* 详情 Dialog 打开或关闭
* 主题切换

# 15. 请求和状态架构

## 15.1 区域状态独立

默认首页至少维护以下独立状态：

```text id="fa0nfm"
discoverState
tagsState
boardsState
allGroupsState
```

搜索模式维护：

```text id="vaj6cy"
searchResultsState
```

群组详情状态由子任务 06 管理。

## 15.2 状态结构

每个区域至少表达：

* idle
* loading
* success
* empty
* error
* retrying

分页区域还需表达：

* initialLoading
* loadingMore
* hasMore
* nextCursor
* loadMoreError

## 15.3 不使用单一全页 Loading

默认首页不得等待所有请求完成后一次性显示。

推荐：

* 页面骨架立即显示
* 各区域独立 Skeleton
* 成功区域先展示
* 失败区域局部显示错误

## 15.4 请求取消

页面模式切换、查询词变化或组件卸载时，应取消不再需要的请求。

尤其：

* 搜索词 A 请求未完成时输入 B
* B 结果不得被 A 覆盖
* 清空搜索后旧搜索请求不得覆盖默认首页状态

# 16. 首页 API 编排

## 16.1 聚合接口与独立接口

本任务允许选择：

### 方案 A：区域独立接口

* 发现新群
* 标签统计
* 公开板块
* 所有群组

优点：

* 区域级重试自然
* 容错隔离清晰
* 可独立缓存

### 方案 B：首页聚合接口 + 分页接口

聚合接口返回：

* 发现新群
* 标签
* 板块

所有群组继续独立 cursor API。

优点：

* 减少首屏请求数
* 同一请求中获得主要发现区域

最终方案由 `design.md` 根据现有后端架构决定。

无论采用何种方案，都必须满足区域级错误展示。

如果聚合接口整体失败，需要能够区分或合理恢复，不得导致搜索框不可用。

## 16.2 禁止 N+1

动态板块必须使用子任务 05 已优化的公开板块接口。

不得：

* 先请求板块列表
* 再逐板块请求成员

# 17. 发现新群

## 17.1 定义

展示最近一次进入已发布状态的群组。

使用：

```text id="rq6zt7"
last_published_at
```

不是：

* 创建时间
* 更新时间
* 随机顺序
* 点赞数
* 当前旋转顺序

## 17.2 查询规则

```text id="r6h7kg"
status = published
ORDER BY last_published_at DESC, id DESC
LIMIT 10
```

使用代码中的真实状态枚举和 ID 字段。

## 17.3 数量

* 最多 10 个
* 少于 10 个显示全部
* 0 个显示空状态
* 不分页
* 不无限加载

## 17.4 更新语义

不使用：

* WebSocket
* 定时轮询
* 客户端每小时刷新
* 自动重新排序

用户：

* 重新进入首页
* 刷新页面
* 手动重试请求

时获得最新数据。

## 17.5 布局

使用子任务 06 的通用 Carousel 和 GroupCard。

不得创建发现新群专用卡片。

## 17.6 标题

Section 标题固定为：

```text id="kfbttu"
发现新群
```

文案调整需通过总 PRD 或设计规范，不由 Agent 临时更改。

## 17.7 重复展示

某群组可以同时出现在：

* 发现新群
* 一个或多个板块
* 所有群组

这是允许的。

本任务不得为了去重隐藏合法内容。

# 19. 所有标签

## 19.1 数据范围

只统计当前已发布群组。

以下群组不计入：

* 已下架
* 回收站
* 永久删除
* 草稿
* 待审核
* 其他非公开状态

## 19.2 计数语义

每个标签对应：

```text id="ksqkkt"
包含该标签的已发布群组数量
```

同一群组中同一标签因共享 Schema 已去重，因此每个群组对同一标签最多计数一次。

## 19.3 标签标准化

标签名称和大小写规则沿用现有标签领域规则。

本任务不得重新建立：

* 大小写合并
* 简繁转换
* 同义词合并
* 标签别名

## 19.4 查询

必须使用数据库聚合查询。

不得：

* 拉取全部群组到前端统计
* 为每个标签发一个查询
* 产生 N+1

## 19.5 排序

默认排序冻结为：

1. 群组数量降序
2. 标签名称稳定升序

如果现有标签排序 Spec 已冻结其他规则，需根据子任务 01 审计结论处理，并记录差异。

## 19.6 返回内容

每项至少包含：

```text id="95cp23"
label
groupCount
```

不得返回群组完整列表。

# 20. 所有标签大卡片

## 20.1 结构

“所有标签”作为一个独立大卡片或 Section 容器展示所有标签及数量。

每个标签项展示：

* 标签名称
* 群组数量

## 20.2 全部展示

产品名称为“所有标签”。

第一版本默认展示全部有效标签，不做隐藏分页。

如实际标签数量巨大导致明显体验或性能问题，应在任务中记录，但不得擅自只展示前若干标签。

## 20.3 响应式

标签项可：

* 自动换行
* 根据宽度调整间距
* 在卡片内部自然增长

不得造成页面级横向滚动。

## 20.4 点击

点击标签后：

1. 用标签文本替换搜索框当前内容
2. 更新 URL `q`
3. 切换到搜索模式
4. 发起搜索
5. 默认首页其他区域隐藏

标签不会追加到已有搜索词后面。

由于所有标签只在默认首页显示，正常情况下点击时搜索框为空。

## 20.5 键盘

标签必须可通过：

* Tab
* Enter
* Space

触发。

应具备明确 Focus 状态和可访问名称，例如：

```text id="ip4mof"
搜索标签“计算机”，共有 12 个群组
```

* 不影响其他区域

空状态文案不应暗示系统错误。

# 23. 空板块

## 23.1 定义

以下情况公开表现为空板块：

* 板块没有任何成员
* 板块只有已下架成员
* 原成员均进入回收站
* 公开成员暂时为 0

## 23.2 显示

启用空板块仍显示：

* 板块标题
* 空状态内容

不得因 `groups.length === 0` 隐藏该板块。

## 23.3 文案

空状态应表达：

* 当前暂无可展示群组

不得泄露：

* 板块中实际存在已下架群组
* 下架数量
* 成员内部状态

# 26. 所有群组 Cursor

## 26.1 兼容现有实现

必须审查现有 cursor 是否包含：

* 排序槽位
* 排序位置
* 稳定 ID
* 查询条件
* 版本或签名

不得因为页面重构而丢失排序稳定性。

## 26.2 Cursor 不透明

前端将 cursor 视为不透明字符串。

不得解析或自行修改 cursor 内容。

## 26.3 重复记录

分页合并时按群组 ID 防止重复。

但不得因群组合法出现在不同首页区域而全局去重。

只在“所有群组”自身分页列表内去重。

## 26.4 请求竞态

不得同时发送多个相同 next cursor 请求。

## 26.5 槽位变化

如果用户跨越现有旋转排序槽位边界并继续加载，必须遵守当前 cursor 设计。

不得用新的首屏排序状态拼接旧 cursor。

如果现有实现已将槽位固化在 cursor，应继续复用。

# 27. 所有群组初始加载

## 27.1 初始状态

## 27.2 返回默认首页

推荐在同一页面会话内缓存默认首页状态，避免每次清空搜索都重新请求。

最终策略需考虑：

* 数据新鲜度
* 实现复杂度
* 滚动恢复
* 内存占用

## 27.3 深链接背景

直接访问 `?group=123` 时，所有群组第一页可以正常异步加载，但不得阻止 Dialog 先打开。

# 29. 搜索 Cursor

## 29.1 查询绑定

搜索 cursor 必须与当前查询词绑定。

前端不得将查询 A 的 cursor 用于查询 B。

## 29.2 查询变化

搜索词变化时：

* 清空旧结果
* 清空旧 next cursor
* 开始新初始请求
* 旧请求取消或结果忽略
* 滚动到搜索区域合理位置

## 29.3 浏览器返回

返回旧搜索词时，可以：

* 恢复缓存的旧结果和 cursor
* 或重新请求第一页

推荐在有限会话缓存中恢复，以改善体验。

但必须避免无限保留大量搜索缓存。

## 29.4 规范化

搜索请求使用 trim 后的有效关键词。

显示框保留用户可见输入的合理形式。

# 30. 搜索加载状态

## 30.1 Debounce 等待

用户刚输入但 debounce 未完成时：

* 可以保留上一组结果并显示轻量“正在输入”状态
* 或立即清空并展示 Skeleton

最终选择应在 `design.md` 中冻结。

推荐：

* 查询首次从空变非空时显示 Skeleton
* 已有搜索结果切换到新查询时立即标记为 loading
* 不展示明显属于旧关键词的结果作为新结果

## 30.2 初始加载

展示搜索结果 Grid Skeleton。

搜索框位置保持不变。

## 30.3 加载更多

保留已有结果，在底部显示加载 Skeleton。

## 30.4 请求错误

初始请求失败：

* 展示搜索错误状态
* 显示当前关键词
* 提供重试

加载更多失败：

* 保留已有结果
* 底部显示加载更多失败
* 提供重试当前 cursor

# 31. 搜索空状态

没有结果时展示：

* 当前搜索关键词
* 明确“没有匹配群组”
* 添加新群组入口

添加入口复用顶栏对应的现有群组提交流程。

不得：

* 自动清空搜索词
* 显示默认首页内容
* 推荐已下架群组
* 将错误误显示为空结果

---

# 32. 搜索错误与空状态区分

后端成功返回 0 条是空状态。

以下属于错误：

* 网络失败
* 服务器错误
* Contract 解析失败
* 请求超时
* 非预期响应

不得将 API 错误吞掉并显示“没有结果”。

# 33. 搜索结果计数

当前产品未冻结必须显示总结果数。

由于 cursor pagination 不一定高效返回 total count，第一版本不要求显示完整总数。

可以显示：

* 已加载结果数量

但不得误写为总结果数。

如果现有搜索 API 已可靠返回 total，可继续使用，但需明确语义。

# 34. 默认首页加载策略

## 34.1 首屏优先级

推荐优先加载：

1. 发现新群
2. 标签
3. 板块
4. 所有群组第一页

可以并行请求，但视觉上各自独立展示。

## 34.2 Search 模式

当前存在有效 `q` 时：

* 不需要立即请求默认首页全部区域
* 优先请求搜索结果
* 群组详情按 `group` 独立请求

为了浏览器返回快速恢复，可以：

* 延迟预取默认首页
* 或在清空搜索后再请求

不得在搜索模式下无必要加载所有板块和所有群组，造成带宽浪费。

## 34.3 Default 模式

无 `q` 时：

* 不请求搜索 API

# 35. 模式切换与状态保留

## 35.1 默认首页进入搜索

应记录：

* 默认首页滚动位置
* 所有群组已加载结果
* 各区域成功状态

进入搜索后默认区域可以从 DOM 中卸载或隐藏，具体由性能设计决定。

## 35.2 搜索清空

恢复默认首页时，推荐：

* 恢复此前状态
* 恢复此前滚动位置或定位到搜索框下方

需要避免用户清空搜索后突然跳到页面底部不可理解位置。

推荐策略：

* 搜索模式始终将页面靠近顶部搜索区
* 清空后保持当前顶部位置，默认区域从搜索框下方出现
* 如果用户通过浏览器返回恢复默认首页，则恢复历史滚动位置

具体通过 Router scrollBehavior 或页面缓存实现。

## 35.3 搜索词切换

搜索词变化时将搜索结果区域滚动到顶部，但不需要把整个窗口强制滚到页面最顶部，如果搜索框本来已经可见。

# 36. 页面滚动恢复

## 36.1 浏览器历史

需要支持：

* 默认首页滚动位置
* 搜索结果滚动位置
* Dialog 打开前背景滚动位置

## 36.2 Dialog

详情 Dialog 的滚动锁定和恢复由子任务 06 提供。

本任务不得在模式 watcher 中额外滚动页面，破坏 Dialog 恢复。

## 36.3 无限滚动恢复

浏览器返回到已加载多页的列表时，推荐恢复：

* 已加载 items
* next cursor
* hasMore
* scroll position

如果架构不支持完整恢复，应至少保证：

* URL 恢复
* 列表重新请求
* 不出现错误的旧 cursor
* 不重复记录

# 38. 区域级错误

每个默认首页区域都应能独立展示：

* 错误说明
* 重试按钮

## 38.1 发现新群失败

* 只影响发现新群
* 标签、板块、所有群组继续显示

## 38.2 标签失败

* 标签点击能力不可用
* 其他区域继续显示

## 38.3 板块失败

* 不显示旧或不完整管理数据
* 所有群组继续显示

## 38.4 所有群组失败

* 已经成功显示的发现区域继续存在
* 展示重试第一页

## 38.5 多区域同时失败

仍需：

* 搜索框可用
* 顶栏可用
* 提交群组入口可用

不得显示整个应用级白屏。

# 39. 区域重试

重试某一区域时：

* 只重试该区域
* 不重置其他区域
* 不关闭详情 Dialog
* 不改变 URL
* 不滚动到顶部
* 不重置点赞状态

分页加载更多失败重试必须使用失败时的原 cursor。

---

# 40. 全局错误边界

虽然区域级容错是主要策略，仍需保留页面级错误边界处理：

* Vue 渲染异常
* 无法解析核心路由
* 共享 Contract 严重不匹配

页面级错误不得暴露内部堆栈给普通用户。

* 手机边距

* 超宽屏处理

保持统一设计 Token。

# 54. 搜索请求竞态

* A 后返回

* 查询 Key

# 55. 首页查询缓存

## 55.1 可缓存数据

会话内可缓存：

* 发现新群
* 标签
* 板块
* 所有群组已加载页
* 搜索结果按有限查询 Key 缓存

## 55.2 数据新鲜度

缓存不能导致：

* 已下架群组长期公开
* 板块关闭后长期显示
* 新发布群组永久不出现

默认会话内短期缓存可以接受。

跨刷新持久化到 localStorage 不属于本任务。

## 55.3 缓存上限

搜索结果缓存应有合理上限或 LRU，防止用户搜索大量关键词后持续占用内存。

如不实现搜索缓存，应清楚记录浏览器返回会重新请求。
