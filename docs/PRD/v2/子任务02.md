# 1. 背景

V2 升级将重构公开首页、群组卡片、群组详情弹窗、自定义板块、管理端列表、板块管理、响应式行为和深色模式。

这些功能会共享大量视觉基础，包括：

* 页面背景和内容容器
* 颜色和文字层级
* 圆角和阴影
* 间距和尺寸
* 按钮和图标
* 群组卡片
* Carousel
* Grid
* Dialog
* 表格
* 分页器
* 管理端板块容器
* 加载、空状态和错误状态
* 浅色、深色和自动主题

如果在各个功能子任务中分别决定样式，会产生以下问题：

* 同类组件视觉不一致
* 每个 Agent 重复解释设计模板
* 深色模式后补导致大面积返工
* 响应式断点缺乏统一原则
* Playwright 视觉基线频繁变化
* 页面完成后仍需第二次全站重构

因此，本任务必须在正式前端功能开发前，将用户提供的视觉模板转化为适合当前项目的完整设计语言，并通过一个不连接后端的可运行视觉样例进行验证。

# 2. 任务目标

## 2.1 核心目标

完成以下三项工作：

1. 分析用户提供的视觉模板，提取可复用的设计规律
2. 将设计规律整理为项目正式前端 Spec：`ui-design.md`
3. 制作一个可运行的无后端视觉样例，让用户在真实浏览器中确认视觉、响应式和核心交互

## 2.2 规范目标

`ui-design.md` 必须能够指导后续 Agent 独立完成页面，而不需要重新猜测：

* 应使用什么颜色
* 不同层级文字如何区分
* 页面和组件使用什么间距
* 卡片和弹窗使用什么圆角
* 深色模式如何映射
* 手机和桌面如何变化
* 按钮和表格有哪些状态
* 哪些交互需要动画
* 哪些组件必须保持一致
* 哪些设计属于强制规则
* 哪些设计允许按内容适配

## 2.3 原型目标

视觉样例不是静态图片，也不是简单组件截图。

它必须是一个能够在浏览器运行和操作的前端空壳网站，用模拟数据展示 V2 的主要页面、状态和响应式行为。

原型用于验证：

* 设计语言是否符合用户预期
* 信息密度是否合理
* 群组卡片是否适合桌面和手机
* Carousel 是否容易理解
* 群组详情弹窗是否清晰
* 顶栏在窄屏是否可用
* 管理端表格是否易读
* 板块管理是否清晰
* 浅色和深色模式是否协调

# 5. 设计原则

## 5.1 借鉴设计语言，不盲目复制页面

Agent 应提取模板中的：

* 色彩关系
* 信息层级
* 空间感
* 圆角语言
* 阴影语言
* 字体比例
* 组件密度
* 导航风格
* 动效风格

不得因为模板存在某种页面结构，就直接覆盖本项目已经冻结的信息架构。

V2 PRD 的产品结构优先于模板页面结构。

## 5.2 项目适配优先

模板可能是：

* 营销网站
* SaaS 仪表盘
* 电商页面
* 博客
* 移动应用
* 静态落地页

Agent 必须将视觉风格适配到本项目的真实内容密度，而不是机械照搬。

## 5.3 设计 Token 优先

不得在样例中大量散落任意色值、任意间距和任意圆角。

视觉样例应尽量通过统一 Token 验证设计系统。

## 5.4 浅色和深色同时设计

不得先完成浅色主题，再通过简单反色生成深色主题。

两个主题需要同时定义：

* 页面层级
* 卡片层级
* 文字层级
* 边框
* 阴影
* Hover
* Active
* Focus
* Disabled
* Success
* Warning
* Error
* Skeleton
* 遮罩

## 5.5 响应式不是隐藏功能

屏幕变窄时：

* 可以调整尺寸和排列
* 可以压缩文字
* 可以切换图标形式
* 可以隐藏次要管理列
* 不得删除公开端核心功能
* 不得打乱首页区域顺序
* 不得让页面产生非预期横向滚动

## 6.1 模板信息记录

`ui-design.md` 必须记录：

* 模板名称
* 模板来源
* 模板链接或本地来源说明
* 获取日期
* 主要参考页面
* 主要参考组件
* 主要参考状态
* 用户明确喜欢的部分
* 不适合本项目的部分
* 最终采用和放弃的设计元素

## 6.2 视觉特征拆解

至少分析：

### 页面层面

* 页面最大宽度
* 内容留白
* 页面背景
* 顶栏高度
* Section 间距
* 卡片密度
* 主次内容关系

### 排版层面

* 标题比例
* 正文字号
* 辅助文字
* 行高
* 字重
* 长文本阅读体验
* 数字和状态显示方式

### 组件层面

* 按钮
* 搜索框
* 卡片
* 标签
* 弹窗
* 表格
* 分页
* 导航
* 空状态
* 加载状态

### 交互层面

* Hover
* Active
* Focus
* 展开和关闭
* 拖动
* 滚动提示
* 状态切换
* 动画节奏

## 6.3 适用性判断

每项视觉特征需要标记：

* 直接采用
* 调整后采用
* 仅作为参考
* 不采用

并说明原因。

不得只写“参考模板风格”。

# 7. 授权和使用范围审查

## 7.1 审查内容

Agent 必须尽可能确认：

* 模板许可证
* 是否允许商用
* 是否允许修改
* 是否允许复制代码
* 是否要求署名
* 是否包含限制使用的图片
* 是否包含限制分发的图标
* 是否依赖付费字体
* 是否包含不可随项目提交的资产
* 是否允许将组件代码用于当前项目

## 7.2 审查记录

`ui-design.md` 必须记录：

| 项目     | 结论          |
| ------ | ----------- |
| 模板许可证  | 已确认、未确认或不适用 |

| 图片可否复用 | 是、否或有限制     |
| 图标可否复用 | 是、否或有限制     |
| 字体可否使用 | 是、否或有限制     |

* 使用项目已有资源、系统字体或明确可用的开源资源替代

本任务不提供法律结论，但必须诚实记录授权信息是否已确认。

# 8. 设计 Token

## 8.1 Token 层级

设计系统至少分为：

1. 原始 Token
2. 语义 Token
3. 组件 Token

### 原始 Token 示例

* 色阶
* 字号
* 间距
* 圆角
* 阴影
* 动画时长

### 语义 Token 示例

* 页面背景
* 卡片背景
* 主文字
* 次文字
* 弱化文字
* 品牌操作
* 边框
* 错误
* 成功
* 警告

### 组件 Token 示例

* 卡片圆角
* 顶栏高度
* 搜索框高度
* Dialog 最大宽度
* 表格行高
* Carousel 间距

## 8.2 颜色 Token

至少定义：

### 基础界面

* `background`
* `surface`
* `surface-raised`
* `surface-muted`
* `overlay`

### 文字

* `text-primary`
* `text-secondary`
* `text-muted`
* `text-inverse`
* `text-link`

### 边框

* `border-default`
* `border-muted`
* `border-strong`
* `border-focus`

### 品牌和操作

* `accent`
* `accent-hover`
* `accent-active`
* `accent-foreground`

### 状态

* `success`
* `warning`
* `danger`
* `info`

### 互动状态

* Hover
* Active
* Selected
* Disabled
* Focus ring

每个语义颜色必须具有浅色和深色映射。

## 8.3 间距体系

必须建立有限且可复用的间距等级。

至少覆盖：

* 页面边距
* Section 间距
* 卡片内边距
* 卡片间距
* 表单项间距
* 按钮内部间距
* 图标与文字间距
* 表格单元格间距

不得在正式规范中出现大量无规律的单次像素值。

## 8.4 圆角体系

至少定义：

* 小型控件
* 按钮和输入框
* 普通卡片
* 大卡片
* 弹窗
* 圆形图标按钮

说明哪些组件允许使用完全圆形外观，哪些不允许。

## 8.5 阴影体系

至少定义：

* 无阴影
* 轻微浮层
* 卡片 Hover
* 顶栏或粘性元素
* Dialog
* 拖拽状态

深色模式不能简单复用浅色阴影值。

## 8.6 字体体系

至少定义：

* 字体家族
* 页面主标题
* Section 标题
* 卡片标题
* 正文
* 辅助文字
* 标签文字
* 按钮文字
* 表格文字
* 数字和统计数据

优先使用：

* 项目已有字体
* 系统字体栈
* 明确允许使用的开源字体

不得把受限字体文件提交到项目。

## 8.7 动效体系

至少定义：

* 快速状态反馈
* 普通展开关闭
* Dialog 进入退出
* Carousel 滚动
* 拖拽反馈
* Toast

同时定义 `prefers-reduced-motion` 下的降级规则。

# 9. 浅色和深色映射

## 9.1 主题模型

设计规范必须与以下主题偏好兼容：

```ts
type ThemePreference = 'system' | 'light' | 'dark'
```

视觉任务不负责连接正式主题状态，但样例应能切换三种状态并展示实际效果。

## 9.2 映射要求

每个关键语义 Token 必须定义：

* 浅色值
* 深色值
* 使用场景
* 对比度注意事项

## 9.3 深色模式禁忌

不得：

* 仅将白色改为纯黑
* 将所有灰色机械反转
* 使用过亮的大面积纯色
* 让边框和卡片层级消失
* 让 Skeleton 与背景无法区分
* 让状态色失去辨识度
* 让二维码内容受到主题滤镜影响

## 9.4 主题样例

视觉原型必须能演示：

* 自动
* 浅色
* 深色

自动模式可以通过模拟系统状态或浏览器媒体查询展示。

# 10. 响应式设计规范

## 10.1 断点原则

断点应基于内容何时无法合理布局，而不是仅复制模板的设备尺寸。

`ui-design.md` 必须定义：

* 页面主要断点
* 每个断点的用途
* 哪些组件使用页面断点
* 哪些组件应使用容器宽度或独立规则

## 10.2 页面容器

定义：

* 最大内容宽度
* 桌面左右边距
* 平板左右边距
* 手机左右边距
* 超宽屏处理
* 安全区处理

## 10.3 顶栏

宽屏：

* Logo
* 网站名
* 主题图标和文字
* GitHub 图标和文字
* `+ 添加新的群组`

窄屏：

* Logo 和网站名优先保留
* 主题仅图标
* GitHub 仅图标
* 添加按钮显示“添加群”
* 不改成单独加号
* 不折叠为汉堡菜单

需要定义各状态开始变化的宽度条件。

## 10.4 Carousel

需要定义：

* 手机最少同时可见两张卡片
* 桌面卡片宽度范围
* 卡片间距
* 左右内边距
* 下一张卡片的露出方式
* 左右箭头出现条件
* 渐变遮罩规则
* 触摸和鼠标状态

## 10.5 Grid

需要定义：

* 手机列数
* 平板列数
* 桌面列数
* 超宽屏最大列数
* 最小卡片宽度
* 卡片间距

标准手机宽度目标为至少两列。

## 10.6 管理表格

群组管理表格按以下优先级隐藏列：

1. 标签
2. 性质
3. 点赞
4. 平台

永久保留：

* 标题
* 状态
* 操作

设计规范必须展示至少三个宽度状态：

* 完整桌面
* 中等宽度
* 窄屏

## 10.7 Dialog 和抽屉

需要定义：

* 桌面 Dialog 最大宽度
* 手机 Dialog 接近全屏的规则
* 管理抽屉桌面宽度
* 管理抽屉窄屏全屏规则
* 安全区
* 底部按钮区域
* 内容滚动区域

* 不强制现有页面立即采用
* 不改变现有页面视觉
* 不引发生产回归

如果无法保证隔离，应将所有样例代码放在独立原型目录中。

* 按钮触摸目标合理
* 表格表头层级清晰
* 深色模式下焦点仍可见
* `prefers-reduced-motion` 降级
* 高倍文字缩放下主要内容可用

如无法使用自动工具完整判断，必须在 `ui-design.md` 中记录人工检查结果。
