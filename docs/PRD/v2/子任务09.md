# 1. 背景

当前管理端群组列表已经具备：

* 群组搜索
* 多状态筛选
* 回收站筛选
* 多列排序
* keyset pagination
* 管理端表格
* 新建和编辑抽屉
* 脏表单守卫
* 群组状态修改
* 版本冲突
* 图片上传
* 标签编辑
* 加群方式编辑
* 移入回收站
* 恢复
* 永久删除

V2 要求将管理端群组列表从 keyset pagination 改为传统页码分页，并固定：

```text
每页 50 条
```

同时，管理端群组表格必须根据可用宽度依次隐藏次要列。

隐藏优先级固定为：

1. 标签
2. 性质
3. 点赞
4. 平台

以下列必须始终保留：

* 标题
* 状态
* 操作

本任务还需要让群组新建和编辑抽屉在窄屏下占满可用页面，保证复杂表单在手机和平板上仍可完成。

本任务不重新设计群组管理领域，不修改群组状态机，也不改变公开端的 cursor pagination。

# 7. 管理端列表 API

## 7.1 目标响应结构

管理端群组列表 API 返回：

```ts
{
  items: AdminGroupSummary[]
  page: number
  pageSize: 50
  totalItems: number
  totalPages: number
}
```

如项目统一响应存在额外包装，应在不改变上述语义的前提下遵守现有格式。

## 7.2 固定每页数量

后端固定：

```text
pageSize = 50
```

客户端不得提交或覆盖 `pageSize`。

即使请求包含：

```text
?pageSize=100
```

也不得返回 100 条。

可选择：

* 忽略该参数
* 将其作为非法未知参数拒绝

最终行为需与项目查询参数规范一致。

## 7.3 页码

页码从：

```text
1
```

开始。

不使用 0-based 页码。

## 7.4 页码默认值

未提供 `page` 时：

```text
page = 1
```

## 7.5 非法页码

以下输入必须安全处理：

* `page=0`
* `page=-1`
* `page=1.5`
* `page=abc`
* `page=`
* 超出整数范围
* 重复 page 参数

推荐行为：

* 格式非法返回统一 400
* 小于 1 返回 400
* 页面超过总页数时返回空页或由前端规范化

最终规则必须在 `design.md` 中冻结。

# 8. 页码超出范围

## 8.1 正常用户操作

当前页面因删除记录导致页码超出时，前端应主动退回有效上一页。

## 8.2 直接 URL

用户直接访问：

```text
/admin/groups?page=999
```

而实际只有 4 页时，推荐：

1. API 返回空 `items`
2. 同时返回正确 `totalPages = 4`
3. 前端使用 `router.replace` 导航到第 4 页
4. 请求第 4 页数据

如果总记录数为 0：

```text
page = 1
totalPages = 0
```

前端保持第一页空状态。

## 8.3 禁止行为

不得：

* 返回最后一页数据却仍声明 `page=999`
* 静默将后端页码改成 4 而前端 URL 仍是 999
* 陷入无限重定向
* 将超出页码视为服务器 500

# 9. Total Count

## 9.1 `totalItems`

表示当前所有管理端查询条件下的记录总数。

它受以下条件影响：

* 搜索词
* 状态筛选
* 回收站筛选
* 其他现有筛选

它不受以下条件影响：

* 当前页码
* 当前页大小
* 排序方向

## 9.2 `totalPages`

计算规则：

```text
totalPages = ceil(totalItems / 50)
```

当：

```text
totalItems = 0
```

时：

```text
totalPages = 0
```

## 9.3 COUNT 条件一致

COUNT 查询和 items 查询必须使用完全相同的筛选条件。

不得出现：

* 列表有 40 条，但总数显示 43
* 回收站筛选后总数仍包含正常群组
* 搜索总数未应用标签匹配
* 状态筛选只应用到 items、不应用到 COUNT

## 9.4 并发变化

在高并发下，COUNT 与 items 之间可能出现瞬时变化。

不要求建立昂贵的跨查询快照事务，但同一请求应尽量使用同一规范化条件和接近的执行时刻。

# 10. OFFSET 查询

## 10.1 计算

```text
offset = (page - 1) * 50
```

## 10.2 可接受性

基于当前项目预计数据规模，管理端使用 OFFSET 页码分页可接受。

Agent 必须根据子任务 01 的数据规模审计结果确认，不得无依据声称无限可扩展。

## 10.3 查询安全

`page` 必须先经过整数校验，避免：

* 负 OFFSET
* 数值溢出
* SQL 拼接注入

查询参数必须使用绑定值。

## 10.4 长期风险

如当前数据规模已经很大，`design.md` 中应记录：

* OFFSET 深页性能风险
* 对应索引
* 未来可能改进方向

但不得因此拒绝实现已冻结的页码分页。

* 创建时间

* 第 1 页结果稳定

* 不重复

# 17. URL 更新策略

## 17.1 页码操作

点击页码、上一页或下一页应使用：

```text
router.push
```

使浏览器返回可回到上一页码状态。

## 17.2 搜索输入

连续输入使用 debounce，并使用：

```text
router.replace
```

避免每个字符产生一条历史。

搜索条件首次正式应用是否使用 push，由 `design.md` 决定。

## 17.3 筛选和排序

修改筛选或排序可以使用：

```text
router.push
```

以便返回恢复旧列表状态。

必须防止一次用户操作触发多次 Router 更新。

## 17.4 规范化

非法或冗余 URL 参数规范化时使用：

```text
router.replace
```

避免增加无意义历史记录。

# 21. 分页器

## 21.1 基本结构

分页器采用：

```text
上一页  1  …  5  6  [7]  8  9  …  24  下一页
```

同时展示：

```text
共 1,173 条，第 7 / 24 页
```

## 21.2 必须元素

* 上一页
* 下一页
* 第一页
* 最后一页
* 当前页
* 当前页附近页码
* 必要省略号
* 总记录数
* 当前页和总页数

## 21.3 当前页

当前页必须：

* 视觉明确
* 使用 `aria-current="page"`
* 不可再次点击或点击无副作用

## 21.4 上一页和下一页

第一页：

* 上一页禁用

最后一页：

* 下一页禁用

零结果：

* 上一页和下一页均禁用
* 不展示无意义页码按钮

---

# 22. 页码窗口算法

需要建立纯函数生成分页项。

建议输出：

```ts
type PaginationItem =
  | { type: 'page'; page: number; current: boolean }
  | { type: 'ellipsis'; key: string }
```

## 22.1 小页数

总页数较少时，展示全部页码。

例如总页数 5：

```text
1 2 3 4 5
```

## 22.2 中间页

当前页位于中间时：

```text
1 … 5 6 [7] 8 9 … 24
```

## 22.3 靠近开头

例如当前第 2 页：

```text
[1] 或 1 [2] 3 4 5 … 24
```

实际窗口宽度由 `ui-design.md` 和响应式设计确定。

## 22.4 靠近结尾

例如当前第 23 页：

```text
1 … 20 21 22 [23] 24
```

## 22.5 窄屏

手机端可减少中间页码数量，但必须保留：

* 上一页
* 当前页信息
* 下一页

如空间允许保留第一和最后页。

具体行为在 `design.md` 中冻结。

# 23. 分页器位置

分页器应位于：

* 表格下方
* 与表格同一内容区域

如列表很长，可选在表格上方提供简要页码，但第一版本不要求双分页器。

分页器不得放入表格横向滚动区域。

# 26. 删除后退页

## 26.1 触发条件

用户在当前页删除或永久删除最后一条记录后，如果：

* 当前页大于 1
* 当前查询条件下当前页变为空
* 总页数减少

则自动回到上一有效页。

## 26.2 示例

删除前：

```text
page = 4
totalItems = 151
totalPages = 4
items.length = 1
```

删除后：

```text
totalItems = 150
totalPages = 3
```

前端应导航：

```text
page = 3
```

## 26.3 Router 行为

这种自动规范化建议使用：

```text
router.replace
```

避免浏览器返回又进入不存在的第 4 页。

## 26.4 不是最后一条

如果删除后当前页仍有记录：

* 保持当前页
* 重新请求当前页
* 更新 totalItems 和 totalPages

## 26.5 第一页

第一页删除最后一条记录后：

* 保持第一页
* 显示空状态
* 不跳到 page 0

# 27. 删除与回收站操作

* 移入回收站
* 恢复
* 永久删除
* 状态改变导致不再符合筛选
* 新建群组
* 编辑群组状态

操作成功后必须重新计算当前列表。

## 27.1 筛选影响

例如当前筛选：

```text
status=published
```

将当前记录改为已下架后，该记录应从当前列表消失。

前端需要：

* 重新请求当前页
* 更新 total
* 必要时退页

不得仅修改当前行状态后继续让其留在不符合条件的列表。

# 28. 新建群组后的列表行为

创建群组成功后，不要求自动跳转到包含新记录的页面。

可以：

* 保持当前查询状态
* 重新请求当前页
* 更新 totalItems
* 显示成功 Toast

如果新群组符合当前筛选和排序，并按当前排序应出现在当前页，可由服务端结果决定。

不得在前端强制插入并破坏排序。

# 29. 编辑后的列表同步

编辑成功后：

* 使用服务器返回数据更新当前行
* 如果记录不再符合筛选，重新查询
* 如果排序字段发生变化，重新查询当前页
* 更新 totalItems
* 必要时退页

不得仅局部修改排序字段后保持错误顺序。

# 33. 列隐藏优先级

屏幕或表格容器宽度不足时，按以下顺序隐藏：

```text
第一：标签
第二：性质
第三：点赞
第四：平台
```

含义是：

1. 最先隐藏标签
2. 再隐藏性质
3. 再隐藏点赞
4. 最后隐藏平台
5. 标题、状态、操作始终保留

不得改变为：

* 平台最先隐藏
* 点赞最先隐藏
* 根据用户设置自由隐藏
* 所有次要列一次性同时隐藏

# 34. 响应式断点

产品规则冻结的是列优先级，而不是固定像素值。

实际断点需要基于：

* 表格容器宽度
* 当前设计 Token
* 标题最小可读宽度
* 操作列所需宽度
* 管理端导航布局

在 `design.md` 中记录：

* 标签隐藏阈值
* 性质隐藏阈值
* 点赞隐藏阈值
* 平台隐藏阈值

推荐优先使用：

* 容器查询
* 或与 AdminLayout 对齐的断点

如果项目环境不支持容器查询，则使用媒体查询。

# 35. 列隐藏实现

## 35.1 表头和单元格一致

隐藏某列时必须同时隐藏：

* 对应 `<th>`
* 所有对应 `<td>`

不得造成表头和数据错位。

## 35.2 DOM 保留

可以通过 CSS 隐藏列。

不要求从数据请求中删除字段。

## 35.3 可访问性

隐藏列不应继续被屏幕阅读器按可见表格内容朗读。

需使用正确 CSS 或条件渲染。

## 35.4 排序字段

若当前排序字段对应已经隐藏的列：

* 排序仍然生效
* 页面需要在筛选或排序控制区显示当前排序
* 管理员不能因列隐藏而完全不知道当前排序条件
