# 网站 V2 大版本升级总任务实施计划

## 1. 当前阶段与执行边界

- 当前 Trellis 任务：`lgqh-v2`。
- 当前状态：`planning`。
- 本阶段只形成总体规划，不运行 `task.py start`，不进入业务实现阶段。
- 本阶段不创建 10 个子任务目录，不写入任何父子任务关系。
- 下面的 T01–T10 是来源 PRD 中的未来工作流登记，不是已经创建的 Trellis 子任务。

总任务本身负责规划、依赖协调、跨任务集成和最终验收；大块功能实现应由后续独立子任务承担，只有必要的跨任务集成问题由总任务处理。

总任务职责逐项为：

1. 阅读本总 PRD。
2. 阅读全部现有 Spec。
3. 建立所有子任务目录和基础文件（本次先不执行）。
4. 为子任务写明范围、依赖和验收要求。
5. 维护任务依赖图。
6. 防止不同子任务重复修改同一领域。
7. 记录跨任务决策。
8. 跟踪迁移顺序。
9. 汇总测试矩阵。
10. 在全部子任务完成后进行系统级验收。
11. 运行完整测试。
12. 检查遗漏和回归。
13. 只处理必要的集成问题，不在总任务中重新开发子功能。

源 PRD 为总任务定义的最终交付物包括：`prd.md`、`research.md`、`design.md`、`implement.md` 和 `acceptance.md`。本次用户明确要求先形成三份规划文件，因此当前只创建 `prd.md`、`design.md`、`implement.md`；`research.md` 由 T01、`acceptance.md` 由 T10 在后续阶段交付，当前不提前创建。

源 PRD 的交付物清单为：

```text
prd.md
design.md
implement.md
research.md
acceptance.md
```

其中 `research.md` 记录代码/Spec 审计，`acceptance.md` 记录最终系统验收；本阶段只生成前三份规划文件。

## 2. 规划前置条件

在任何子任务进入实现前，必须完成：

1. 读取全部相关 Spec、归档任务、真实代码、migration 和测试，确认源 PRD 中的现状描述。
2. 产出审计结论并修订受影响的子任务边界、文件所有权和验收标准。
3. 用户提供并确认视觉模板、设计 Token 和可运行无后端样例。
4. 冻结共享 Contract、数据库字段/表、API 边界、错误语义和迁移顺序。
5. 明确高冲突共享文件的唯一负责人，禁止多个子任务同时大范围改动。

在以上条件未满足前，不得启动正式业务实现。

### 3.1 T01：全量 Spec 与代码审计

- 建议名称：`lgqh-v2-spec-audit`。
- 依赖：无；执行阶段为 V2 功能开发前；不允许修改业务代码或数据库迁移。
- 目标：在不改业务代码的前提下，核对真实实现、Spec、历史决策、测试覆盖与 V2 PRD 的冲突，回答“当前行为是什么、哪些可直接实施、哪些需要补充/修订、后续任务影响哪些文件”。
- 工作范围：阅读全部 Spec、归档任务及相关 design/implement；阅读活动任务模板；审查公开首页、搜索与 cursor pagination、旋转排序、管理列表与 keyset pagination、群组状态机、回收站/永久删除、主题基础/CSS 自定义属性、Playwright、D1 migration。
- 交付物：`research.md`、`impact-map.md`、基于证据的总 PRD 修改方案。

T01 交付物文件名固定为：

```text
research.md
impact-map.md
```

- 验收必须明确：可复用模块、必须修改模块、现有 Spec 冲突、数据迁移风险、API 影响面和测试影响面。

### 3.2 T02：设计语言规范与视觉样例

- 建议名称：`lgqh-v2-ui-design-language`。
- 依赖：T01 和用户提供的视觉模板；不连接真实后端。
- 目标：分析模板并将其转化为适合本项目内容密度的设计系统，不机械复制模板页面结构。
- 工作范围：审查授权/可使用范围；提取设计 Token；建立浅色/深色映射、响应式规范、组件视觉规范；制作可在浏览器运行的无后端视觉样例。
- 样例至少覆盖顶栏、搜索框、一张群组卡片、一段 Carousel、详情弹窗、一行管理表格、浅色模式和深色模式，并验证信息密度、移动端卡片、板块容器和管理表格。
- 不属于本任务：真实 API/D1/R2、认证、CSRF、提交、点赞、复制、真实 CRUD、正式分页、正式搜索、状态机、migration、正式首页/管理端业务重构。
- 交付物：前端 Spec `ui-design.md` 和可运行视觉样例；完成门槛为用户明确确认设计语言，确认前后续前端任务不得进入正式实现。

```text

├─ T02 设计语言 ─ T03 主题/Token/顶栏
│                 ├─ T06 卡片/弹窗/Carousel
│                 ├─ T08 管理端板块

└─ T04 Schema/发布/迁移 ─ T05 板块后端
                           ├─ T07 首页/搜索
                           └─ T08 管理端板块

T03 + T05 + T06 → T07 首页/搜索
T03 + T04 → T09 管理端分页/响应式
T03–T09 全部完成 → T10 系统回归
```

源 PRD 的依赖关系原文保留如下：

```text
01 全量审计
├── 02 设计语言
│   └── 03 主题、Token 与顶栏
│       ├── 06 卡片、Carousel 与详情弹窗
│       ├── 08 管理端板块管理
│       └── 09 管理端分页与响应式
│
└── 04 Schema、发布字段与迁移
    ├── 05 板块后端
    │   ├── 07 首页与搜索
    │   └── 08 管理端板块管理
    ├── 06 卡片、Carousel 与详情弹窗
    └── 09 管理端分页与响应式

06 + 05 + 03 → 07 首页与搜索

全部完成 → 10 系统回归

总任务 → 最终验收
```

允许并行的前提：

- T02 与 T04 在 T01 完成后可以并行，但 T06/T08/T09 必须等待它们各自的 Contract/Token 结果。
- T03 完成基础 Token 后可与 T05 的后端实现并行收尾，但正式 UI 页面需等待 T03。
- T06 的通用组件可以提前开发，但不得在 API/共享 DTO 未确定时复制临时字段结构。
- T08 与 T09 可并行，但必须事先划清管理端导航、共享表格、抽屉和 query state 的文件所有权。
- T07 只有在公开查询 API、卡片/弹窗和主题基础均可用后进入完整整合。
- T10 不承接新功能设计，只处理跨任务集成缺陷和验收阻塞。

## 9. 最终集成验收

总任务最终验收按以下顺序执行：

1. 对照本总 PRD 检查范围。
2. 对照各子任务 PRD 检查交付物。
3. 检查所有 migration。
4. 检查共享 Zod Contract。
5. 检查安全模式。
6. 检查状态转换。
7. 检查公开端数据过滤。
8. 检查桌面和手机布局。
9. 检查浅色和深色模式。
10. 运行全部 Vitest。
11. 运行全部 Workers Vitest。
12. 运行全部 Playwright。
13. 运行视觉回归。
14. 手动验证关键流程。
15. 检查 Git 工作区和提交记录。
16. 记录剩余非阻塞问题。
17. 形成最终 `acceptance.md`。

任何子任务未完成、测试失败或公开端泄露下架数据时，总任务不得标记完成。总任务不能借最终验收重新设计功能或大规模重构已验收子模块。
