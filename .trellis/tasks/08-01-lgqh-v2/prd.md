## 1. 目标与用户价值

在不破坏现有公开浏览、搜索、提交、匿名点赞、管理 CRUD、图片资源、安全防护和回收站能力的前提下，完成“来个群号”网站的 V2 大版本升级：

1. 将公开首页从单一群组网格升级为“发现新群、标签、自定义板块、完整目录”的发现型信息架构。
2. 将群组卡片定位为摘要浏览和点赞入口，将完整信息及加群方式统一收敛到详情弹窗。
3. 建立可配置的自定义板块，支持管理员控制启用状态、顺序、成员和排序模式。
4. 建立统一设计语言、三态主题和跨桌面/平板/手机的响应式体验。
5. 将管理端群组列表改为固定每页 50 条的页码分页，并保证窄屏仍能访问核心字段和操作。
6. 通过共享 Contract、迁移策略、自动化测试和系统级回归，保证 V2 可安全发布和回滚。

## 2. 背景与现有能力

现有系统已经具备：

- 公开群组浏览、搜索、提交和匿名点赞。
- 群组卡片、无限滚动和 URL 搜索同步。
- 管理端群组 CRUD、筛选、排序和回收站。
- WebP 图片上传及 R2 资源生命周期管理。
- HMAC 会话、CSRF 防护、版本冲突处理和突变令牌/批量操作模式。
- Cloudflare D1、R2、Analytics 集成。
- 前后端共享 Zod Schema、Workers 集成测试和 Playwright E2E 测试。

本次升级是兼容现有系统的系统性重构，不是从零开发，也不以替换现有认证、存储或分析基础设施为目标。

## 3. 产品范围

### 3.1 公开首页与搜索

默认首页在搜索框为空时按以下顺序展示：

1. 顶栏。
2. 主搜索框。
3. “发现新群” Carousel。
4. “所有标签”聚合卡片。
5. 零个、一个或多个启用的自定义板块 Carousel。
6. “所有群组”响应式 Grid。

布局契约如下，不能用单一布局替代这些语义：

| 区域 | 布局 |
| --- | --- |
| 发现新群 | Carousel |
| 自定义板块 | Carousel |
| 所有标签 | 标签聚合卡片 |
| 所有群组 | Grid |
| 搜索结果 | Grid |

输入有效搜索内容后，保留顶栏和搜索框，仅展示搜索结果 Grid；清空搜索后恢复默认首页。搜索框纵向位置和主要尺寸保持稳定，不因模式切换产生明显布局跳动。

搜索行为必须满足：

- 无搜索按钮，输入经过 debounce 自动搜索。
- 中文输入法 composing 阶段不发送无效请求。
- 搜索词同步到 `?q=<keyword>`，刷新、前进和后退均恢复状态。
- 继续搜索标题、简介和标签，不改变既有匹配语义和排序算法。
- 公开列表和搜索结果继续使用 cursor pagination 与无限滚动，不一次性返回全部记录。
- 明确定义初始、等待、加载、继续加载、无结果、失败和重试状态。
- 搜索模式下隐藏“发现新群”“所有标签”“自定义板块”和“所有群组”，清空后恢复；搜索框位置和主要尺寸保持稳定。

### 3.2 顶栏、主题与设计语言

桌面顶栏左侧保留网站 Logo 和网站名称，右侧提供主题模式控件、GitHub 支持按钮和添加群组按钮。窄屏优先压缩间距和文字：主题与 GitHub 支持按钮可仅显示图标，添加按钮缩短为“添加群”，但不得缩减为单独加号或隐藏核心操作。

推荐的宽屏按钮文字为：

- 主题控件：太阳/月亮图标 + “自动”“浅色”或“深色”。
- GitHub 按钮：GitHub Logo + “支持项目”。
- 添加按钮：加号图标 + “添加新的群组”。

主题偏好为：

```ts
type ThemePreference = 'system' | 'light' | 'dark'
```

要求：

- 默认值为 `system`。
- 合法的 localStorage 偏好优先；缺失或非法值回退到 `system`。
- `system` 根据 `prefers-color-scheme` 决定实际主题，并实时响应系统主题变化。
- Vue 挂载前尽早应用主题，避免首屏闪烁。
- 公开端、搜索结果、弹窗、提交入口、登录页、管理端、数据分析、抽屉、Toast、错误、骨架、空状态、二维码、表单和表格均覆盖浅色与深色主题。
- 所有图标按钮具有可访问名称、Tooltip 或等效提示、清晰焦点态。
- 视觉模板只作为设计语言来源，必须提炼为项目 Token 和组件规范，不直接覆盖既定产品信息架构。

设计规范必须覆盖以下 Token：主色、辅助色、页面背景、卡片背景、分层文字、边框、圆角、阴影、间距、字号、行高、字重、动画时长、动画缓动，以及浅色/深色映射。组件规范至少覆盖顶栏、搜索框、群组卡片、详情弹窗、Carousel、Grid、标签、主/次/图标按钮、表格、板块容器、表单、抽屉、Toast、ErrorBanner、Skeleton、空状态和分页器。

响应式规范至少定义页面最大宽度、页面边距、卡片宽度、Grid 列数、Carousel 间距、管理端断点、弹窗/抽屉宽度和顶栏压缩规则。不使用移动端汉堡菜单替代当前三个主要操作；顶栏必须保留左右语义且不产生页面级横向滚动。

在正式功能实现前，需形成 `ui-design.md` 和可运行的无后端视觉样例，覆盖顶栏、搜索框、群组卡片、Carousel、详情弹窗、管理表格以及浅色/深色模式，并经用户确认。

### 3.3 群组内容与共享校验

前后端使用同一套显示宽度规则，不得使用 JavaScript `string.length` 作为产品长度限制。共享函数目标为：

```ts
measureDisplayWidth(value: string): number
```

规则至少包括：ASCII/半角拉丁字符按 1 个宽度单位；中日韩及全角字符按 2 个单位；单个 Emoji 字素簇按 2 个单位；组合 Emoji 按一个可见字素计算；带重音的拉丁字母不能简单按非 ASCII 统一计为 2；校验前清理前后空格；换行符计入合理宽度。

具体 Unicode 算法由技术设计确定，但前后端结果必须完全一致；不得由客户端和服务端各自采用近似实现。

- 标题上限为 50 个显示宽度单位，卡片最多显示两行，详情弹窗显示完整标题。
- 简介上限为 1000 个显示宽度单位，卡片最多显示四行，详情弹窗显示完整简介。
- 创建和编辑表单展示当前使用宽度、上限和超限错误。
- 客户端与服务端必须使用同一共享校验规则。

### 3.4 群组卡片、详情弹窗与 Carousel

群组卡片统一展示头像、标题、平台、最多四行简介、点赞按钮和点赞数量；不直接展示群号、链接、二维码、加群方式按钮或复制按钮。

卡片主体点击打开详情弹窗，不跳转独立详情页；点赞和其他独立控件不得误触发弹窗。卡片需支持鼠标、触摸、键盘聚焦、Enter 和 Space，且不得通过嵌套原生按钮制造非法结构。

详情弹窗展示完整群组信息、点赞、一个或多个按管理员顺序排列的加群方式、二维码/复制/打开链接等现有能力和分享按钮。打开弹窗时将 `group=<group_id>` 写入 URL，关闭时只移除 `group` 并保留其他查询参数。直接访问 `?group=` 时自动打开已发布群组详情；已下架、回收站、永久删除或无效群组不得通过深链接泄露信息。

当页面存在搜索词时，URL 形态应类似 `/?q=计算机&group=<group_id>`。从卡片打开弹窗后，浏览器返回应关闭弹窗，前进应重新打开；关闭弹窗不得清除搜索词或其他页面筛选状态，焦点应返回原卡片。无效详情深链接应显示非敏感错误，并允许关闭或清理无效 `group` 参数。

详情弹窗必须支持 Escape、遮罩、关闭按钮、焦点锁定和恢复、底层滚动锁定、移动端接近全屏、内容区滚动、深色模式和 `prefers-reduced-motion`。分享按钮复制不携带搜索词等无关参数的规范公开链接，成功和失败均有明确反馈。

详情 URL 契约示例：

```text
?group=<group_id>
/?q=计算机&group=<group_id>
/?group=<group_id>
https://当前域名/?group=<group_id>
```

Carousel 仅用于“发现新群”和自定义板块：

- “所有群组”和搜索结果不得使用超长单行 Carousel。
- 手机标准宽度至少同时露出两张卡片，不改为单卡独占。
- 支持触摸滑动、鼠标拖动、触控板/滚轮横向查看、键盘左右键和 `scroll-snap`。
- 仅在仍存在横向溢出时拦截滚轮；到达边界后恢复页面纵向滚动。
- 拖动距离超过阈值时视为拖动，不触发卡片点击。
- 通过露出下一张、渐变、箭头或位置指示等方式提示横向内容。

### 3.5 发现新群、标签与自定义板块

“发现新群”展示最近一次进入已发布状态的群组，不再使用随机排序。数据库新增可为空的 `last_published_at`，仅在以下状态转换时更新：新建后直接发布、草稿/待审核发布、已下架群组重新发布、从回收站恢复后再次发布。编辑已发布群组的标题、简介、标签、头像、加群方式，或保存一个仍为已发布状态的群组，均不更新时间。查询按 `status = published`、`last_published_at DESC, id DESC`，最多 10 条，不使用 WebSocket 或自动轮询；重新进入、刷新或触发请求即可看到更新。

查询规则必须等价于：

```text
status = published
ORDER BY last_published_at DESC, id DESC
LIMIT 10
```

少于 10 个时展示全部，不支持无限加载，使用 Carousel 展示。

“所有标签”使用一个独立大卡片，只统计已发布群组；已下架、回收站和永久删除群组不计入数量。通过聚合查询一次获得标签名称和数量，不得为每个标签单独发起数据库查询。点击标签会用标签文本替换而不是追加搜索框内容，标签不会追加到已有搜索词后面；更新 URL 并进入搜索状态，不跳转新页面。默认排序为数量降序、标签名称稳定次序，最终大小写/文本规则须在设计/审计阶段确认。

自定义板块必须支持：

- 创建、改标题、启用、关闭、删除、板块间拖拽排序。
- 修改内部排序模式、添加群组、移除群组、成员上移和下移。
- 仅启用板块出现在公开端；关闭板块仍可在管理端编辑。
- 启用但没有公开成员时显示板块空状态；板块总数为零时隐藏整个区域。
- 首次初始化或迁移幂等创建可编辑、可关闭、可删除的空板块“自定板块”，删除后允许板块数为零。
- 默认板块不具有特殊系统权限；它与其他板块具有相同的编辑、关闭和删除能力。
- 一个群组可属于多个板块，但同一板块不得重复。
- 板块成员数量不设硬上限；过长板块可以显示软性体验提示，但不得阻止保存。
- 可添加已发布和已下架群组，不可添加回收站群组；回收站移除群组时原子删除全部板块关联，并复用现有突变令牌/批量操作模式，恢复后不自动恢复。

群组状态与板块关联规则为：已发布保留关联且公开显示，已下架保留关联但不公开显示，回收站移除关联且不公开显示，永久删除不存在关联且不公开显示。

板块排序模式为：

```ts
type BoardSortMode = 'manual_asc' | 'manual_desc' | 'hourly_random'
```

其完整联合类型为：

```ts
type BoardSortMode =
  | 'manual_asc'
  | 'manual_desc'
  | 'hourly_random'
```

手动正序按管理员配置的成员位置展示；手动倒序按位置反向展示，管理端仍按标准位置顺序编辑。每小时随机模式在同一自然小时内稳定、刷新不变、下一小时重新排序、不写数据库、不覆盖人工位置，并使用 `board_id + 小时槽位 + group_id` 等稳定种子和站点配置时区。

### 3.6 所有群组与公开数据边界

“所有群组”使用响应式 Grid，仅展示已发布群组，继续沿用当前系统默认排序及其时区感知旋转规则，并保持 cursor pagination 与无限滚动。产品层面允许用户最终浏览全部群组，但 API 不得一次性返回全部记录。标准手机目标为至少两列，极端窄屏和高倍缩放优先保证可用性和无横向溢出。

所有公开接口不得返回下架、回收站或永久删除群组的敏感内容；详情深链接和各板块查询同样遵守此边界。板块单独加载失败时显示局部错误，不使整个首页白屏。

各区域状态必须具体可见：发现新群无数据显示空状态；所有标签无有效标签显示空状态；启用但无公开成员的板块显示板块空状态，板块总数为零时不显示该区域；所有群组无已发布群组时显示空状态并可引导提交；搜索无结果时展示关键词、无匹配提示和提交入口；群组详情不存在或不可公开时只显示非敏感错误并允许清理参数。

### 3.7 管理端

管理端主导航调整为群组管理、板块管理、数据分析；现有认证、登录、会话和权限机制保持不变。

群组管理改为固定每页 50 条的页码分页，返回 `items`、`page`、`pageSize: 50`、`totalItems`、`totalPages`。页码、搜索词、状态筛选、回收站筛选、排序字段和方向同步到 URL；筛选/排序/搜索变化回到第一页，删除当前页最后一项导致空页时自动退回上一页，刷新/前进/后退恢复状态。所有排序有稳定次排序字段。

管理端响应契约为：

```ts
{
  items: Group[]
  page: number
  pageSize: 50
  totalItems: number
  totalPages: number
}
```

URL 状态示例为：

```text
/admin/groups?page=3&status=published&sort=updated_at&direction=desc
```

分页器需要展示上一页、页码省略和下一页等导航，例如 `上一页 1 … 5 6 [7] 8 9 … 24 下一页`，并同时展示“共 1,173 条，第 7 / 24 页”等总量和当前位置。

分页器示例：

```text
上一页  1  …  5  6  [7]  8  9  …  24  下一页
共 1,173 条，第 7 / 24 页
```

以下能力必须保留：多状态筛选、回收站、排序、抽屉编辑、新建群组、脏表单守卫、版本冲突、图片上传、标签、加群方式和永久删除流程。

响应式表格永不隐藏标题、状态和操作列；空间不足时按标签、性质、点赞、平台的顺序依次隐藏，隐藏信息仍可在编辑抽屉查看。窄屏编辑/新建抽屉占满页面、锁定底层滚动，并保留 Escape、`beforeunload` 和路由守卫；安全区和软键盘不得遮挡操作按钮。

板块管理页面展示多个板块容器，每个容器包含拖拽手柄、标题、启用状态、排序模式、成员数、添加、编辑和删除入口及固定尺寸成员表格。板块拖拽使用原子批量更新并在失败时回滚乐观排序；成员表格内部滚动且不分页；编辑、上移、下移、移除和添加行为必须区分“移除关联”和“删除群组”。删除板块二次确认，删除成员关联但不删除群组，允许删除最后一个板块。

成员表格固定展示标题、状态和操作，状态至少区分已发布/已下架；第一项禁用上移，最后一项禁用下移；移除按钮不得命名为“删除群组”。添加选择器支持搜索，展示已发布/已下架、不展示回收站，清晰显示状态，对当前板块已有成员禁用或隐藏并防止重复添加。未启用板块仍可重命名、调整成员、调整排序、修改排序模式和删除。

### 3.8 数据库、API、安全与性能

数据库新增 `last_published_at`、`boards`、`board_groups` 及相应索引、外键、级联和位置约束。`board_groups` 主键为 `(board_id, group_id)`；板块/成员位置更新使用原子批量操作，不能产生重复位置、丢失位置或部分更新。

迁移要求：

- 已发布群组优先使用可靠发布时间回填 `last_published_at`，没有可靠时间时回填 `created_at`，不得统一回填部署时间。
- 从未发布的群组保持为空。
- 默认板块创建幂等，重复迁移不重复插入且不破坏既有板块。
