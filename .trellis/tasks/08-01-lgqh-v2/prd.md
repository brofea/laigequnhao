## 1. 已完成基线：T01-T03 不重新设计

### 1.1 T01 基础工程与现有后端

T01 已完成基础工程、项目框架和既有后端基础能力。现有认证、会话、CSRF、版本冲突、提交、点赞、图片资源生命周期、回收站、永久删除、D1、R2、Analytics、共享 Schema 和测试体系，均视为可复用基线。

T04 如果发现基线缺口，只能在总 PRD 和任务记录中明确缺口、影响、兼容策略和验收方式；不得在没有归属的情况下重写现有认证或存储机制。

### 1.2 T02 prototype v2 视觉基线

T02 已完成前端设计阶段。`prototype v2` 是最终产品视觉标准和唯一前端视觉真源，包含已确认的页面、Dialog、组件、布局、交互表现、主题、响应式规则和视觉细节。

后续任务不得以“优化体验”“统一设计”“重构组件”“修正审美”或类似理由推翻 prototype v2。任何与视觉基线的差异，都必须记录为问题并进入评审，不得在 T04-T06 中直接改设计。

### 1.3 T03 正式项目迁移与既有业务接入

T03 已完成 prototype v2 到正式项目的迁移，并接入已存在的业务能力。正式运行页面必须与 prototype v2 保持像素级一致；prototype 中的视觉结构可以被正式项目消费，但 prototype 不能作为生产运行时依赖，生产环境也不得混入 fixture、localStorage 假数据或临时 Mock。

T03 的验收结果作为 T04-T06 的冻结输入：页面结构、Vue 表现组件、CSS、布局、颜色、间距、动画、Dialog 设计和用户交互流程均不可重新设计。

## 2. 前端冻结规则（T04-T06 强制）

### 2.1 禁止修改

T04、T05、T06 禁止修改任何前端表现层内容，包括但不限于：

- 页面结构、页面信息架构和区域顺序。
- Vue 页面组件、表现组件和 Dialog 组件。
- CSS、Tailwind class、Token、颜色、间距、圆角、阴影、字体和布局。
- 动画、过渡、响应式视觉规则和断点表现。
- 卡片、Carousel、表格、抽屉、表单、Toast、ErrorBanner、Skeleton、空状态的设计。
- 按钮文案布局、控件排列、交互手势和用户交互流程。
- 以视觉“优化”、代码“重构”或接口“方便接入”为理由的表现层改动。

### 2.2 允许修改

在不改变冻结表现的前提下，可以修改：

- 后端服务、repository、service、route、权限和数据校验。
- D1 migration、索引、约束、数据清理和回滚脚本。
- API 请求/响应、共享 Contract、Zod Schema 和数据结构。
- R2 文件存储的必要服务端适配，但不得改变既有资源生命周期规则。
- 前端 API client、composable、store、query adapter、DTO mapper、请求取消和数据状态适配代码。
- 自动化测试、测试夹具、固定时间/主题/时区工具、部署配置和发布文档。

### 2.3 前端问题处理

发现正式项目与 prototype v2 不一致时，必须记录：问题截图或复现步骤、基线来源、影响范围、建议方案、是否阻塞发布和责任归属。T04-T06 不得直接修改前端表现实现来掩盖问题。

如果接口数据无法适配现有视觉结构，优先修正 T04 Contract/API 或 T05 非表现层 adapter；如果确实需要表现层变化，必须暂停该项、提交方案并取得用户明确批准。

## 3. V2 产品目标

本次剩余工作不是重新做前端，而是让已冻结的正式前端稳定消费完整真实业务能力，并安全发布：

1. 根据总 PRD 提供发现新群、标签聚合、自定义板块、详情深链、管理页码分页等后端能力。
2. 保留现有认证、提交、点赞、图片上传、回收站、永久删除、并发保护和资源清理能力。
3. 将正式前端的 Mock/fixture 接口替换为真实 API，同时保持 prototype v2 像素级视觉和既定流程。
4. 完成跨公开端、管理端、后端、数据库、存储、安全和测试体系的发布验收。

## 4. 非目标

以下事项不属于本次重新规划：

- 不重新设计 T01-T03。
- 不重新制作 prototype，不改变其页面、组件、样式和交互。
- 不增加普通用户注册、普通用户账号或原生移动端。
- 不将群组详情改成独立页面。
- 不引入 WebSocket、服务端实时推送或新的搜索相关性算法。
- 不重写管理员认证体系。
- 不改变现有 R2 图片资源生命周期。
- 不重新定义 Cloudflare Analytics 数据来源。
- 不为板块成员设硬上限、管理端每页条数切换或第一版拖拽成员排序。
- 不通过 T06 大规模重构已验收模块。

## 5. 新任务总览

### T04：后端能力扩展（`backend-feature-expansion`）

#### 任务目标

依据 `RPD.md` 为已冻结前端和后续业务流程提供完整、可测试、可安全迁移的后端能力。

#### 工作范围

- `last_published_at`、`boards`、`board_groups` 数据模型、migration、索引、约束和幂等初始化。
- 发布状态转换、发现新群、已发布公开过滤、标签聚合、公开详情和板块查询。
- 板块 CRUD、启停、顺序、排序模式、成员添加/移除/上移/下移和版本保护。
- 管理端固定每页 50 条的页码分页、稳定排序、总数和 URL 所需数据。
- 共享 TypeScript/Zod Contract、显示宽度规则、标题/简介边界和请求校验。
- 管理认证、CSRF、权限、突变令牌、原子更新和错误语义。
- 现有 R2 文件存储能力所需的服务端接口兼容；不得改变资源生命周期。
- Workers Vitest、domain 测试、迁移测试和 API Contract 测试。

#### 不包含内容

- 任何前端页面、Vue 表现组件、CSS、布局、主题、Dialog、动画或交互流程。
- 替换生产前端 Mock、接线 composable 或端到端用户流程。
- 视觉验收、发布部署和最终回归。

#### 依赖关系

依赖已完成的 T01-T03、现有数据库/服务/认证基础和 `RPD.md`。T04 是新 T05 的必要前置；T04 可在不等待 T05 的情况下独立完成后端规划与实现。

#### 验收标准

- 所有新表/字段/索引/约束可在本地和 Workers 测试数据库安全迁移，重复执行幂等。
- `last_published_at` 只在真实的非 published → published 转换时写入；现有数据保持 NULL。
- 公开 API 不泄露下架、回收站和永久删除内容，板块成员规则与总 PRD一致。
- 板块位置、成员位置和回收站关联清理具备原子性、并发保护和失败测试。
- 公开查询、标签聚合、详情、页码分页、Contract、权限和 CSRF 有自动化测试。
- 未修改任何前端表现层文件或视觉行为。

### T05：全栈业务适配（`fullstack-integration`）

#### 任务目标

在 T04 API/Contract 完成后，将 T03 交付的正式前端从 Mock/fixture 接入真实后端，打通公开端和管理端完整业务流程，同时保持 prototype v2 像素级一致。

#### 工作范围

- 盘点并移除生产路径中的 fixture、Mock、临时 fallback 和不应存在的 localStorage 假业务数据。
- API client、composable、store、DTO mapper、query adapter 和状态机接入真实 API。
- 公开端默认首页、搜索、标签、发现新群、板块、所有群组、详情深链、点赞、分享和提交流程的数据连接。
- 管理端登录/会话、群组 CRUD、分页/筛选/排序、图片上传、回收站、板块管理和分析数据连接。
- Loading、空数据、局部错误、重试、取消请求、并发更新、版本冲突和权限失败的既有状态接线。
- URL 查询状态和浏览器前进/后退的现有行为与真实数据同步。
- 端到端用户流程、接口契约和 adapter 测试。

#### 不包含内容

- 修改任何 Vue 表现组件、页面结构、CSS、Tailwind class、主题 Token、布局、动画、Dialog 或交互流程。
- 通过隐藏字段、改按钮、改变文案布局或增加临时视觉状态解决 API 问题。
- 新增 T04 未定义的业务规则或改变服务端数据语义。
- T06 的发布演练、性能基准、安全审计和最终验收。

#### 依赖关系

依赖 T01-T03 的冻结前端与 T04 已验收的 API/Contract。T05 必须在 T04 的迁移、权限、公开过滤和错误语义稳定后开始正式接线；T04 与 T05 不可同时修改同一 API 契约。

#### 验收标准

- 生产路径不再依赖 Mock/fixture，公开端和管理端关键流程均使用真实 API。
- 既有页面视觉快照与 prototype v2 保持像素级一致；若发现差异，只记录并上报，不直接改表现层。
- Loading、错误、空状态、重试、权限、CSRF、会话失效、版本冲突和 URL 状态均能按既有界面表现正确工作。
- 公开端、管理端、上传、回收站和板块流程均有可重复的自动化验证。
- 适配工作未改变产品交互流程或前端表现层定义。

### T06：系统加固与发布验收（`system-hardening-release`）

#### 任务目标

对 T04 后端和 T05 全栈适配形成的系统执行最终质量门禁，完成测试、性能、安全、迁移、部署、文档和发布验收。

#### 工作范围

- Vitest、Workers Vitest、Playwright 和视觉回归的全量执行与缺口补齐。
- 公开端/管理端关键用户流程、浏览器矩阵、键盘焦点、主题、响应式和无横向溢出验证。
- API、认证、CSRF、权限、输入校验、公开数据边界、速率限制、文件上传和资源清理安全检查。
- D1 migration 重复执行、旧新代码兼容窗口、失败恢复、备份/回滚和数据演练。
- 构建、部署、环境变量、健康检查、日志、监控、发布清单和回滚文档。
- 性能基线、查询计划、N+1 检查、页面加载和 API 错误率门禁。
- 只做必要的跨任务集成修复；表现层差异只记录，不直接改设计。

#### 不包含内容

- 重新设计任何前端表现或推翻 prototype v2。
- 大规模重构 T04/T05 已验收的业务模块。
- 借回归任务新增未经批准的产品需求。
- 以关闭测试、降低断言或删除视觉基线来制造“通过”。

#### 依赖关系

必须等待 T04 和 T05 完成并提供可部署构建、迁移说明、测试证据和已知问题清单。T06 是发布前最后一个实施任务；最终发布结论由总任务汇总。

#### 验收标准

- 全量测试和必要的视觉/无障碍/性能/安全门禁通过，失败项有明确阻塞结论。
- 迁移可重复演练、回滚路径可执行、生产配置和健康检查可验证。
- 现有提交、点赞、认证、上传、回收站、永久删除和 R2 清理无回归。
- 未发现公开数据泄露、关键权限绕过、CSRF 绕过、重复位置或不可恢复数据问题。
- 形成可审计的发布文档、测试报告、遗留问题和最终验收记录。

          │
          ▼

## 7. 总任务级验收

总任务只有在以下条件全部满足后才能完成：

1. T04、T05、T06 的 planning 文档齐全且已获用户认可。
2. 迁移、Contract、公开过滤、权限、CSRF、版本冲突和资源生命周期有证据。
3. 公开端和管理端真实流程通过自动化验证。
4. prototype v2 与正式前端的视觉冻结验收通过，或所有差异均有用户批准的记录。
5. 全量测试、部署、迁移演练、性能和安全检查通过。
6. 没有未记录的前端表现改动、公开数据泄露或破坏性迁移风险。
7. 发布文档包含部署步骤、环境变量、健康检查、回滚、监控和遗留问题。
