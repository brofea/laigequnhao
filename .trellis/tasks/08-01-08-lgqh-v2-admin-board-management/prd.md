## 1. 任务定位与联合 Review

T08 依赖 `t03-visual-migration` 的正式 AdminLayout/Token/管理组件基础和 T05 的板块 API/Contract，间接复用 T01/T02 的审计与视觉基线。它在已迁移的三页面 UI 上接入真实板块 CRUD、固定高度成员表、添加/编辑/移动/移除、板块重排、冲突/回滚和管理数据流。

联合产品、Staff Engineer、QA Review 冻结：

1. 现有群组管理和数据分析业务必须保留，只接入统一壳层、导航、标题和状态视觉。
2. 实际路由先审计，建议语义为 `/admin/groups`、`/admin/boards`、`/admin/analytics`；旧书签不得无提示失效。
3. T08 不改群组列表 API、页码分页、每页 50、表格列隐藏、窄屏最终抽屉；这些全部由 T09 负责。
4. 板块页面使用 T05 后端正式返回顺序、version、状态、计数和成员；前端不自行修改 position 或重算小时随机。
5. 板块数量可为 0，默认“自定板块”可删除且删除后不重建；空板块仍显示完整容器和添加入口；未启用板块仍可编辑成员。
6. 管理成员表固定高度、内部滚动、三列标题/状态/操作，不分页、不硬上限、不实现成员拖拽；板块之间才允许拖拽排序。
7. 已发布和已下架群组可添加；回收站/永久删除不可选；移除只解除关系，不删除群组；编辑复用现有群组抽屉。
8. 版本冲突、CSRF、会话失效、网络/Contract 错误必须有明确反馈和乐观回滚，不静默覆盖其他管理员。
9. 所有管理写入使用 T05 typed client、CSRF、mutation token、expectedVersion；不得散落原始 fetch 或建立第二套 Toast/Dialog。

## 2. 用户价值

- 管理员在统一导航下快速切换群组管理、板块管理和数据分析。
- 管理员可直观维护板块顺序、启用状态和成员关系，并看到已发布/已下架状态。
- 失败操作可回滚，版本冲突可刷新后重试，避免“看起来成功但数据被覆盖”。
- 固定高度成员表支持大量成员的可控浏览，手机仍能完成所有关键操作。
- 现有群组审核、回收站、永久删除、统计和会话能力不因壳层整合退化。

## 5. 需求与验收

### R08-01 三页面壳层

三个页面使用统一 AdminLayout、导航、标题区域、加载/错误/Toast、管理员会话、主题和响应式。当前路由有高亮和 `aria-current=page`；可鼠标/触摸/键盘/直接 URL/返回前进；未认证不能读取管理数据。

### R08-02 板块容器

每板块按 API 顺序显示 title、启用状态、用户文案 sortMode、成员计数、添加/编辑/删除。未启用仍可操作；空板块不隐藏；零板块显示创建说明和主按钮，不生成本地虚拟默认。

### R08-03 CRUD

创建 title/isEnabled/sortMode、服务端追加位置；编辑 title/isEnabled/sortMode+expectedVersion；删除确认明确只移除关系、不删群组，并支持普通/默认/最后板块。成功以服务端对象/version 覆盖本地，失败不插临时/不局部移除。

### R08-04 重排

只拖拽板块头部，桌面支持 pointer，手机/键盘有上移/下移后备。完整顺序+版本+token 提交；可乐观显示，成功以服务端顺序覆盖，失败/409 回滚并刷新最新数据；成员表内部滚动和按钮点击不能被拖拽捕获。

### R08-05 成员表与操作

固定高度、内部滚动、语义 table 三列。管理顺序始终人工 position ASC，sortMode 不改变表行。候选分页/限量、允许 published/delisted、排除 trash/duplicate；添加追加、移除压缩关系、上移/下移交换相邻、边界禁用、版本/token 原子。移除不删群组。

### R08-06 群组编辑/联动

复用现有群组编辑抽屉和脏表单守卫。群组下架保留行并标记下架；重新发布恢复显示；进入回收站后后端清理关系，页面移除/同步；恢复后不自动恢复旧关系。

### R08-07 状态、安全和无障碍

页面/板块/成员有独立 Loading/Error/Retry；写操作认证+CSRF+Zod+version+token；错误不泄露 SQL/token。导航、板块、table、drag handle、buttons、dialogs 有语义、focus、Escape、live feedback；手机无页面横向溢出，reduced motion 不丢功能。
