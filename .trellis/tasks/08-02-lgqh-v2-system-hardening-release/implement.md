## 13. 阶段十三：缺陷回派

- Schema、API、迁移、事务、安全：回 T04。
- API client、adapter、竞态、Mock：回 T05。
- Vue、CSS、布局、Dialog、交互：记录并向用户 brainstorm。
- 测试工具、部署、监控、文档：T06 自行处理。

每个缺陷包含：编号、严重性、复现、期望、实际、证据、任务、阻塞、修复 commit、复测结果。

## 14. 阶段十四：编写 acceptance.md

每项写明：

- 需求来源章节。
- 验收编号。
- 场景和前置数据。
- 命令或操作步骤。
- 环境和版本。
- 期望结果。
- 实际结果。
- 截图/trace/log 路径。
- 状态 passed/failed/blocked/waived。
- 责任人和复测。

不得把未执行项写成 passed；waived 必须有批准、风险和有效期。

## 15. 阶段十五：最终发布结论

只有以下均满足才可建议发布：

- [ ] T04/T05/T06 移交齐全。
- [ ] 自动化测试通过。
- [ ] 视觉/无障碍通过。
- [ ] 性能/安全无阻塞。
- [ ] migration/部署/回滚可执行。
- [ ] 无生产 Mock。
- [ ] 无公开数据泄露。
- [ ] 无未批准前端表现改动。
- [ ] 所有遗留问题有明确结论。

## 16. T06 完成定义

T06 只能在 `acceptance.md`、发布文档、测试结果、演练证据和遗留问题均完成后进入 review。完成 review 不等于自动发布；最终发布仍由总任务和用户确认。

## 19. 最终停止条件

若发现公开泄露、权限绕过、不可恢复 migration、生产 Mock、关键流程失败或未批准前端改动，立即停止发布建议，保留证据并回派责任任务。不能用降低测试范围、更新截图基线或手动修改数据来制造通过。
