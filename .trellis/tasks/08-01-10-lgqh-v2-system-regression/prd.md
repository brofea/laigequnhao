## 2. 联合 Review 结论

本 PRD 已从高级产品经理、Staff Engineer 和 QA 负责人三个视角进行二次 Review。

### 2.1 产品视角

- T10 的职责是证明既有 V2 交付物可以整体发布，而不是新增产品功能。
- 所有产品规则以冻结的 V2 总 PRD、已确认 UI 设计和各子任务 PRD 为准。
- 发现产品规则冲突时必须记录决策问题并退回原任务或总任务，不可在验收期间私自改规则。
- 默认首页顺序、搜索模式、板块排序、卡片信息、Dialog 行为、管理分页和响应式优先级均属于冻结规则。
- 发布结论必须是明确的“通过，可以发布”或“未通过，禁止发布”。
- “大部分通过”“基本可用”“已知小问题”不能替代发布闸门结论。

### 2.2 Staff Engineer 视角

- T10 必须验证前端、共享 Contract、Workers API、D1 migration、R2 生命周期和部署顺序的完整数据流。
- 现有仓库已经提供 `typecheck`、`lint`、`build`、`test`、`test:workers`、`test:e2e` 和测试迁移脚本；执行时必须以 `package.json` 实际脚本为准。
- 当前 Playwright 配置已覆盖 Chromium 桌面和手机，Firefox、WebKit、完整视口与主题矩阵需要在规划执行阶段补齐或明确证据来源。
- D1 迁移不可假定可回滚；必须优先验证备份、前向修复和旧代码兼容性。
- 公共 API 必须严格投影公开字段，管理 API 必须认证、CSRF 和版本并发控制完整。
- 跨任务修复必须最小化，并且每个修复都要有根因、自动化回归和重新验收记录。

### 2.3 QA 视角

- 单文件测试通过不等于全量回归通过；必须检查串行、并行、重复执行、数据隔离和时间稳定性。
- S0、S1 和未批准延期的 S2 是发布阻塞项。
- 视觉截图只能使用固定数据、固定时间、固定字体、固定浏览器和已审查的基线。
- 键盘、焦点、ARIA、对比度、200% 缩放、减少动态效果和 WebKit 移动端均属于验收范围。
- migration 必须覆盖空库初始化、旧库升级、超限旧数据、默认板块幂等和失败演练。
- 每个失败都要有可复现步骤、预期、实际、严重级别、责任归属、修复和复测证据。

## 3. 目标

- 验证 T01–T09 的公开端、管理端、共享层、Workers 和数据库行为可以共同工作。
- 验证首页、搜索、标签、动态板块、所有群组、卡片、Carousel、Dialog、分享和点赞没有跨功能回归。
- 验证管理群组分页、响应式表格、三页面导航、板块管理、成员操作、回收站、永久删除和 Analytics 没有跨页面回归。
- 验证 `last_published_at`、显示宽度、板块排序、稳定随机、游标、页码、总数和关联清理的一致性。
- 验证浅色、深色、自动主题、桌面、平板、手机、横屏和低高度窗口。
- 验证 Chromium、Firefox、WebKit 桌面和 WebKit 移动端核心流程。
- 验证键盘完整可用、焦点管理、ARIA 语义、对比度、200% 缩放和减少动态效果。
- 验证请求数量、N+1、缓存失效、事件监听器、Observer、DOM 规模和内存没有明显 V2 回归。
- 验证空数据库、旧数据库、迁移顺序、回填、默认板块、超限数据和失败恢复路径。
- 形成真实可执行的最终验收证据，而不是提前声称测试通过。

## 5. 范围内功能对象

### 5.1 公开端

- 顶栏、Logo、站点名、主题三态、GitHub 支持和添加群组入口。
- 默认首页固定区域顺序。
- 发现新群最多 10 个、已发布过滤、`last_published_at` 和稳定 ID 次序。
- 标签聚合、排序、换行、点击搜索和无泄露。
- 动态板块启用过滤、位置排序、空板块、零板块、公开成员投影和每小时随机。
- 所有群组 Grid、现有旋转排序、cursor、无限滚动、去重和失败重试。
- 搜索 debounce、IME、标题/简介/标签匹配、`q` URL、cursor、清空恢复和竞态保护。
- GroupCard 的头像、标题、平台、简介、点赞和不显示加群按钮规则。
- Carousel 的鼠标、触摸、触控板、滚轮、键盘、边界、拖动误触和减少动效。
- 详情 Dialog、`group` 深链接、加群方式、二维码、复制、分享、焦点、滚动锁定和移动端。
- 点赞同步、乐观更新、失败回滚、匿名设备状态和跨实例同步。
- 群组提交、显示宽度、标签、加入方式、图片、Turnstile 和主题。

### 5.2 管理端

- 管理员登录、会话、认证保护和 CSRF。
- 群组、板块、Analytics 三页面导航及旧路径兼容。
- 群组固定每页 50 条、`totalItems`、`totalPages`、URL 状态、稳定排序和删除退页。
- 响应式表格列隐藏优先级：Tags、Property、Likes、Platform，Title/Status/Actions 始终保留。
- 新建/编辑全屏抽屉、动态视口、安全区、软键盘、脏状态和焦点恢复。
- 板块 CRUD、启用状态、排序模式、板块拖拽、键盘/移动端后备和版本冲突。
- 成员候选、添加、编辑、上移、下移、移动、移除、固定高度表和内部滚动。
- 回收站、恢复、永久删除、资源生命周期和关联清理。
- 数据分析既有能力、加载、空数据、错误、重试、主题和移动端。

### 5.3 后端与数据

- 共享 Zod Contract、DTO、Schema、错误映射和公开/管理字段边界。
- `last_published_at` 的写入、回填和排序语义。
- `boards`、`board_groups`、索引、约束、默认板块和删除规则。
- 板块公开过滤、排序、稳定随机、成员批量查询和 no N+1。
- 管理分页、COUNT 与 items 条件一致、稳定 tie-break 和边界规范化。
- cursor 公开 API 不受管理页码分页影响。
- 回收站原子清理、恢复不重挂关联、永久删除和 R2 共享资源保护。
- 缓存、canonical origin、环境变量、D1、R2、Analytics 和 Turnstile 配置。

## 6. 范围外和禁止事项

- 不重新设计首页信息架构、管理端导航或卡片信息。
- 不改变四行简介、标题 50、简介 1000、管理每页 50、响应式列优先级或排序规则。
- 不增加新的用户角色、批量管理、通知、WebSocket 或其他产品功能。
- 不大规模重写 repository、service、组件树或引入大型 UI/请求框架。
- 不修改历史 migration；仅允许总任务批准的前向修复 migration。
- 不删除、跳过或永久标记测试以取得通过。
- 不以扩大全局超时、无条件重试或无审查刷新视觉基线掩盖问题。
- 不在文档、日志、截图或测试数据中暴露密钥、会话、CSRF、设备哈希或真实生产敏感数据。
- 不在 T10 中擅自解决需要产品决策的冲突；应退回原任务或总任务。

## 7. 严重级别和发布闸门

### 7.1 S0：数据或安全灾难

- 未授权读取管理数据。
- CSRF 可绕过或会话信息泄露。
- 已下架、回收站或非公开群组出现在公开端。
- migration 丢数据、永久删除误删共享资源或板块误删群组。
- 版本冲突静默覆盖。
- 分享链接包含会话、安全参数或错误环境域名。
- S0 必须为 0，必须修复并新增自动化回归。

### 7.2 S1：核心功能不可用

- 首页、搜索、登录、群组编辑、板块创建/排序、Dialog 关闭或深链接不可用。
- 管理分页跨页重复/遗漏、回收站关联未清理或核心移动端流程失败。
- S1 必须为 0，必须修复并重新运行受影响全量套件。

### 7.3 S2：重要体验或兼容问题

- 某浏览器 Carousel、深色模式、抽屉键盘、返回历史、焦点或响应式列异常。
- 默认阻塞发布；只有总任务或用户明确批准延期，且不影响核心使用，才可延期。

### 7.4 S3：非阻塞问题

- 轻微间距、非核心动画或不影响操作的视觉差异。
- 必须记录后续归属、风险和处理建议。

### 7.5 发布闸门

- S0 = 0。
- S1 = 0。
- 未批准延期的 S2 = 0。
- Typecheck、Lint、Format check、Build 以及全部必需自动化测试通过。
- migration 空库、旧库、超限数据和失败演练通过。
- 公开数据、认证、CSRF、共享 Contract 和缓存检查通过。
- Chromium、Firefox、WebKit 的核心流程通过。
- 桌面、平板、手机、深浅主题、键盘、缩放和减少动效通过。
- 视觉基线经审查，`acceptance.md` 完整且记录真实命令与结果。
- 最终结论只能是明确可发布或禁止发布。
