## 3. 目标与产品价值

### 3.1 核心目标

在 T02 已确认的 `ui-design.md` 基础上，将设计语言正式接入生产前端：

1. 建立语义化 CSS 自定义属性、Tailwind 映射和必要的尺寸/动效 Token。
2. 建立默认 `system`、可手动选择 `light`/`dark` 的三态主题偏好，并区分用户偏好和实际主题。
3. 安全持久化主题、监听系统主题、同步根节点标记并避免首屏闪烁。
4. 建立正式全站顶栏：Logo、网站名、主题控件、GitHub 支持和添加群组入口，宽屏与窄屏均保留核心操作。
5. 建立后续组件可复用的 Focus-visible、Hover、Active、Disabled、状态色、Skeleton、遮罩和减少动态效果基础。

### 3.2 产品价值

- 后续 V2 前端任务消费同一套视觉运行时，不重复解释颜色、层级、主题和顶栏行为。
- 用户可以清楚选择自动、浅色或深色，并在刷新、系统变化和多标签页场景下得到可预测结果。
- 顶栏在桌面和手机上保持品牌、主题、GitHub 和添加群组三类核心操作，不以汉堡菜单或单独加号隐藏功能。
- 旧页面可以渐进迁移，不因基础设施任务一次性重写所有生产业务。

## 5. 范围内需求

### R03-01 正式 Token 体系

根据已确认 `ui-design.md` 建立原始、语义、组件三层 Token。至少覆盖：

- 页面/表面：页面背景、内容背景、卡片、抬升表面、弱化表面、输入框和遮罩。
- 文字：主、次、弱化、反色、链接、禁用。
- 边框：默认、弱、强、焦点、分隔线。
- 操作：主色、Hover、Active、前景色、次操作背景和 Hover。
- 状态：成功、警告、危险、信息及其背景、文字、边框。
- 交互：Hover、Active、Selected、Focus ring、Disabled。
- 加载：Skeleton 基础/高光、Loading 遮罩。
- 原始色阶、间距、字号、行高、圆角、阴影、动画时长、缓动和层级数值。
- 稳定组件尺寸：顶栏高度、页面最大宽度、搜索框高度、卡片圆角、Dialog 最大宽度和表格行高等。

语义 Token 是生产组件的首选；不得在新顶栏中散落十六进制颜色、任意间距或重复主题 class；不得为每个局部像素值建立难以维护的变量。

### R03-02 Tailwind 映射与渐进迁移

Tailwind 必须映射到 CSS 自定义属性，保持浅色/深色共用语义 class。不得破坏现有 `brand.primary` / `brand.accent` 使用，不得一次性重命名全部旧 class 或引入大型 UI 框架。

渐进迁移规则：新代码使用正式语义 Token；本任务直接负责的顶栏必须完成迁移；容易安全替换的全局背景/文字可迁移；卡片、首页、板块和分页等复杂组件留给对应子任务；未迁移旧硬编码颜色必须记录。

### R03-03 三态主题模型

正式主题必须表达：

```ts
type ThemePreference = 'system' | 'light' | 'dark'
type EffectiveTheme = 'light' | 'dark'
```

默认用户偏好为 `system`。规则为：`light → light`、`dark → dark`、`system → 根据 prefers-color-scheme`。用户偏好和实际主题必须分离：系统当前为深色时，用户选择“自动”仍显示“自动”而不是“深色”。

### R03-04 主题持久化和异常

使用集中定义、带项目命名空间、与 `deviceId`/`likedIds` 不冲突的稳定 key。存储规则唯一且写入文档：选择自动保存 `system`，不通过删除 key 产生歧义。

以下值均安全回退到 `system`，且不能阻止应用加载：空字符串、未知字符串、JSON 损坏、旧版本无效值、非字符串值、读取/写入 `SecurityError`、隐私模式和存储禁用。当前会话内切换仍必须生效。

如实现跨标签页同步，使用 `storage` 事件并覆盖：一个标签页变更、另一个更新、当前标签页不重复处理；如 T01 证明不需要，必须记录不实现的原因。

### R03-05 系统主题监听

偏好为 `system` 时首次读取和持续监听 `prefers-color-scheme`；系统浅深变化应立即更新实际主题。偏好为 `light`/`dark` 时系统变化不得覆盖用户选择；切回 `system` 立即采用当前系统状态。

监听必须兼容目标浏览器、只注册必要次数、在生命周期清理、避免 HMR/重复挂载多次注册，并在测试中可替换/模拟。`matchMedia` 不可用时按项目指定安全默认实际主题加载。

### R03-06 根节点和首屏初始化

实际主题统一应用到 `document.documentElement` 的唯一标记机制，采用 class、`data-theme` 或 T02 Spec 指定方式；不得同时维护互相竞争的 `.dark`、`data-theme` 和仅媒体查询三套来源。必要时同步 `meta[name="color-scheme"]`，避免原生控件与页面冲突。

在 Vue 和可见 CSS 内容前执行最小、同步、无网络、无异步请求、无大型依赖的初始化：安全读取偏好、校验、读取系统主题、写入根节点标记；失败时安全回退。首屏逻辑必须与正式主题模块保持一致，不能形成两套漂移算法。

### R03-07 正式主题控件

控件必须明确提供“自动”“浅色”“深色”，而不是只有不断循环的图标按钮。控件遵守 `ui-design.md` 的形式，可为菜单、分段选择器或下拉；必须有当前偏好语义、键盘和触摸操作、Escape/方向键等适用行为、可访问名称和即时反馈。主题切换不得修改路由或查询参数，除非 T02 明确要求视觉反馈且不改变业务状态。

### R03-08 正式全站顶栏

顶栏左侧固定 Logo 和网站名；右侧固定主题模式控件、GitHub 支持按钮、添加新群组按钮。品牌、GitHub 地址和添加目标来自正式配置/常量，不在多个组件硬编码。

宽屏：Logo/网站名完整；主题和 GitHub 显示图标+文字；添加按钮显示 `+ 添加新的群组`；间距稳定、不折行、不遮挡。

窄屏：保留 Logo 和原则上保留网站名；主题/GitHub 可仅显示图标；添加按钮显示 `添加群`，不得缩减为单独加号；不得使用汉堡菜单、隐藏主题/GitHub/添加操作或产生页面级横向滚动。极窄时只按已确认 Spec 缩小间距、Logo 或截断网站名，不删除功能。

顶栏导航遵守现有路由规则：Logo/网站名延续当前首页导航；添加按钮进入现有提交流程；GitHub 使用真实配置；主题切换不清除 `q`、`group`、管理页码/筛选/排序等 URL 状态。

顶栏只负责品牌、主题、GitHub、提交入口和布局，不负责搜索、详情、点赞、管理员会话、板块或分析数据。公开页面至少复用同一正式顶栏；登录页/管理端可使用共享基础壳层和变体，但不得强行改变管理业务导航。

### R03-09 公共基础状态样式

建立后续组件可复用的 Focus-visible、Hover、Active、Disabled、Success、Warning、Error、Info、Skeleton 和遮罩基础。Focus 不得被全局规则移除；Disabled 同时有视觉、指针/交互和原生/ARIA 语义；Hover/Active 不造成布局跳动；状态不只依赖颜色；所有状态有浅深色映射。

支持 `prefers-reduced-motion: reduce`，至少降级主题切换、顶栏按钮、Skeleton、菜单和 Hover 位移动画；不得用长时间全页面颜色过渡制造闪动。

### R03-10 兼容性和渐进接入

现有页面必须继续可打开、搜索可用、登录页可用、管理页可用、提交入口可进入、Toast/ErrorBanner 可见、管理抽屉可打开、二维码弹窗层级正常、点赞可点击。修复由 T03 引入的功能性破坏，但不提前修复属于 T06/T07/T08/T09 的视觉重构。

不得用过宽的全局 CSS 规则破坏所有 `button`、`a`、`input`、`table`、`img` 或 `dialog`；不得一次性重写所有正式页面。

### R03-11 可访问性、性能和配置

主题控件需支持 Tab、Enter/Space、适用方向键、Escape、当前选项语义和可访问名称；窄屏图标按钮必须有名称、Tooltip/等效提示、合理触摸目标和清晰焦点。浅深色均检查主/次文字、按钮、链接、Focus ring、状态标签和禁用态对比度；200% 缩放下顶栏核心操作可用、无不可恢复溢出。

主题初始化不得发网络请求、动态加载大型模块、长时间阻塞或依赖异步 Vue 生命周期；顶栏图标复用现有体系，不为三个按钮引入大型图标库。GitHub/Logo 配置缺失时开发环境应可发现失败，不渲染无效链接或虚假地址。

### R03-12 测试和交付物

必须交付正式 CSS Token、浅深映射、Tailwind 映射、主题类型/模块/持久化/系统监听/根节点同步/首屏初始化、三态控件、正式顶栏、公共状态样式、Vitest、Playwright、视觉截图、回归结果和实施说明（key、根节点标记、Token/顶栏路径、后续使用方式、未迁移范围）。

Vitest 覆盖主题解析、非法值、存储异常、实际主题、手动/系统关系、状态同步、监听生命周期、顶栏配置和可访问性。Playwright 覆盖默认自动、自动深色、手动浅色/深色、切回自动、非法存储、首屏防闪烁、360/390/768/1024/1280/1440 顶栏、外链/提交路由和查询参数保护。生成桌面/手机浅深色顶栏、主题控件、现有公开/管理页面基础 Token 截图，并回归现有核心流程。

## 6. 非目标与禁止事项

本任务不负责：数据库、migration、Hono route、repository、service、认证、CSRF、板块后端、群组卡片、Carousel、详情 Dialog、首页信息架构、搜索、管理分页、板块管理、大规模正式页面重构或业务 API。

禁止引入大型 UI 框架/新状态管理库、复制 T02 Mock 业务、使用授权不明字体/资产、把主题写入后端、让主题修改 URL、把自动模式固定为首次检测结果、用单一循环按钮替代三态选择、窄屏用单独加号或汉堡菜单隐藏操作、在 T02 未确认前自行改变 Token。
