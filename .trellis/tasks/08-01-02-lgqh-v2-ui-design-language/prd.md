## 3. 目标与产品价值

### 3.1 核心目标

本任务要在 V2 正式前端功能开始前完成三项可独立审查的产出：

1. 以用户提供且可审查的主要视觉模板为来源，记录视觉分析、采用/调整/放弃的特征及授权风险。
2. 形成项目级前端 Spec `ui-design.md`，让后续 Agent 能按照明确的 Token、主题、响应式、组件和状态规则实现页面，而不重新猜测视觉方向。
3. 制作一个不连接真实后端的可运行视觉样例，用固定模拟数据验证公开端、管理端、浅色/深色、核心状态、响应式行为和本地交互。

### 3.2 产品价值

- 让公开端发现群组、搜索、标签、板块、卡片和详情弹窗形成一致的信息层级。
- 让管理端表格、板块容器、抽屉、状态和操作在相同视觉语言下保持可读且可操作。
- 在正式组件大规模开发前发现信息密度、窄屏布局、主题对比度、焦点和滚动行为问题，减少返工。
- 为 T03 主题/Token/顶栏、T06 卡片/Carousel/详情弹窗、T07 首页/搜索、T08 板块管理、T09 管理分页和 T10 回归验收提供同一份可追踪视觉契约。

## 5. 范围内需求

### R02-01 模板来源与设计语言分析

`ui-design.md` 必须记录主要模板的名称、来源、链接或本地来源、获取/审查日期、主要参考页面、主要参考组件和主要参考状态。必须区分主要模板、辅助参考和用户明确不采用的内容。

至少分析以下四个层面：

- 页面：最大宽度、内容留白、页面背景、顶栏高度、Section 间距、卡片密度、主次内容关系。
- 排版：标题比例、正文字号、辅助文字、行高、字重、长文本阅读和数字/状态展示。
- 组件：按钮、搜索框、卡片、标签、弹窗、表格、分页、导航、空状态和加载状态。
- 交互：Hover、Active、Focus、展开/关闭、拖动、滚动提示、状态切换和动画节奏。

每项特征必须标记为“直接采用”“调整后采用”“仅作参考”或“不采用”，并记录适配当前项目内容密度和 V2 信息架构的原因。

### R02-02 授权与资产风险

必须记录模板许可证、商用许可、修改许可、代码复用许可、图片/插图/图标/字体的使用限制、署名要求、不可提交资产及替代方案。无法确认授权时，只能借鉴一般视觉规律，不复制模板源码、品牌资产、专有插图、受限字体或具有明显独创性的整套页面。

该记录不是法律结论；必须诚实标记“已确认”“未确认”或“不适用”，并给出采用系统字体、项目已有资源或明确可用开源资源的替代方案。

### R02-03 Design Token 规范

`ui-design.md` 必须建立原始 Token、语义 Token 和组件 Token 三层体系，使用语义化命名。至少覆盖：

- 原始 Token：色阶、字号、间距、圆角、阴影、动画时长和缓动。
- 语义 Token：`background`、`surface`、`surface-raised`、`surface-muted`、`overlay`；`text-primary`、`text-secondary`、`text-muted`、`text-inverse`、`text-link`；默认/弱/强/焦点边框；`accent`、`accent-hover`、`accent-active`、`accent-foreground`；`success`、`warning`、`danger`、`info`。
- 组件 Token：顶栏高度、搜索框高度、卡片圆角和内边距、Dialog 最大宽度、表格行高、Carousel 间距、按钮尺寸和管理容器间距。

设计规范必须建立有限、可复用的间距等级，覆盖页面边距、Section、卡片、表单、按钮、图标文字和表格单元格；建立小控件、按钮/输入框、普通卡片、大卡片、弹窗和圆形图标按钮的圆角规则；建立无阴影、轻浮层、卡片 Hover、粘性顶栏、Dialog 和拖拽状态的阴影规则。

### R02-04 主题设计

设计规范和样例必须兼容：

```ts
type ThemePreference = 'system' | 'light' | 'dark'
```

每个关键语义 Token 必须有浅色值、深色值、使用场景和对比度注意事项，同时覆盖页面、卡片、文字、边框、Hover、Active、Focus、Disabled、Selected、Success、Warning、Error、Skeleton 和遮罩。样例必须能切换自动、浅色、深色三种偏好，并展示实际效果。

深色模式不得只是把白色变纯黑、机械反转灰色、使用过亮大面积纯色、抹平层级、让 Skeleton 与背景不可区分、让状态色失去辨识度或对二维码内容施加破坏性滤镜。

### R02-05 响应式规范

`ui-design.md` 必须以内容何时无法合理布局为依据定义断点，说明页面断点与容器/组件独立规则的使用边界。至少覆盖 360px、390px、768px、1024px、1280px、1440px 代表宽度，以及 200% 缩放、横屏手机/窄高度、超长中文、超长英文单词和 Emoji 混排。

必须定义：

- 页面最大宽度、桌面/平板/手机左右边距、超宽屏处理和安全区。
- 顶栏 Logo、网站名、主题控件、GitHub 控件和添加群组按钮的宽屏布局；窄屏时主题/GitHub 可仅显示图标，添加按钮文案为“添加群”，不得变成单独加号、汉堡菜单或隐藏核心操作。
- Carousel 的手机至少同时露出两张卡片、桌面卡片宽度、间距、边缘露出、箭头条件、渐变遮罩、触摸和鼠标行为。
- Grid 的手机/平板/桌面/超宽列数、最小卡片宽度、间距；标准手机目标至少两列。
- 管理表格按“标签 → 性质 → 点赞 → 平台”顺序隐藏列，并永久保留“标题 → 状态 → 操作”；至少展示完整桌面、中等宽度和窄屏状态。
- 桌面 Dialog 最大宽度、手机接近全屏规则、管理抽屉宽度、窄屏全屏规则、安全区、底部操作区和内容滚动区。
- 全部目标宽度不得产生非预期页面级横向滚动。

### R02-06 组件规范

`ui-design.md` 必须覆盖以下组件及其尺寸、层级、状态、响应式和无障碍要求：

1. 顶栏：高度、背景、边框/阴影、Logo、网站名、操作按钮、粘性建议和响应式。
2. 主搜索框：桌面/手机宽度、高度、圆角、图标、Placeholder、输入、Focus、Loading、清除、错误和切换时的位置稳定。
3. Section：标题、可选说明、操作区、上下间距、空状态位置、Carousel/Grid 内容区。
4. 群组卡片：头像、标题、平台、最多四行简介、点赞按钮和数量；不得包含加群按钮、群号、二维码和复制按钮；覆盖 Carousel/Grid、Hover、Focus、Pressed、点赞、长标题/简介、缺失头像、长平台名和手机双列。
5. 群组详情 Dialog：头像、完整标题/简介、平台、点赞、多个加群方式、分享、关闭、二维码、长内容滚动、手机和深色模式。
6. Carousel：滚动区、间距、箭头、边缘提示、拖动、键盘焦点和边界。
7. 标签聚合卡片：名称、数量、Hover、Focus、Selected/Active、标签过多和展开策略预留。
8. 按钮：主、次、文本、危险、图标、紧凑六类；每类覆盖默认、Hover、Active、Focus、Disabled、Loading。
9. 表单控件：单行/多行输入、Select、Checkbox、Switch、标签编辑器、字符计数、错误和帮助文字。
10. Toast、ErrorBanner、Skeleton：成功、错误、警告、信息、加载骨架、深色和手机位置。
11. 管理端群组表格：表头、行高、Hover、Selected、状态标签、排序图标、操作、分页、空/加载和响应式列隐藏。
12. 板块管理容器：拖拽手柄、标题、启用状态、排序模式、成员数、添加/编辑/删除、固定高度成员表格、内部滚动、空/未启用状态和拖拽状态。

### R02-07 可运行无后端视觉样例

样例必须能通过项目规定命令在浏览器运行，不需要 Cloudflare、D1、R2、认证或后端；使用固定模拟数据；与正式生产路由、导航、API、localStorage 业务键、管理员会话、真实数据和正式 Playwright 场景隔离；易于删除或后续转化为正式组件。

在 T01 影响图确认安全位置前，不锁死入口方案。候选方案必须从独立原型目录、独立 Vite 入口、仅开发环境预览入口或既有且无需重依赖的组件预览环境中选择；不得为原型直接安装完整模板依赖或不相容大型 UI 框架。

固定模拟数据必须覆盖短标题、接近 50 宽度单位标题、中文/英文/Emoji 标题、短简介、超过四行简介、接近 1000 宽度单位简介、多平台、多个加群方式、已/未点赞、已发布/已下架、空板块、成员较多板块和头像缺失/加载失败。

### R02-08 样例页面

样例必须包含以下页面或可独立审核的视图：

- 公开首页默认态：顶栏、主搜索、发现新群 Carousel、所有标签、至少两个自定义板块、空板块、所有群组 Grid、加载/空/错误状态。
- 搜索结果态：搜索词、搜索框位置稳定、结果 Grid、加载下一页、无结果和错误；只做本地模拟过滤。
- 群组详情 Dialog：桌面/手机、完整简介、多个加群方式、分享、点赞、二维码、长内容滚动、关闭和焦点视觉。
- 管理端群组管理：导航、搜索/筛选、表格、状态、排序、页码分页器、`共 X 条，第 Y / Z 页`、完整/中等/窄屏列、全屏抽屉。
- 管理端板块管理：至少三个板块，启用/未启用/空板块、拖拽手柄、排序模式、固定高度成员表格、内部滚动、已发布/已下架成员、编辑/上移/下移/移除、添加群组、删除确认。
- 设计系统展示页：颜色 Token、字体、间距、圆角、阴影、按钮/输入状态、标签、状态徽标、Toast、ErrorBanner、Skeleton 和空状态。

### R02-09 本地交互

样例至少实现三态主题、即时浅深色切换、顶栏响应式、搜索输入与本地结果、标签替换搜索词、卡片打开 Dialog、点赞不打开 Dialog、Dialog 开关、模拟复制反馈、Carousel 鼠标拖动、滚轮/触控板和触摸滚动、管理表格列变化、板块展开/视觉滚动、板块拖拽反馈、删除确认和 Toast。

这些交互只验证体验，不得宣称实现真实点赞、复制、分页、搜索、板块 CRUD、认证或 API 行为。

### R02-10 无障碍与质量要求

样例必须验证文字对比度、可见键盘焦点、图标按钮可访问名称、卡片键盘焦点、Dialog 焦点边界、非颜色状态表达、合理触摸目标、表头层级、深色焦点、`prefers-reduced-motion` 降级和高倍缩放下的主要内容可用。无法由自动工具证明的内容必须记录人工检查。

### R02-11 用户评审与确认

必须按四轮评审组织材料：

1. 方向确认：模板分析、设计关键词、颜色/排版、顶栏/搜索/卡片、浅色/深色初稿。
2. 核心公开端：完整首页、Carousel、Grid、标签、Dialog、手机响应式。
3. 管理端：群组列表、页码、响应式列、板块管理、固定高度表格、抽屉。
4. 最终确认：用户明确确认视觉方向、浅色、深色、卡片、Dialog、首页、管理列表、板块管理和手机响应式。

“未提出意见”不等于确认；确认后才可将 `ui-design.md` 标记为已确认、记录日期并解除依赖本任务的正式前端任务阻塞。
