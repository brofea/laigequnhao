## 2. 阶段 A：收集并审查视觉输入

### A-1 记录模板来源

- 保存模板名称、链接/本地来源、审查日期、主要页面、组件和状态。
- 区分主要模板、辅助参考和用户明确不希望采用的部分。
- 对页面、排版、组件和交互逐项记录：直接采用、调整后采用、仅参考、不采用。
- 不以截图或“风格相似”代替可追踪来源。

### A-2 完成授权审查

记录以下字段：模板许可证、商用、修改、代码复用、图片、图标、字体、署名、不可提交资产和替代方案。任何未确认项不得复制源码、专有插图、品牌资产、受限字体或整套独创页面。

### A-3 产品适配评审

把模板特征映射到 V2 已冻结结构：顶栏、搜索、发现新群、所有标签、自定义板块、所有群组、详情 Dialog、管理群组列表和板块管理。若模板页面结构与 V2 冲突，保留 V2 信息架构，只借鉴视觉关系和交互表达。

### A-4 阶段门禁

输出一份输入审查记录，必须回答：

- 视觉方向是否有真实用户来源？
- 模板资产能否合法使用？
- 哪些特征仍需用户决策？
- 是否存在 T01 识别的 C4/C5 阻塞？
- 原型能否在不碰正式路由/API/共享文件的情况下运行？

任意问题无法回答时，不进入 Token 冻结和样例开发。

## 3. 阶段 B：编写 `ui-design.md`

### B-1 元信息和设计目标

写入版本、状态、主要模板、最后确认日期和用户确认状态；明确希望传达的视觉感受、信息密度目标、公开端/管理端一致性和与 V2 PRD 的关系。

### B-2 模板分析和授权附录

保留采用/调整/放弃矩阵、许可证结论、资产替代方案和未确认风险。不得只写“参考模板风格”。

### B-3 Token 章节

按原始、语义、组件三层编写：

- 色阶、字号、间距、圆角、阴影、动画时长和缓动。
- 页面背景、surface 层级、overlay、文字层级、边框、品牌操作色和 success/warning/danger/info。
- 顶栏高度、搜索框高度、卡片圆角、Dialog 最大宽度、表格行高、Carousel 间距和按钮尺寸。
- 字体家族/回退、标题/正文/辅助/标签/按钮/表格/数字层级。
- 哪些规则是 MUST、SHOULD、MAY。

所有关键语义 Token 都要有浅色/深色值、用途、对比度注意事项；不把未经用户确认的候选值写成冻结值。

### B-4 主题、布局和响应式章节

完整描述 `system` / `light` / `dark`，并同时说明首屏主题注意事项、页面/卡片/文字/边框/阴影/交互/状态/Skeleton/遮罩/二维码的主题表现。

记录 360、390、768、1024、1280、1440 的验证目标；包括页面容器、顶栏压缩、Carousel 两卡露出、Grid 列数、管理列隐藏顺序、Dialog/抽屉和安全区。

### B-5 组件和状态章节

逐项覆盖顶栏、搜索、Section、GroupCard、GroupDialog、Carousel、标签聚合卡、按钮、表单、Toast/ErrorBanner/Skeleton、管理表格和板块容器。每项写尺寸、层级、内容、交互态、错误/加载/空态、响应式和无障碍要求。

### B-6 原型和后续实现章节

记录原型路径、命令、入口、固定数据位置、隔离方式、允许复用边界、未实现业务能力、已知视觉问题、评审反馈和修改记录；明确后续 T03/T06/T07/T08/T09/T10 必须遵守的 MUST 以及重新确认条件。

### B-7 文档门禁

- 从头到尾阅读 `ui-design.md`，检查所有原始 PRD 条件仍有归属。
- 检查没有“已确认”但没有用户记录的结论。
- 检查没有把原型实现描述成生产业务。
- 检查所有路径、命令、测试和截图位置真实存在或明确标记为待创建。

## 4. 阶段 C：建立隔离原型骨架

### C-1 选择入口

根据 T01 影响图从以下候选中选择一种并记录理由：独立原型目录、独立 Vite 入口、仅开发环境预览入口或已有组件预览环境。当前仓库没有 Storybook，不能默认引入。

必须通过生产暴露检查；如果入口方案无法证明生产隔离，改用更严格的独立目录/开发隔离方案并停止扩大范围。

### C-2 目录边界

建议将原型分为以下逻辑层，实际路径由 T01 确认：

```text
prototype/
  app/              # 仅样例入口和页面状态
  components/       # 样例专用视觉组件
  data/              # 固定 fixture，不含真实数据
  tokens/            # 候选 Token 展示和主题映射
  tests/             # 原型专用 Vitest/Playwright
  README.md          # 命令、入口、隔离说明
```

若审计要求复用正式 `src/` 位置，必须把复用限制在无业务的纯视觉 Token/基础样式，并在文件中标注候选状态；不得直接修改正式页面行为。

### C-3 入口安全验证

完成骨架后先验证：没有生产导航入口、不读正式 localStorage、不用管理员会话、不发真实业务请求、生产构建不会暴露可达入口、删除原型不会破坏正式应用。该门禁未通过，停止后续页面开发。

## 5. 阶段 D：固定模拟数据和视觉状态

### D-1 数据覆盖

建立可复现 fixture，覆盖：短标题、接近 50 宽度单位标题、中文/英文/Emoji、长英文单词；短简介、超过四行、接近 1000 宽度单位；多平台；多加群方式；已/未点赞；公开视图只含已发布群组，管理端群组表/板块成员表另含已下架状态；空板块、成员较多板块；头像缺失/失败；加载、空、错误和删除确认。

### D-2 本地状态

固定 `system/light/dark` 主题、搜索 idle/filtering/results/empty/error、Dialog closed/open、点赞 liked/unliked、分享 copied/failed、Carousel idle/dragging/settled、板块 collapsed/expanded/dragging、删除 idle/confirm/cancelled/confirmed 等状态。

不得使用真实 API、随机数据、当前时间、真实设备 ID、真实群组标题/联系方式或真实管理员数据。

### D-3 内容安全

二维码只使用占位/模拟内容；分享只复制安全的模拟链接或显示模拟反馈；样例中的“删除”“分页”“点赞”不产生真实副作用，并在 UI/文档中标记为样例行为。

## 6. 阶段 E：实现公开端样例

按以下顺序实现，先完成静态视觉，再接本地交互：

1. 顶栏：宽屏和窄屏操作、主题/GitHub 图标化、添加群文案、焦点。
2. 主搜索框和 Section：位置稳定、Loading/错误/空态。
3. 发现新群 Carousel：卡片露出、箭头、边缘提示、拖动、滚轮、触摸、键盘。
4. 标签聚合卡片：数量、选中和超多标签状态。
5. 自定义板块：至少两个启用板块和一个空/未启用板块。
6. 所有群组 Grid：手机双列、长内容、头像失败和点赞状态。
7. 搜索结果：本地过滤、下一页加载状态、无结果和错误。
8. GroupDialog：完整简介、多个加群方式、二维码、分享、点赞、长内容滚动、桌面/手机和焦点。
9. 设计系统展示页：集中展示所有 Token、组件和状态。

卡片必须只展示头像、标题、平台、最多四行简介、点赞按钮/数量；不得把加群按钮、群号、二维码或复制按钮塞回卡片。

## 7. 阶段 F：实现管理端样例

1. 管理端导航和板块/群组入口视觉。
2. 群组管理工具栏：搜索、筛选、排序和页码信息。
3. 完整桌面表格：表头、状态、排序、操作、分页、加载/空态。
4. 中等宽度按标签、性质、点赞、平台顺序隐藏。
5. 窄屏只保留标题、状态、操作，并提供全屏抽屉视觉。
6. 板块管理：至少三个板块，启用/未启用/空板块，拖拽手柄、排序模式、成员数。
7. 固定高度成员表格内部滚动；管理端可展示已发布/已下架成员，公开板块视图不得展示已下架成员。
8. 编辑、上移、下移、移除、添加群组、删除确认和 Toast 反馈均为本地状态。

不得把管理样例接入现有 `useAdminAuth`、`useAdminGroups`、`AdminGroupTable` 或真实 `AdminGroupDrawer` 的 API 生命周期，除非 T01 明确批准纯视觉复用且不会形成生产路径耦合。

## 8. 阶段 G：本地交互和无障碍

### G-1 交互清单

- 主题三态和浅/深色即时切换。
- 顶栏响应式变化。
- 搜索输入、本地过滤和标签替换搜索词。
- 卡片打开 Dialog；点赞按钮不打开 Dialog。
- Dialog 打开/关闭、关闭按钮、焦点边界和滚动锁定的视觉验证。
- 分享模拟复制和 Toast 反馈。
- Carousel 鼠标拖动、横向滚轮/触控板、触摸、键盘、边界。
- 管理表格列变化、分页器本地展示和抽屉全屏状态。
- 板块展开/滚动、拖拽视觉反馈、删除确认和 Toast。

### G-2 无障碍

按 role/label 设计交互，验证：文字对比度、图标按钮 accessible name、键盘 focus、卡片 focus、Dialog 焦点边界、状态不只靠颜色、触摸目标、表头语义、深色 focus、`prefers-reduced-motion` 和 200% 缩放。

无法自动证明的项目必须在评审记录中标明人工检查人、视口/主题、结果和遗留问题。

## 12. 风险停止条件

出现以下任一情况立即停止并回到规划：

1. 用户模板、许可证或主要视觉方向仍不明确。
2. T01 `impact-map.md` 未确认 Spec 目录或原型隔离边界。
3. 需要修改正式首页、管理端、API、migration、认证、状态机、R2 或生产路由才能继续。
4. 原型请求触发真实业务 API，或写入正式 localStorage/会话。
5. 需要安装完整模板依赖、大型 UI 框架或提交授权不明资产。
6. 深色/窄屏/键盘/对比度验证失败且无法通过隔离样例修复。
7. 用户反馈要求改变 V2 冻结的信息架构，而不是视觉表达。
8. 并行修改导致共享文件冲突；重新读取当前文件后仍无法安全应用时，向主任务报告并停止，不使用破坏性 Git 命令。
