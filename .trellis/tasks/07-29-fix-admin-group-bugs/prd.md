# 修复管理端群组管理与生命周期加固的 Bug

## 背景

commit `feat(admin): 完善管理端群组管理与生命周期加固` 引入大量管理端功能变更（70 个文件，+4017/-1060），人工测试中发现多个 Bug 和功能缺失。

## 需求

### A. Admin 主页

- **A1**：筛选按钮顺序改为 待审核 → 已发布 → 已下架 → 已拒绝 → 回收站
- **A2**：无排序列点击时，默认按状态排序（待审核 → 已发布 → 已下架 → 已拒绝），再按标题 ASC
- **A3**：列头排序改为三态循环：升序 → 降序 → 取消排序（回到默认），刷新不保留排序状态

### B. 群聊编辑/新建抽屉

- **B0**：平台与加群方式完全解绑。平台纯展示标签，从配置列表选择或自定义输入。配置平台名支持中文。自定义平台名不加入筛选下拉。
- **B1**：新增 Logo 头像编辑功能。抽屉顶部独立头像区（圆形图 + 编辑/删除按钮）。Logo 可选。
- **B2**：加群方式按钮始终显示 3 种类型（二维码/群号/URL），已存在的类型隐藏。不可重复。
- **B3**：二维码上传接受任意格式 ≤5MB，最长边缩放到 1024px，压缩为 ≤300KB 有损 webp。错误提示中文化。
- **B4**：编辑模式显示已有 Logo 和二维码图片。QR 加群方式存在时图片不能为空。Logo 可为空。
- **B5**：全局审计并替换面向用户的英文报错为中文。

### C. 关联修复

- **C1**：`restore()` 恢复群组时，重新激活 logo asset 的 ref_count
- **C2**：状态排序权重定义为单一常量，A1 和 A2 共用
- **C3**：管理端 API 返回 joinMethods 的 `assetUrl`（当前为 null）

## 验收标准

- [ ] A1：筛选按钮顺序符合要求
- [ ] A2：无排序时默认按状态→标题排列
- [ ] A3：列头三态循环正常，刷新重置
- [ ] B0：平台 selector 支持选择+自定义输入，加群方式不限制平台
- [ ] B1：抽屉顶部有头像编辑区，上传/替换/删除功能完整
- [ ] B2：加群方式按钮正确显示/隐藏已有类型
- [ ] B3：5MB 任意格式 → ≤300KB webp 压缩正常，alpha 通道保留，中文提示
- [ ] B4：编辑模式显示已有图片，QR 图片必填校验生效
- [ ] B5：无面向用户的英文报错
- [ ] C1：恢复群组时 logo asset ref_count 正确递增
- [ ] C2：状态排序权重只有一处定义
- [ ] C3：管理端 API 返回有效的 assetUrl
- [ ] typecheck 通过，现有测试全部通过
