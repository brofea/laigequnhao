# T06 系统加固与发布验收：技术设计规划

## 0. 设计原则

T06 使用“证据驱动的发布门禁”。每个结论都必须能够回到测试命令、固定环境、数据夹具、截图、日志、迁移输出或安全检查结果。没有证据的“看起来正常”不能作为通过。

T06 的修复策略是最小化和分层回派：后端问题回 T04，adapter/请求生命周期问题回 T05，表现差异进入冻结问题记录；T06 不承担重新设计。

## 1. 验收架构

```text
产品流程验收
      ├─ 公开端 E2E
      ├─ 管理端 E2E
      └─ 视觉/无障碍
服务正确性
      ├─ Domain/Vitest
      ├─ Workers/API
      └─ Contract/adapter
运行质量
      ├─ 性能
      ├─ 安全
      ├─ 迁移
      └─ 部署/回滚
              │
              ▼
       acceptance.md + 发布结论
```

## 2. 环境固定

每次验收记录：

- Git commit/工作区状态。
- Node 和 pnpm 版本。
- 浏览器及版本。
- OS 和系统主题。
- viewport 和 device scale factor。
- 数据库 schema 版本。
- seed 数据版本。
- 站点配置时区。
- 固定日期和小时槽位。
- R2 测试 bucket。
- 环境变量来源。
- 运行命令和开始结束时间。

不固定这些条件时，小时随机、时间字段、主题和视觉截图可能产生假失败。

## 3. 测试数据设计

准备最小可审计数据集：

- published 群组。
- unpublished 群组。
- trash 群组。
- 被删除群组。
- 没有标签群组。
- 多标签群组。
- 长标题和长简介。
- Emoji/全角文本。
- 多种加群方式。
- 发现新群时间相同的群组。
- 空板块。
- 启用板块。
- 关闭板块。
- 多板块成员。
- 手动正序、倒序和小时随机板块。
- 刚好 50、51、100、101 条管理记录。
- 多管理员版本冲突数据。
- 上传成功、失败、替换和删除资源。

测试数据必须可重置，不使用生产数据直接做不可逆演练。

## 4. 自动化质量门禁

### 4.1 Unit 门禁

先运行 domain、Contract、adapter 和错误处理测试。Unit 失败时不继续用 E2E 结果掩盖基础错误。

### 4.2 Workers 门禁

验证真实 D1、migration、权限、事务、公开过滤、排序、分页、关联清理和 R2 兼容。测试必须覆盖成功和失败事务路径。

### 4.3 E2E 门禁

E2E 使用隔离测试数据库和可控 session。每个流程记录前置数据、操作步骤、期望状态、截图和日志。失败测试保留 trace/video，不删除断言。

## 5. 视觉回归设计

prototype v2 和正式项目使用相同 viewport、字体、主题、数据和固定时间生成基线。视觉比较按以下层级执行：

1. 页面区域顺序。
2. 组件尺寸和位置。
3. 颜色和主题映射。
4. 字体、行高和折行。
5. 间距、圆角、阴影。
6. Dialog/Drawer 尺寸与焦点遮罩。
7. 手机至少两张 Carousel 卡片和无横向滚动。

真实 API 数据与 prototype fixture 内容不同造成的文本差异，要区分数据差异和视觉实现差异；不能直接更新基线掩盖产品问题。

## 6. 无障碍设计

使用键盘流程和辅助技术可识别的检查组合。重点验证：

- 主题、GitHub、添加按钮名称。
- 卡片主体和点赞独立聚焦。
- Dialog 打开、锁焦、Escape、关闭后恢复。
- Carousel 左右键和拖动不误开卡片。
- 表格表头/隐藏列和操作名称。
- Toast、Error、Loading 和空状态可感知。
- reduced motion。
- 对比度。
- 触摸尺寸。

不通过添加视觉装饰或改变布局修复自动化检查；缺少语义时记录并回派 T03/用户决策。

## 7. 性能设计

### 7.1 查询

用固定数据量和逐步放大数据量检查：

- 发现新群是否限制 10。
- 标签是否单次聚合。
- 板块是否批量读取。
- 公开目录/搜索是否 cursor。
- 管理列表是否只返回 50。
- 总数查询是否可接受。
- 稳定随机是否不产生写操作。

### 7.2 客户端

- 首屏请求数量和重复率。
- 搜索 debounce 和取消。
- 无限滚动 cursor 去重。
- 图片懒加载。
- 主题首屏闪烁。
- 大板块 DOM 高度。
- 生产 bundle 是否含 fixture。

### 7.3 门禁证据

记录请求数量、响应时间、数据库查询形状、页面关键时间、bundle 检查结果和阈值。阈值若总 PRD未指定，必须记录采用的基线及原因，不伪造产品硬指标。

## 8. 安全设计

### 8.1 权限矩阵

| 操作 | 匿名 | 普通公开访问 | 管理员会话 | 无效会话 |
| --- | --- | --- | --- | --- |
| 读 published | 允许 | 允许 | 允许 | 允许 |
| 读 unpublished | 禁止 | 禁止 | 按管理接口允许 | 禁止 |
| 写提交 | 按现有匿名规则 | 按现有规则 | 允许 | 禁止 |
| 板块管理 | 禁止 | 禁止 | 允许 | 禁止 |
| 群组管理 | 禁止 | 禁止 | 允许 | 禁止 |
| 上传 | 禁止 | 禁止 | 按现有规则 | 禁止 |
| 永久删除 | 禁止 | 禁止 | 按现有强确认规则 | 禁止 |

实际权限以 T01/T04 既有规则为准；矩阵用于发现遗漏，不授权新增能力。

### 8.2 攻击面

- 未认证管理写入。
- CSRF 缺失或 token 重放。
- 越权 group id。
- 深链状态泄露。
- 标签/搜索泄露 unpublished。
- 位置参数越界。
- 重复成员竞态。
- 上传类型绕过。
- R2 key 泄露。
- 错误栈泄露。
- 速率限制回归。

## 9. Migration 演练设计

### 9.1 演练一：空库

从空库执行完整 migration，验证所有表、字段、索引、外键、默认板块和初始数据。

### 9.2 演练二：现有库

使用脱敏且可重置的现有结构，验证旧群组保留、发布时间 NULL、旧能力可读、默认板块不重复。

### 9.3 演练三：重复和中断

重复执行 migration；在可控步骤模拟中断后重新执行，验证幂等与恢复。

### 9.4 演练四：失败回滚

记录失败点、错误、影响范围、恢复命令、数据验证和重新发布条件。不能以删除数据库代替回滚验证。

## 10. 部署设计

部署前：

- 锁定构建 commit。
- 检查环境变量。
- 备份/快照可用。
- 迁移版本正确。
- 运行健康检查。
- 确认 R2/Analytics 绑定。
- 确认 session/CSRF 配置。

部署中：

- 按 runbook 顺序执行 migration 与代码发布。
- 观察错误率、响应时间和健康接口。
- 检查公开过滤和管理登录。
- 记录每步输出。

部署后：

- 跑 smoke flows。
- 检查主题和关键页面截图。
- 检查提交/点赞/上传/删除。
- 检查回滚信号。

## 11. 回滚设计

回滚必须区分代码回滚和数据回滚。新增 nullable 字段/表能否被旧代码忽略要有证据；已写入板块数据的 migration 不得凭想当然删除。若不可逆，发布前必须有备份和 forward-fix 方案，并在报告中明确。

## 12. 缺陷分类和回派

| 缺陷 | 回派 | T06 行动 |
| --- | --- | --- |
| Schema/API/事务 | T04 | 记录阻塞、复测 |
| client/adapter/竞态 | T05 | 记录阻塞、复测 |
| Vue/CSS/布局/交互 | T03/用户 | 只记录，不改 |
| 测试工具/环境 | T06 | 修复测试基础设施 |
| 部署/文档/监控 | T06 | 在本任务修复 |

## 13. Acceptance report 设计

`acceptance.md` 每项至少包含：编号、来源章节、场景、前置数据、命令/操作、环境、期望、实际、证据、状态、阻塞级别、责任任务和复测结果。

状态限定为：`passed`、`failed`、`blocked`、`waived`。`waived` 必须有用户或负责人批准、原因、风险、替代措施和有效期；不能把未执行写成 passed。

## 14. 发布准入

准入条件：

- 所有 P0/P1 缺陷关闭。
- 公开数据边界通过。
- 管理权限和 CSRF 通过。
- migration 演练通过。
- T05 无生产 Mock。
- 关键 E2E 通过。
- 视觉冻结差异已批准或关闭。
- 性能和安全无阻塞问题。
- 部署与回滚可执行。
- 文档完整。

## 15. 设计完成定义

- [ ] 所有门禁有数据、命令和证据格式。
- [ ] 视觉冻结在测试策略中被明确保护。
- [ ] 缺陷回派责任明确。
- [ ] 迁移/部署/回滚可演练。
- [ ] acceptance.md 字段明确。
- [ ] 没有用“最终优化”作为未授权前端改动入口。
