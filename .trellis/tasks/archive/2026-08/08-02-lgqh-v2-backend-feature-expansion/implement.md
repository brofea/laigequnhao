## 3. 阶段二：共享规则先行

实施顺序：

1. 明确 `ThemePreference`、`BoardSortMode` 和板块 DTO。
2. 明确公开 DTO、管理 DTO 和错误 DTO。
3. 明确显示宽度函数和边界。
4. 明确分页和排序参数。
5. 为 schema 写单元测试。
6. 记录会影响 T05 adapter 的字段。

共享 Contract 的每次变更都要同步接口示例和 T05 移交记录。不能先写 route 再临时拼 DTO。

## 4. 阶段三：数据库 migration

### 4.1 编写前

- [ ] 确认最新 migration 编号。
- [ ] 确认 D1 外键和级联实际行为。
- [ ] 确认测试数据库重建方式。
- [ ] 确认 nullable 字段向后兼容。
- [ ] 确认默认板块幂等键。
- [ ] 确认位置索引和查询计划。

### 4.2 执行顺序

1. 增加 `last_published_at`。
2. 增加板块表。
3. 增加成员表。
4. 增加索引、主键、外键和级联。
5. 幂等创建“自定板块”。
6. 检查已有群组字段均为 NULL。
7. 在空库、已有库、重复运行中验证。

不得用旧时间字段回填发布时间；不得在 migration 中静默改变现有状态或删除已有业务数据。

## 12. 失败处理

- 迁移失败：停止 API 实现，保留失败证据，先修迁移。
- Contract 不稳定：停止 T05 移交，统一版本。
- 公开过滤失败：阻止发布，添加回归测试。
- 权限失败：阻止所有管理写路由验收。
- 事务失败：检查 D1 实际行为，不以重试掩盖部分更新。
- 性能失败：记录 query plan 和数据量，不提前放宽要求。
- 与前端表现冲突：记录问题，不修改表现。
