# Bootstrap PRD：来个群号

## 项目目标

从零建立“来个群号”网站及首版开发规范。每个部署实例只服务一所高校或一家大型企业，帮助该机构成员发现、搜索并加入官方群或同好群，同时为管理员提供审核、维护、图片管理和基础运营数据能力。

同一套代码必须能被不同机构独立复用。产品以低运维成本为前提：GitHub 托管代码，Cloudflare Pages 部署静态前端，Pages Functions 提供轻量 API，D1 保存关系数据，R2 保存图片，不部署常驻后端。

## 用户价值

- 访客可以快速发现、复制或打开合适的加群方式。
- 访客可以点赞并提交尚未收录的群聊。
- 管理员可以审核、发布、下架、删除和恢复群聊，并查看业务、访问和运行指标。
- 部署方可以通过一个类型安全配置文件和 Cloudflare 环境配置复用项目，不需要散改业务组件。

## 已确认的技术基线

- Vue 3、Vite、严格模式 TypeScript、Composition API、Vue Router
- Tailwind CSS + CSS Variables
- Vue composables；MVP 不引入 Pinia或完整 UI 组件库
- Cloudflare Pages Functions + Hono，仅处理 `/api/*`
- Zod 共享 API 契约
- D1 prepared statements + SQL migrations；MVP 不引入 ORM
- R2 保存最终 WebP
- Cloudflare Turnstile保护公开提交
- Vitest、Vue Test Utils、Cloudflare Workers Vitest integration、Playwright
- pnpm、ESLint、Prettier、`vue-tsc`

当前仓库没有产品源代码，因此本次 Specs 是首版实现契约；首轮实现完成后必须补充真实源码与测试路径作为范例。

## MVP 需求

### 公开首页

- `REQ-HOME-01`：以卡片和游标分页展示群聊。
- `REQ-HOME-02`：卡片展示 Logo、标题、平台、官方群/同好群性质、标签、状态、点赞，以及该群聊实际具有的加群按钮。
- `REQ-HOME-03`：同一浏览器对同一群聊最多保持一个有效点赞，再次点击取消。
- `REQ-HOME-04`：复制群号成功或失败时均提供可感知反馈。
- `REQ-HOME-05`：一个关键词输入框同时搜索标题和标签。
- `REQ-HOME-06`：点击“提交新的群聊”打开纯文本提交弹窗。

搜索忽略首尾空白，对拉丁字符不区分大小写，对中文、标题和标签做子串匹配。MVP 不提供其他筛选器；结果保持当前滚动窗口的相对顺序。

### 群聊模型与可见性

- 群聊使用稳定唯一 ID，不以标题或群号作为主键。
- 群聊性质是必填且互斥的 `official`（官方群）或 `interest`（同好群）；标签仅描述游戏、摄影、编程等主题。
- 平台必须来自 `site.config.ts`；平台以部署方提供的统一风格 SVG 展示。
- 群聊至少具有一种加群方式，并可同时具有多种：
  - `group_number`：复制文本群号。
  - `url`：安全跳转到 HTTPS 加入链接。
  - `qr_code`：展示 R2 中的二维码 WebP；卡片按钮在二维码阶段启用。
- 业务状态只有四种：
  - `pending`：待审核，仅管理员可见。
  - `published`：已发布，普通用户和管理员可见。
  - `rejected`：已拒绝，仅管理员可见。
  - `delisted`：已下架，普通用户和管理员可见，公开卡片明确标注。
- 管理员可以在四种状态间任意调整，不设置单向状态机。

### 访客提交

- 必填：标题、群聊性质、已配置平台、至少一种文本加群方式（群号或 HTTPS URL）。
- 可选：1–5 个标签、简介、补充说明、提交者联系方式。
- 联系方式和补充审核信息仅管理员可见，不进入公开 API。
- 普通访客不能上传任何文件；multipart 或文件字段必须拒绝。
- 所有文本执行长度、格式、控制字符和 URL 协议校验。
- 有效提交以 `pending` 状态写入 D1。
- 公开提交必须同时通过 Turnstile 与服务端频率限制。

### 点赞

- 浏览器本地保存匿名设备 ID 和已点赞群聊 ID，只用于恢复当前浏览器状态。
- 点赞/取消同步到 D1；D1 保存匿名去重记录和全站汇总。
- 服务端使用带 Secret pepper 的设备标识哈希、唯一约束和频率限制提高刷票成本，不长期保存原始 IP。
- 无账号场景不承诺严格的一人一票。
- 点赞数不参与首页排序。

### 卡片排序

- 首页采用确定性的循环轮换，不按点赞数或每次访问随机洗牌。
- 时区为可配置的 IANA 时区，默认 `Asia/Shanghai`。
- 默认每天北京时间 `04:01` 与 `16:01` 进入下一轮换窗口；时间点可在 `site.config.ts` 修改。
- 同一窗口内所有访客看到相同基础顺序；算法根据当前时间计算，不依赖定时进程。
- 搜索只过滤当前轮换序列，清空后恢复该窗口完整顺序。

### 管理功能

- `REQ-ADMIN-01`：未认证用户不能读取管理数据或执行管理操作。
- `REQ-ADMIN-02`：管理员可以查看全部状态、访客提交和回收站。
- `REQ-ADMIN-03`：管理员可以新建群聊。
- `REQ-ADMIN-04`：管理员可以编辑内容、加群方式和业务状态。
- `REQ-ADMIN-05`：管理员可以查看运行、访问、性能、业务和点赞指标。
- `REQ-ADMIN-06`：管理员可以在四种业务状态间调整群聊。
- `REQ-ADMIN-07`：管理员可以软删除、恢复或永久删除群聊。

MVP 只有一个共享管理员密码，不建立账号、角色或找回密码流程。密码保存在 Cloudflare Secret；认证成功后签发有期限的 `HttpOnly`、`Secure`、`SameSite=Lax` Cookie。会话签名、过期、退出、同源/CSRF 和服务端登录失败限流必须生效。默认会话 8 小时、默认登录限制为 15 分钟 5 次，均仅通过服务端配置调整。

软删除使用独立删除标记，不增加第五种业务状态。软删除后记录只在回收站可见；恢复时清除删除标记并保留删除前状态。永久删除需二次确认，并清理关联加群方式、点赞和无其他引用的 R2 图片；D1/R2 部分失败必须保留可重试状态。

### 图片管理

- 只有已认证管理员可以上传和配置 Logo/二维码。
- 管理员浏览器本地接受 WebP、PNG、JPG/JPEG：
  - JPG 转为有损 WebP。
  - PNG 转为保留透明通道的有损 WebP。
  - WebP 可直接使用或重新压缩；支持有损、无损和透明 WebP。
- 原始输入不离开浏览器；只上传最终 WebP。
- 压缩工具展示预览、尺寸和体积；透明背景不得被强制填充。
- Logo 最终硬上限为 100 KB，二维码最终硬上限为 300 KB；前端阻止超限，服务端再次验证 WebP 签名、元数据、用途和实际体积。
- R2 key 由系统生成；D1 只保存对象 key、用途、尺寸、体积和内容类型，不保存图片二进制。
- 生产图片通过 R2 自定义域名和不可变缓存提供，不把 `r2.dev` 写入业务数据。

### 运行状态与分析

- 管理页真实检查 API、D1、R2，并展示应用版本和部署时间。
- 访问与前端性能只读取 Cloudflare Web Analytics，不在 D1 重复记录页面访问。
- 服务端使用 Cloudflare Secret 中的只读 Analytics Token 查询最近 24 小时、7 天和 30 天的浏览量、独立访客、趋势和可用的 Core Web Vitals。
- D1 汇总四种状态数量、待审核数、新增提交趋势、总点赞、近期增减和各群聊点赞。
- API、D1、R2、Analytics 面板独立失败；单个依赖不可用不能隐藏其他有效数据。

### 复用、部署与规模

- 所有公开机构差异集中在受 TypeScript 校验的 `site.config.ts`：
  - 机构名称/简称、站点标题/介绍、Logo、favicon、联系信息、页脚。
  - 主题主色/强调色、默认明暗模式。
  - 排名时区/时间点。
  - 平台名称/SVG/允许的加群方式。
  - 阶段功能开关。
- MVP 不允许在线修改站点配置；修改配置后重新构建部署。
- D1/R2 bindings 位于 Wrangler 配置；密码、会话密钥、点赞 pepper、Turnstile 与 Analytics Token 使用 Secrets。
- `main` 部署生产；预览部署使用独立预览 D1/R2，本地默认只使用本地 Wrangler 数据。
- 首发预计 100–300 个群聊；架构与测试覆盖 1,000 个已发布群聊、约 10,000 日访问、每日不超过 50 次内容变更。
- MVP 不引入独立搜索服务；持续超过 1,000 个群聊或每日数万访问时重新评估索引、缓存、分页与 Functions 配额。

## 后续阶段顺序

基本功能完成后按顺序实施，除非需求重新确认，不并行扩大范围：

1. 完善手机和桌面响应式体验。
2. 在不显著牺牲性能的前提下优化 UI/UX。
3. 添加跟随系统与手动切换的深色模式。
4. 针对数百张 Logo 和大列表进行专项性能优化。
5. 启用卡片二维码按钮：桌面端扫码，移动端查看或保存。

## 验收标准

### 公开功能与提交

- `AC-01`：首页从持久化数据展示卡片，包含 Logo、标题、平台、性质、标签、点赞和实际可用的加群操作。
- `AC-02`：标题/标签搜索符合规范；清空后恢复当前轮换窗口完整序列。
- `AC-03`：复制群号成功与失败均有可感知反馈。
- `AC-04`：首次操作创建一个点赞，再次操作取消；刷新后本地状态与 D1 汇总一致。
- `AC-05`：有效纯文本提交进入管理员待审核列表；无效输入不写 D1/R2。
- `AC-13`：普通用户不能看到待审核或已拒绝记录。
- `AC-14`：已发布和已下架记录公开可见，已下架具有明确标识。
- `AC-17`：同一卡片只显示已配置加群方式对应按钮，行为与类型一致。
- `AC-18`：平台 SVG 在浅色和深色主题均清晰可辨。
- `AC-19`：本地点赞状态在同一浏览器刷新后恢复。
- `AC-21`：绕过按钮重复请求时，服务端仍执行去重与频率限制。
- `AC-22`：不同浏览器的有效点赞在 D1 汇总，服务端计数为权威值。
- `AC-28`：访客提交包含文件字段时拒绝，R2 不产生对象。
- `AC-44`：新建、提交和编辑必须使用 `official` 或 `interest`。
- `AC-45`：性质徽章与主题标签分别展示。
- `AC-46`：缺少必填、未知平台/性质或不安全 URL 时服务端拒绝写入。
- `AC-47`：公开 API 不返回联系方式或审核私有字段。
- `AC-48`：超过 5 个标签、包含文件或触发反滥用时返回稳定错误且不写入。

### 排序、规模与配置

- `AC-20`：点赞数不影响排序；默认北京时间 `04:01`、`16:01` 进入下一确定性循环窗口。
- `AC-23`：同一窗口重复访问得到相同基础顺序。
- `AC-24`：修改配置时间点后无需修改排序业务代码。
- `AC-12`：更换 `site.config.ts` 和部署 Secrets/bindings 即可复用实例，不修改页面业务代码。
- `AC-37`：1,000 个已发布群聊时仍可分页、轮换和搜索，且不急切加载全部 Logo。
- `AC-38`：目标规模下不需要独立搜索服务或常驻后端。
- `AC-39`：缺失配置、未知平台或无效时间导致类型检查/构建失败并可定位。
- `AC-40`：管理员页面不存在在线修改机构配置的入口。

### 管理功能与安全

- `AC-06`：未认证用户无法读取管理数据或执行管理写操作。
- `AC-07`：认证管理员可查看提交、新建、编辑和持久化群聊变更。
- `AC-15`：管理员可以查看四种状态并调整为任一状态。
- `AC-16`：软删除后普通用户不能读取该记录。
- `AC-25`：仓库和构建产物不含管理员密码；缺少 Secret 时安全失败。
- `AC-26`：Cookie 过期、篡改或退出后管理 API 返回未认证。
- `AC-27`：连续错误密码触发服务端限流且不泄露认证细节。
- `AC-41`：软删除只进入回收站；恢复后回到原业务状态及可见规则。
- `AC-42`：永久删除需二次确认，成功后关联数据与无引用图片不可恢复。
- `AC-43`：D1/R2 清理部分失败时保留可重试状态，不误报成功。

### 图片、API 与运行状态

- `AC-08`：管理页展示来源真实的运行、访问、性能、业务和点赞指标，失败时明确不可用。
- `AC-09`：API 使用统一可机器识别的成功/错误结构，不暴露堆栈、SQL 或 Secrets。
- `AC-10`：本地使用隔离 D1/R2 测试，并可经 GitHub 部署 Pages。
- `AC-11`：后续阶段有独立完成标准，不提前阻塞 MVP。
- `AC-29`：浏览器将 JPG 转有损 WebP，将 PNG 转保留透明通道的有损 WebP，并预览尺寸/体积。
- `AC-30`：D1 不保存图片二进制。
- `AC-31`：有效有损、无损和透明 WebP 均可处理和正确展示。
- `AC-32`：Logo >100 KB 或二维码 >300 KB 时前端与服务端均拒绝，R2 不写入。
- `AC-33`：服务器/R2 只接收最终 WebP，原始输入不离开管理员浏览器。
- `AC-34`：管理页显示 Cloudflare Web Analytics 的 24 小时、7 天、30 天指标，Token 不暴露给浏览器。
- `AC-35`：首页不会为自建访问统计写 D1，管理页可区分业务与访问来源。
- `AC-36`：任一外部数据源失败只影响自己的面板。

## MVP 范围外

- 多机构多租户、用户账号、个人资料、社交关系或私信。
- 站内实时聊天或原生移动应用。
- 多管理员身份、角色、找回密码和个人操作归因。
- 在线修改机构配置。
- 复杂推荐、全文搜索集群、独立分析平台或常驻后端服务器。
- 已排序为后续阶段的完整响应式、视觉精修、深色模式、性能专项和二维码公开交互。

## 风险与延期事项

- 匿名设备可被清理或更换，防刷只能提高成本，不能保证一人一票。
- 共享管理员密码无法区分操作者，必须依靠 Secrets、会话安全和限流降低风险。
- R2 与 D1 无跨资源事务，图片替换和永久删除必须使用可重试操作状态。
- Cloudflare Web Analytics 的采样、保留和字段受账户计划与当前产品能力约束。
- 公开配置、Wrangler bindings 与 Secrets 边界不清会导致复用部署错误或秘密泄漏。
- 浏览器图像处理受设备内存与编码能力影响，服务端必须继续验证最终文件。
