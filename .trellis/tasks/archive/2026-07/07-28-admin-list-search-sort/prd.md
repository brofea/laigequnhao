# 统一搜索并完善管理员列表

## 父任务

`.trellis/tasks/07-28-improve-admin-page`

## 目标

让管理员通过可组合状态、回收站、标题/简介/标签搜索和六个数据列排序准确定位完整结果；同时让主页与管理端使用相同搜索字段和匹配语义。

## 范围

- 五个状态按钮：四业务状态至少一个、回收站互斥并恢复先前组合。
- 管理端搜索框位于筛选和表格之间。
- 主页与管理端只搜索标题、简介、标签，采用 trim、拉丁不区分大小写、中文子串匹配。
- 输入约 300ms 防抖，回车/清空立即执行，取消或忽略过期响应。
- 管理表格增加标签列。
- 标题、性质、状态、平台、标签、点赞六列对完整结果集做服务端升降序排序；操作列不排序。
- 完整结果可遍历，URL 可恢复筛选、搜索和排序。
- 变更后保留滚动位置，不恢复无条件全量刷新跳顶。

## 不在范围

- 群组编辑抽屉和聚合写入。
- 二维码上传、资源清理和公开二维码交互。
- 拼音、同义词、错字容忍、FTS 或外部搜索。

## 依赖与约束

- 使用共享 Zod query schema和固定 SQL 排序映射。
- 公开可见性和轮换排序保持不变；搜索只过滤公开基础序列。
- 管理员响应继续保持私有字段隔离和 `no-store`。
- 不直接修改父任务或其他子任务正在负责的写入/asset 契约。

## 验收标准

- [ ] 初始四状态全选，最后一个状态不能关闭，回收站进入/退出恢复正确。
- [ ] 主页和管理端同一关键词都匹配标题、简介、标签，且各自可见性规则正确。
- [ ] 防抖、回车、清空和请求乱序行为可通过测试证明。
- [ ] 状态、搜索、排序写入 URL，刷新和前进/后退可恢复。
- [ ] 标签列正确展示 0–5 个标签。
- [ ] 六个数据列均有可访问的升降序排序，操作列没有排序控件。
- [ ] 排序覆盖完整命中集，跨页无重复、遗漏和仅当前页有序。
- [ ] 管理员能访问首 50 条之后的记录。
- [ ] 编辑/删除/恢复后不发生滚动跳顶回归。
- [ ] 子任务要求的单元、Worker、Vue 和 E2E 测试通过。
