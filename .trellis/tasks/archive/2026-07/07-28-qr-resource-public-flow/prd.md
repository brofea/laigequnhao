# 完成二维码资源与公开交互闭环

## 父任务

`.trellis/tasks/07-28-improve-admin-page`

## 目标

让二维码成为与群号、URL 等价的正式加群方式，完成从 WebP 上传、D1 引用、抽屉编辑、主页查看到安全清理和失败重试的资源闭环。

## 范围

- 新增有序 migration，补齐 `assets` 表、`join_methods.asset_id`、索引和可重试清理字段。
- 不修改已应用的 `0001_initial.sql`，覆盖从已有 0001 schema 升级。
- 二维码 JPG/PNG/WebP 在浏览器转为 WebP，服务端再次验证签名、尺寸和 300 KB 上限。
- 上传创建 staged asset；聚合保存后成为 ready 引用。
- 管理端二维码支持新增、预览、替换和删除。
- 无引用 asset 安全清理；R2/D1 部分失败保留状态并可重试。
- 永久删除只作用于软删除群组，按可重试状态清理 Logo、二维码和关联数据。
- 删除 `qrCodePublic` 配置、schema、分支、文档和测试；二维码始终公开。
- 公开 DTO 不泄漏 asset ID/R2 key；主页二维码按钮打开可访问对话框。

## 不在范围

- 站点配置在线编辑。
- 图片 CDN 方案或外部媒体服务。
- 除二维码查看外的主页视觉改版。
- 群组基本字段、标签和文本加群方式抽屉实现。

## 依赖与约束

- 先稳定 migration、asset DTO 和服务命令，再由聚合编辑子任务消费。
- 不从任意公开 URL 猜测 R2 key。
- 删除前必须检查引用；对象已不存在按幂等成功处理。
- 公开响应只返回可展示 URL/元数据。

## 验收标准

- [ ] 空数据库和已有 0001 数据都能安全应用新 migration。
- [ ] 当前路由依赖的 `assets` 表真实存在，QR 使用可靠 asset 引用。
- [ ] 上传拒绝非 WebP 结果、无效签名/尺寸和超过 300 KB 的文件。
- [ ] staged asset 只有在群组保存成功后转为正式引用。
- [ ] 取消、保存失败和替换不会误删仍引用的资源。
- [ ] 无引用 QR 可删除；R2/D1 任一失败均保留可重试状态。
- [ ] 永久删除不是回收站记录时拒绝，重复调用可从当前进度继续。
- [ ] `qrCodePublic` 从配置、代码、测试和文档中完全移除。
- [ ] 主页可打开/关闭二维码对话框，键盘和焦点行为正确。
- [ ] 公开 DTO 不包含 asset ID、R2 key、联系方式或审核备注。
