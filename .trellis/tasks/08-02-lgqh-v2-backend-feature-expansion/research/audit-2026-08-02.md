## 2. Review 发现（按角色）

### 产品经理
- P0：公开列表仍返回 delisted，必须收紧。
- 接口形态为 design.md 缺口（RPD §26.2），已与用户确认采用分区独立接口。
- 标签排序：RPD §14.4 默认建议 `count DESC, tag ASC`，旧子任务 PRD 已删，唯一依据即总 PRD 默认建议。
- 管理列表参数：沿用现有 `sortBy/sortDir`，不采用 RPD §21.3 示例参数名（api-guidelines 要求 `/api/v1` 稳定）。
- `DemoBoard.description` 无后端字段，记录为已知差异，T05 忽略。

### Staff Engineer
- 公开过滤收紧 + 负向测试。
- 管理分页 cursor → page/50/totalItems/totalPages，稳定次排序 `id`。
- 事务复用 mutation token 模式；`board_groups` 主键 `(board_id, group_id)` 防重。
- 时区：site.config 显式新增 `boards.timezone`（默认 `Asia/Shanghai`）。
- D1 外键：验证 `PRAGMA foreign_keys` 与级联实际行为。
- N+1：板块成员批量查询、标签单次聚合。

### QA
- Migration 测试：空库、旧 schema 升级、重复运行、中断重试、默认板块幂等、`last_published_at` 全 NULL。
- 负向：delisted/trash/deleted 不得出现在列表、搜索、板块、详情深链。
- 边界：50/51、totalPages 零条目、NULL 时间排序位置、小时槽位换界（固定时间 + IANA 时区）。
- 并发：双管理员编辑 → VERSION_CONFLICT；成员交换失败不留重复位置。

## 3. 已确认决策（用户批准）

1. **公开首页采用分区独立接口**（用户确认）：`/discover`、`/tags`、`/boards`、`/groups`、`/groups/:id`，不提供聚合首页接口。

## 4. 采用默认/推荐且记录的决策（无需用户确认）

| 决策 | 依据 |
|---|---|
| 标签排序 `count DESC, tag ASC` | RPD §14.4 默认建议 |
| 管理列表参数沿用 `sortBy/sortDir` | api-guidelines 稳定性要求 |
| `boards.timezone` 显式配置，默认 `Asia/Shanghai` | RPD §16.4 站点配置时区 |
| 公开 DTO 不暴露 `last_published_at` | RPD §13 无展示需求，发现接口内部排序 |
| 公开详情不可用统一 `404 NOT_FOUND` 非敏感 | error-handling 规范 |
| 重复成员 → `STATE_CONFLICT` | error-handling 领域不变量 |
| 板块添加群组选择器复用管理列表接口（statuses=published,delisted + q） | RPD §23.5，排除 trash |
| 管理写操作错误顺序：认证 → CSRF → schema → 版本/突变令牌 → 业务 → 事务 | RPD §26.4 + database-guidelines |
