# 04 后端能力扩展

## 0. 任务信息

| 项目 | 内容 |
| --- | --- |
| 任务编号 | T04 |
| Trellis 目录 | `08-02-lgqh-v2-backend-feature-expansion` |
| 任务名称 | 后端能力扩展 |
| 状态 | planning |
| 权威来源 | `docs/PRD/v2/RPD.md` |

| 后续任务 | T05 全栈业务适配 |

本任务是新任务体系的第一个实施任务。旧的“Schema 与发布字段”“板块后端”等任务已废弃，不得拆回旧任务边界；本任务统一承担后续真实业务所需的后端能力。

## 1. 任务目标

根据总 PRD 为已冻结的正式前端提供完整、稳定、可验证的服务端能力，覆盖数据库、共享 Contract、API、业务逻辑、权限、校验、文件存储兼容和管理端接口。

T04 的结果必须让 T05 可以在不改变 Vue 表现、CSS、布局、Dialog 或交互流程的前提下完成真实数据适配。所有接口都必须有明确的请求、响应、错误、权限和迁移语义。

## 2. 产品范围

### 2.1 发现与公开查询

- 支持 `last_published_at` 和“发现新群”查询。
- 只返回已发布群组。
- 发现新群按 `last_published_at DESC, id DESC` 稳定排序，最多 10 条。
- 标签统计只统计已发布群组，使用一次聚合查询，不产生逐标签 N+1。
- 启用板块及其已发布成员可被公开查询。
- 所有群组和搜索结果继续使用 cursor pagination。
- 已发布群组详情支持 `group` 深链接所需的公开查询。
- 详情、板块、搜索和目录均不得泄露下架、回收站或永久删除数据。

### 2.2 发布状态时间

服务端维护 `last_published_at`：

- 新建后直接发布时写入服务端时间。
- 草稿或待审核转为 published 时写入服务端时间。
- 下架后重新发布时写入服务端时间。
- 从回收站恢复并再次发布时写入服务端时间。
- published → published 的编辑不更新时间。
- 其他字段编辑不改变发布时间语义。
- 现有数据迁移后该字段必须保持 NULL，不用 created/updated 时间推断。

### 2.3 板块数据能力

新增并维护：

```text
boards
- id
- title
- is_enabled
- position
- sort_mode
- version
- created_at
- updated_at
```

```text
board_groups
- board_id
- group_id
- position
- created_at
```

必须满足：

- `board_groups` 使用 `(board_id, group_id)` 主键。
- 板块删除级联清理成员关联。
- 群组永久删除清理成员关联。
- 回收站动作原子删除全部板块关联。
- 板块和成员位置有查询索引。
- 同一板块不得重复加入同一群组。
- 不为成员数量设置硬上限。
- 默认“自定板块”可编辑、可关闭、可删除。
- 默认板块创建幂等，重复迁移不重复插入。

### 2.4 板块服务规则

管理 API 至少支持：

- 板块列表。
- 创建、编辑、启用、关闭、删除。
- 板块间位置批量更新。
- 修改 `manual_asc`、`manual_desc`、`hourly_random`。
- 添加已发布或已下架群组。
- 拒绝添加回收站群组。
- 防止同板块重复成员。
- 移除成员关联，不删除群组。
- 成员上移和下移。
- 版本冲突和失败回滚所需的响应语义。

公开 API 必须：

- 只返回启用板块。
- 保留板块配置和成员关联的服务端事实。
- 只返回公开可见成员。
- 对空板块返回可被前端识别的空结果。
- 支持三种排序模式。

### 2.5 每小时稳定随机

`hourly_random` 必须：

- 同一个站点自然小时内稳定。
- 刷新不会改变顺序。
- 下一小时形成新顺序。
- 不写数据库位置。
- 不覆盖管理员人工位置。
- 使用 `board_id + 小时槽位 + group_id` 等可测试种子。
- 小时槽位使用站点配置时区，不依赖服务器本地时区。

### 2.6 管理端页码分页 API

管理端群组列表必须提供固定每页 50 条：

```ts
{
  items: Group[]
  page: number
  pageSize: 50
  totalItems: number
  totalPages: number
}
```

接口需要支持现有搜索、状态、回收站、排序字段和排序方向。所有排序必须有稳定次排序字段，避免跨页跳动。

### 2.7 共享 Contract 与校验

至少新增或更新：

- `ThemePreference`。
- `BoardSortMode`。
- `Board`、`BoardMember`、`BoardWithGroups`。
- 公开详情 DTO。
- 公开区域 DTO。
- 管理页码分页 DTO。
- `last_published_at`。
- 显示宽度函数和标题/简介校验。
- API 错误和冲突结构。

显示宽度规则必须支持 ASCII、半角拉丁、中日韩/全角、单个 Emoji 字素簇、组合 Emoji、带重音拉丁字符、前后空格和换行符；标题上限 50，简介上限 1000。前后端不得各自采用近似算法。

### 2.8 文件存储兼容

按总 PRD 保留现有 R2 图片资源生命周期。T04 只补齐后续 API 所需的服务端接口、校验和错误语义：

- 管理权限仍在服务端验证。
- 文件类型、大小和处理结果可被 API 明确返回。
- 临时资源、替换资源、删除资源和失败清理遵循已有规则。
- 不改变已确认的 R2 清理时机。
- 不用前端隐藏按钮替代文件操作授权。

## 3. 工作范围

### 3.1 数据库与迁移

- 设计增量 migration。
- 增加字段、表、索引、约束、外键和级联。
- 处理 D1 外键配置和现有数据库兼容。
- 默认板块幂等初始化。
- 现有数据 `last_published_at = NULL`。
- 验证旧代码在迁移窗口的兼容性。
- 验证新代码在迁移未完成时的明确失败方式。
- 同步本地测试数据库和 Workers 测试数据库。
- 提供重复迁移、失败迁移和回滚说明。

### 3.2 Repository 与 Service

- 群组发布状态服务。
- 发现新群查询。
- 标签聚合查询。
- 板块 repository。
- 板块成员 repository。
- 稳定排序计算。
- 位置原子更新。
- 回收站关联清理。
- 永久删除关联清理。
- 管理页码查询和总数查询。
- 共享错误分类。

### 3.3 路由与接口

- 公开发现接口。
- 公开标签接口。
- 公开板块接口。
- 公开目录和搜索接口。
- 公开详情接口。
- 管理板块接口。
- 管理板块成员接口。
- 管理群组页码接口。
- 既有提交、点赞、上传、回收站和永久删除路由的兼容调整。

### 3.4 权限与安全

- 复用管理员认证和会话。
- 复用 CSRF 防护。
- 复用 Zod 输入校验。
- 复用版本冲突保护。
- 复用突变令牌和批量操作模式。
- 公开接口实施状态过滤和敏感字段过滤。
- 管理接口拒绝越权和缺失 CSRF 的写请求。
- 错误响应不泄露数据库细节、私有加群信息或隐藏状态。

### 3.5 自动化测试

- Domain：显示宽度、主题类型、排序模式和页码边界。
- Workers：发布时间、公开过滤、板块 CRUD、位置更新、回收站清理。
- API：成功响应、校验错误、权限错误、冲突、分页和过滤。
- Migration：空库、已有数据、重复运行、默认板块、NULL 初值。
- R2：保留既有上传、替换、失败和清理回归。

## 4. 不包含内容

T04 明确不包含：

- 修改任何 `.vue` 页面或组件。
- 修改 CSS、Tailwind、主题 Token、颜色、间距、布局和动画。
- 修改 prototype v2。
- 改变 Dialog、Carousel、卡片、表格、抽屉、Toast 或用户交互流程。
- 接入生产前端 Mock、替换 fixture 或调整 composable 调用顺序。
- 为了适配 API 而改变表单视觉或导航行为。
- 设计新的搜索算法、实时推送或移动端应用。
- 进行最终部署、性能发布门禁和最终验收。

共享数据类型和 API Contract 属于本任务允许范围，但必须保持与 T03 既有视图模型可适配；不能借共享类型变更偷偷改变表现语义。

## 6. 关键业务规则验收

### 6.1 公开数据边界

给定群组状态集合：

| 状态 | 公开目录 | 公开详情 | 板块公开成员 | 管理端 |
| --- | --- | --- | --- | --- |
| published | 返回 | 返回 | 返回 | 可编辑 |
| unpublished | 不返回 | 不返回 | 不返回 | 可编辑 |
| trash | 不返回 | 不返回 | 不返回 | 回收站 |
| deleted | 不存在 | 不返回 | 不存在 | 不存在 |

### 6.2 板块成员边界

- published 可添加并公开。
- unpublished 可添加但不公开。
- trash 不可添加，进入回收站时原子移除全部关联。
- deleted 不保留关联。
- 同一板块不可重复成员。
- 恢复群组不自动恢复原板块关联。

### 6.3 位置更新边界

- 上移第一项返回业务拒绝或幂等结果，不产生负位置。
- 下移最后一项返回业务拒绝或幂等结果，不越界。
- 批量拖拽不能产生重复位置。
- 并发版本不匹配返回冲突，不覆盖他人更新。
- 事务中任何一步失败都不留下部分位置。

## 7. 错误与可观测性要求

接口至少区分：

- 参数格式错误。
- 字段超限。
- 未认证。
- 无权限。
- CSRF 失败。
- 版本冲突。
- 目标不存在。
- 目标不可公开。
- 重复成员。
- 非法状态转换。
- 数据库约束失败。
- 存储失败。
- 服务器内部错误。

错误响应必须可被 T05 adapter 稳定识别；不能要求前端解析任意数据库错误字符串。服务端日志应包含 request id、路由、业务动作和可关联的错误类别，但不记录私密加群内容或敏感凭证。

## 10. Review 与 brainstorm 门禁

开始实施前，必须重新读取总 PRD 原文，并从产品、Staff Engineer、QA 三个角度检查：

- 产品规则是否被完整映射。
- API 是否支持冻结前端已有流程。
- 迁移是否可回滚、可重复和可观测。
- 公开数据边界和管理权限是否可测试。
- 是否存在必须改变前端表现的未决问题。

如果发现最后一项，停止进入代码实施，携带证据与用户 brainstorm；不得自行把前端冻结规则改成例外。
