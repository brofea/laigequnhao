# 前端架构

## 分层

依赖方向如下：

```text
路由视图
  -> 功能组件
    -> 功能 composable
      -> 共享 API 客户端
        -> 共享 Zod 契约
```

- 路由视图协调页面区块和路由状态。
- 组件渲染有类型约束的状态，并发出用户意图事件。
- Composable 负责异步生命周期、乐观更新、持久化和取消操作。
- API 客户端负责 HTTP 传输和响应解析。
- `shared/` 负责 DTO 和领域联合类型，不得依赖 Vue 或 DOM。

前端代码禁止导入 `functions/`，组件中禁止复刻服务端数据库行结构。

## 路由

- `/` 是公开群聊导航页。
- `/admin` 及其子路由是管理界面。
- 搜索词属于 URL 状态（`?q=`），刷新页面和前进/后退导航后必须保留。
- 管理路由守卫只用于改善体验；服务端始终是鉴权边界。

## T03 正式页面边界

- 正式路由固定为公开首页 `/`、管理员登录 `/admin/login` 和唯一管理工作台 `/admin`；板块管理与运行数据不得拆成新的顶层页面。
- `/admin` 内部只允许三个工作台板块：`groups`（群组管理）、`boards`（板块管理）、`stats`（运行数据）。设计系统展示只属于视觉评审材料，不进入正式路由或生产导航。
- 公开顶栏左侧只能渲染可配置品牌链接；管理员入口不得作为公开顶栏左侧按钮。顶栏标题、品牌标识、GitHub 地址和投稿按钮文案从 `site.config.ts` 读取。
- 管理工作台可以复用公开顶栏的主题/GitHub 控件，但不得把板块管理或运行数据移到公开首页；群组管理操作必须继续通过现有认证 API 和 CSRF 会话完成。
- 后续 T04–T10 若新增管理功能，必须作为 `/admin` 的内部板块或当前板块内的 Dialog 接入，并在对应任务书中明确真实 API、认证和数据契约边界。

## 数据流

公开群聊数据通过 `/api/v1/groups` 使用游标分页。搜索词变化时必须取消前一个请求并重置游标。每个响应都必须先通过共享的公开 schema 解析，才能进入组件。

当前轮换时间窗和游标由 API 返回。浏览器不得自行实现第二套排序算法。搜索结果必须保持服务端顺序。

点赞使用乐观 UI 更新：

1. 更新本地卡片状态；
2. 发送幂等的点赞或取消点赞命令；
3. 使用权威响应覆盖点赞数；
4. 请求失败时回滚并向用户播报错误。

## 渲染与性能

- 群聊卡片中的 Logo 必须显式声明宽度和高度。
- 屏幕外 Logo 使用浏览器原生懒加载；禁止预加载完整的 1,000 条记录测试夹具。
- Logo 缺失或加载失败时，必须渲染同一个确定性占位图。
- 管理端代码按路由懒加载。
- 只有性能测量证明有必要时才引入虚拟列表；必须保留游标 API，使以后引入虚拟列表时无需更改契约。

## 主题与资源

`site.config.ts` 提供机构信息和功能配置。主题值在应用根节点转换为 CSS 自定义属性。Tailwind 工具类可以使用这些 token，但组件不得硬编码机构颜色。

单色平台 SVG 使用 `currentColor`。多色品牌资源保留透明背景，并放在可感知主题的徽标容器中渲染。

## 浏览器边界

Clipboard、本地存储、媒体查询、canvas 和对象 URL 的访问必须封装在小型适配器或 composable 中。每次使用都必须处理权限拒绝、不支持的浏览器、配额失败和资源清理。

浏览器只能保存主题偏好、匿名设备 ID 和已点赞群聊 ID。管理员凭据、会话 token、提交者联系方式、R2 密钥和 Analytics token 禁止存入前端状态。
