# 前端状态管理

## 状态分类

| 分类 | 负责方 | 示例 |
|---|---|---|
| 本地 UI | 组件 | 对话框开关状态、草稿字段焦点 |
| URL | Vue Router | 首页搜索词、管理员筛选项 |
| 浏览器持久化 | 聚焦单一职责的 composable | 主题偏好、设备 ID、已点赞 ID |
| 服务端 | 功能 composable/API 客户端 | 群聊、计数、审核队列 |
| 构建配置 | `site.config.ts` | 机构、平台、主题、轮换规则 |

没有记录明确同步规则时，不得把一个分类的状态复制到另一个分类中。

## MVP 不使用 Pinia

应用只有两组路由，可共享的客户端状态有限，composable 足以明确职责。只有至少两个独立路由树都需要可写共享状态，且无法用 URL 状态、props 或重新请求服务端消除重复时，才引入 Pinia。

## 服务端状态

- 每个响应都必须先解析再存储。
- 将 API 结果视为快照；不得原地修改响应对象。
- 群聊状态、可见性、排序时间窗和点赞总数均以服务端为准。
- 只有游标页的搜索词和轮换时间窗仍与当前请求一致时，才能追加该页。
- 认证失败时清除仅管理员可见的状态和内存中的 CSRF token，并跳转到登录页。CSRF token 只保存在当前页面内存中，不写入本地存储。

## 持久化状态

使用由单一模块负责、带版本号的 key。必须处理存储不可用、配额错误、JSON 格式错误和 schema 变更。不得持久化管理员响应、联系方式、会话 Cookie、Secret 或 Analytics 数据。

## 乐观更新

默认只有点赞使用乐观更新。保存旧值，发出幂等命令，成功时接受服务端返回的计数，失败时回滚。管理员 CRUD 以确认后的响应为准，因为审核准确性比即时反馈感更重要。
