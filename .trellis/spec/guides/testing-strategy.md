# 测试策略

## 目的

测试必须证明 bootstrap PRD 中的跨层契约：公开/私有数据隔离、四状态审核、软删除、匿名点赞、确定性轮换、WebP 限制、管理员会话，以及 Cloudflare 依赖失败时的行为。

绿地项目没有需要保留的历史行为。首次实现必须建立这些测试，作为后续 Spec 引用的参考示例。

## 测试分层

| 层级 | 工具 | 负责内容 |
|---|---|---|
| 纯单元测试 | Vitest | 领域 helper、schema、轮换、归一化和图片决策 |
| Vue 组件测试 | Vitest + Vue Test Utils | 渲染、交互和无障碍状态 |
| Function 集成测试 | Cloudflare Workers Vitest integration | Hono、D1、R2、中间件和 migration |
| 浏览器 E2E | Playwright | 访客和管理员的关键路径 |
| 构建/部署 smoke test | Vite + Wrangler | 生产 bundle、Pages 路由和 binding 结构 |

不要 mock 被测单元。只 mock 当前测试层不负责的外部边界。

## 契约测试

共享 Zod schema 是可执行的 API 契约。每条路由都必须：

- 解析一份有代表性的成功响应；
- 解析每一种已记录的错误信封；
- 拒绝泄漏任何禁止公开私有字段的响应；
- 测试性质、状态、加群方式和资源用途的枚举穷尽性；
- 验证前端测试夹具由共享 schema 生成，而不是来自单独声明的 interface。

公开投影测试必须明确证明响应中不存在联系方式、审核备注、软删除元数据、内部版本、R2 key、设备 ID 和投票者 hash。

## 单元测试清单

- 搜索归一化：空白、Unicode 兼容性、拉丁字母大小写、中文、空输入和控制字符输入
- 轮换时间窗：`Asia/Shanghai` 时区下 `04:01` 和 `16:01` 之前/当时/之后、日期边界、自定义配置时间、同一时间窗内顺序稳定，以及相邻时间窗按一个位置循环移动
- 配置校验：缺少字段、平台 ID 重复、不支持的加群方式、无效时间字符串和功能开关
- 点赞持久化解析：存储缺失、JSON 格式错误、schema 版本变化和重复 ID
- 图片处理决策：JPG、带 alpha 的 PNG、WebP 直接使用/重新压缩、预览元数据、恰好达到/超过字节限制、对象 URL 清理
- 错误映射和脱敏 helper

使用注入的虚假时钟。测试不得依赖开发者机器的时区或当前日期。

## Vue 组件测试

必须建立的参考用例：

- `GroupCard`：平台和性质徽标、有序加群按钮、已下架标记、Logo 兜底、图片懒加载属性
- 复制/点赞控件：键盘操作、乐观更新成功、失败回滚、实时反馈
- 提交对话框：必填字段、1–5 个标签、不安全 URL、没有文件控件、Turnstile 失败
- 管理员认证：会话过期和通用登录失败
- 管理员群聊表单：四种状态、版本冲突、软删除、恢复和永久删除确认
- 图片工具：透明 PNG 预览，以及超过 100/300 KB 时禁用上传
- 仪表盘：一个依赖不可用时，其他组件仍可使用

优先按无障碍 role 查询，不使用依赖实现细节的 selector。

## Pages Functions 集成测试

使用 Cloudflare Vitest integration 在 `workerd` 中运行 API 测试。每个测试文件都在隔离的本地 D1 中应用真实 SQL migration。配置隔离的 R2 binding，只 stub Turnstile/Analytics 网络响应。

必须覆盖：

- 公开列表绝不返回待审核、已拒绝或软删除群聊
- 游标、query、固定纪元和轮换时间窗一致性
- 纯文本提交校验、Turnstile 和限流
- `X-Device-Id` 校验、幂等点赞/取消点赞和投票者唯一约束
- 缓存点赞数始终等于点赞行聚合值
- 登录成功/失败/限流、Cookie 篡改、过期、退出登录、Origin，以及会话绑定 `X-CSRF-Token` 的缺失、错误和成功场景
- 管理员 CRUD、所有状态、过期 `version` 和私有投影
- WebP 签名、用途、字节限制和生成的 R2 key
- 资源替换顺序和孤立对象安全
- 软删除、恢复、`pending`/`r2_done` 永久清理进度，以及 R2 或 D1 失败后的重试
- D1、R2 和 Analytics 不可用时映射为已记录的错误/部分可用组件

Workers 测试必须消费 fetch 和 R2 响应体。生产 compatibility flag 必须显式配置，因为测试池可能启用生产环境没有的 Node compatibility。

## Playwright 关键路径

1. 浏览、翻页、搜索、清除搜索、复制群号。
2. 点赞、刷新、确认本地状态、取消点赞。
3. 提交一个有效的纯文本群聊，并看到安全的受理回执。
4. 登录、复核待审核记录、将其发布，并在公开页面看到它。
5. 下架群聊，并确认它仍公开展示且带有标记。
6. 软删除，确认公开页面/管理员列表移除，恢复，然后在确认后永久删除。
7. 将带透明度的 PNG 转为 WebP，在 Logo 限制内上传，并拒绝超限结果。
8. 切换当前实现阶段要求的视口和颜色偏好。

关键 E2E 测试至少在一个桌面视口和一个移动视口运行。阶段专属的响应式、深色模式和二维码用例，在相应功能开关启用后成为必测项。

## 规模与性能夹具

维护一个确定性的测试夹具，包含：

- 1,000 个已发布/已下架群聊；
- 多种平台、性质、标签和加群方式组合；
- Logo 失败/缺失用例；
- 不影响顺序的不同点赞数。

断言：

- 初始请求受游标页大小限制；
- 不会提前请求屏幕外 Logo；
- 搜索和轮换结果保持正确；
- 不出现 N+1 API 或 D1 查询模式；
- 已知图片尺寸引起的布局偏移保持在限度内。

首次实现并完成测量后再记录性能预算，不要凭空制定没有依据的数字。相对该基线的性能回退必须有书面决策。

## 必须运行的命令

```bash
pnpm lint
pnpm format:check
pnpm typecheck
pnpm test
pnpm test:workers
pnpm test:e2e
pnpm build
```

除非测试被明确记录为隔离状态，CI 必须运行全部命令。隔离测试必须有负责人、原因和解除条件；反复重试不稳定测试直到通过不属于质量门禁。

## 环境安全

- 测试只使用本地 D1/R2。
- 预览 smoke test 只使用预览 binding。
- 自动化测试不得选择使用生产数据或生产写入 token。
- 测试夹具不得包含真实联系方式、Secret、Cookie、设备 ID 或 Cloudflare API token。
