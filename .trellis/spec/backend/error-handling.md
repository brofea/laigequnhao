# 错误处理

## 错误分类

已知失败统一使用一种 `AppError` 结构，包含稳定错误码、安全的 HTTP 状态码、安全消息、可选的安全字段错误、cause 和日志上下文。

| 错误码 | 状态码 | 含义 |
|---|---:|---|
| `VALIDATION_FAILED` | 400 | 请求体、query、游标、配置或文件元数据无效 |
| `AUTH_REQUIRED` | 401 | 没有有效管理员会话 |
| `AUTH_FAILED` | 401 | 通用登录失败 |
| `FORBIDDEN` | 403 | 已认证请求缺少权限或来源证明 |
| `NOT_FOUND` | 404 | 资源不存在或被有意隐藏 |
| `VERSION_CONFLICT` | 409 | 管理员编辑基于过期版本 |
| `STATE_CONFLICT` | 409 | 领域不变量或永久删除状态冲突 |
| `PAYLOAD_TOO_LARGE` | 413 | 超过 Logo/二维码硬上限 |
| `UNSUPPORTED_MEDIA_TYPE` | 415 | 最终上传文件不是有效 WebP |
| `RATE_LIMITED` | 429 | 超出服务端限制 |
| `DEPENDENCY_UNAVAILABLE` | 503 | D1、R2、Turnstile 或 Analytics 不可用 |
| `INTERNAL_ERROR` | 500 | 未预期错误的安全兜底 |

前端文案可以对错误码做本地化。API 消息只是安全的兜底内容，不是主要 UI 契约。

## 错误传播

在路由边界校验并归一化。已知 `AppError` 实例直接传播到最终 Hono 错误中间件。Service 只有在需要补充上下文、执行补偿或转换依赖错误时才捕获异常；禁止仅为了记录日志后继续执行而捕获。

最终中间件：

1. 获取请求 ID；
2. 映射已知错误；
3. 把未知值转换为 `INTERNAL_ERROR`；
4. 脱敏后只记录一次日志；
5. 返回标准信封和 `X-Request-Id`。

## 依赖失败

- 读取期间 D1/R2 失败时，该操作返回依赖错误。
- 仪表盘数据源相互隔离：每个组件返回数据或自己的不可用标记。
- Turnstile 超时时，访客提交按失败关闭处理。
- Cloudflare Analytics 失败不应隐藏 D1 业务指标。
- 永久删除期间 R2/D1 部分失败时保留重试状态，绝不报告完全成功。

## 客户端行为

- `400`：显示字段错误并保留安全输入。
- `401`：清除管理员状态并要求登录；不要循环重试。
- `409`：重新获取当前数据，并要求管理员 Review。
- `413`/`415`：保留本地图片，并说明修正方法。
- `429`：遵守 `Retry-After`，在此之前不要自动重试。
- `5xx`/网络错误：显示重试操作和请求 ID。

## 绝不暴露

堆栈、SQL、D1/R2 内部信息、原始依赖响应、Secret、会话 Cookie、设备 ID、投票者 hash、IP 数据、联系方式，以及某个具体密码字符是否正确。
